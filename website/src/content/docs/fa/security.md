---
title: امنیت
description: Meridian با کجا ارتباط می‌گیرد، چه داده‌ای می‌فرستد، چگونه بارگیری‌ها را بررسی می‌کند و چگونه آسیب‌پذیری را گزارش دهید.
---

Meridian **تله‌متری، تحلیل رفتار یا تبلیغات ندارد** و گزارش‌های عیب‌یابی را بارگذاری نمی‌کند. صفحه‌های اتصال و پشتیبانی، پنل وب و وب‌سایت، اسکریپت‌ها، سبک‌ها، فونت‌ها، آیکون‌ها و ابزار ساخت QR را از منبع خود ارائه می‌کنند؛ **هیچ منبع شخص ثالثی بارگیری نمی‌شود**. باز کردن فروشگاه برنامه، راه ارتباط با مالک یا هر پیوند خارجی انتخاب شماست.

نصب، تمدید گواهی، DNS و آزمایش اتصال به شبکه نیاز دارند. فهرست زیر مقصدها و داده‌های ارسالی را توضیح می‌دهد تا بتوانید دربارهٔ استفاده از هر سرویس تصمیم بگیرید.

## گزارش آسیب‌پذیری‌ها

اگر آسیب‌پذیری امنیتی در Meridian پیدا کردید:

1. **issue عمومی باز نکنید.**
2. از [گزارش خصوصی آسیب‌پذیری در GitHub](https://github.com/getmeridian/meridian/security/advisories/new) استفاده کنید.
3. مراحل بازتولید و پیامد احتمالی را بنویسید.

هدف ما پاسخ‌گویی ظرف 48 ساعت و قدردانی از گزارش‌دهندگان در توضیح اصلاحیه است.

## درخواست‌های خروجی

گیرندهٔ هر اتصال IP ماشین متصل‌شده و سرآیندهای معمول پروتکل را می‌بیند. جدول‌ها داده‌های اضافی را مشخص می‌کنند. تنظیمات سرورها، اعتبارنامه‌های کاربران VPN و سوابق مصرف فقط به سرورها و سرویس کنترل خودتان فرستاده می‌شوند. گزینهٔ واحدی برای استقرار کاملاً بدون شبکه وجود ندارد. بارگیری‌ها ممکن است تغییر مسیر منبع، از جمله میزبان فایل‌های انتشار GitHub، را دنبال کنند. نام‌های مورد استفادهٔ نصب‌کننده و بررسی میزبان با DNS تنظیم‌شدهٔ ماشین متصل حل می‌شوند.

### روی کامپیوتر مدیریت شما

| درخواست | زمان اجرا و دادهٔ ارسالی | اختیار شما |
|---------|-------------------------|------------|
| **نصب CLI → `getmeridian.org`، GitHub و منابع بسته‌ها** | شما `https://getmeridian.org/install.sh` را می‌گیرید. اگر uv نصب نباشد، نصب‌کننده اسکریپت نسخهٔ ثابت را از astral-sh/uv و آرشیو اجرایی منطبق را دریافت می‌کند، سپس Meridian و وابستگی‌ها را از منابع بسته‌ها، معمولاً PyPI، با Python مدیریت‌شده در صورت نیاز نصب می‌کند. درخواست اسکریپت، فایل، نسخهٔ بسته و پلتفرم ارسال می‌شود. | فقط هنگام اجرای نصب‌کننده؛ uv موجود بارگیری‌های راه‌اندازی خودش را حذف می‌کند. |
| **اعلان به‌روزرسانی → PyPI** (`pypi.org/pypi/meridian-vpn/json`) | اجرای CLI با خروجی متنی، فهرست نسخه‌های بسته را حداکثر یک‌بار در دقیقه می‌گیرد. درخواست نام بسته را مشخص می‌کند و دادهٔ سرورها را نمی‌فرستد. خروجی JSON و دستور `serve` این بررسی را رد می‌کنند. | `MERIDIAN_DISABLE_UPDATE_CHECK=1` را تنظیم کنید. این متغیر اعلان پس‌زمینه را خاموش می‌کند، نه دستور صریح `meridian update` را. |
| **`meridian update` → PyPI و منابع بسته‌ها** | نسخه‌ها را بررسی می‌کند و با uv، pipx یا pip نسخهٔ انتخابی و وابستگی‌ها را نصب می‌کند. مدیر بسته درخواست‌های نام، نسخه و پلتفرم را به نمایهٔ تنظیم‌شده، معمولاً PyPI و `files.pythonhosted.org`، می‌فرستد. uv ممکن است Python مدیریت‌شده را هم از GitHub بگیرد. | زمانی اجرا کنید که قصد به‌روزرسانی دارید. نمایه، حافظهٔ نهان و حالت آفلاین در مدیر بسته تنظیم می‌شوند. |
| **`meridian fleet upgrade` → API انتشارهای GitHub** | برای شبکه‌ای با سرور واسطه، انتشارهای Realm و SHA-256 منتشرشدهٔ آن‌ها را می‌خواند. درخواست مخزن عمومی و، اگر تنظیم کرده باشید، `GITHUB_TOKEN` را می‌فرستد. | `meridian fleet upgrade --tested` نسخه‌های آزمایش‌شده را نگه می‌دارد و جست‌وجوی انتشار را رد می‌کند؛ نصب هنوز ممکن است به بارگیری نیاز داشته باشد. |
| **پیشنهاد کشور → IANA و سرویس RDAP ثبت‌کنندهٔ منطقه‌ای اینترنت (RIR)** | هنگام افزودن خروجی، نقشهٔ ثبت‌کنندگان IPv4/IPv6 را از IANA می‌گیرد و سپس سابقهٔ ثبت IP سرور را از RIR می‌خواهد. RIR آن IP را می‌بیند؛ IANA فقط درخواست نقشه را دریافت می‌کند. | در `deploy` یا `node add`، `--country` را تعیین کنید تا پرس‌وجو انجام نشود. راهنمای setup هم تا وقتی منطقه ذخیره نشده باشد پیشنهاد می‌گیرد. |
| **تشخیص IP عمومی محلی → `ifconfig.me`، `api.ipify.org` یا `api64.ipify.org`** | برای هدف تازهٔ `local`، آدرس عمومی این ماشین را از سرویس بازگرداندن IP می‌پرسد و در صورت شکست مقصدهای جایگزین را امتحان می‌کند. | از هدف ذخیره‌شده یا آدرس صریح سرور استفاده کنید تا تشخیص تازه لازم نباشد. |
| **تصویر ظاهر صفحه → URL تصویر شما** | آیکون تصویری یک‌بار روی کامپیوتر شما دریافت و به‌صورت دادهٔ تصویر ذخیره می‌شود. میزبان تصویر URL و سرآیند user-agent مربوط به Meridian را می‌بیند. | از ایموجی یا دادهٔ تصویر ازپیش‌تعبیه‌شده استفاده کنید. مرورگر URL اصلی تصویر را بارگیری نمی‌کند. |
| **مدیریت → سرورها و سرویس کنترل خودتان** | عملیات زنده، احراز هویت SSH، دستورها و فایل‌ها یا توکن HTTPS API و تنظیمات، اعتبارنامه‌ها، فرمان‌ها و درخواست‌های پشتیبان لازم را می‌فرستند. مهاجرت فقط پنل قدیمی مشخص‌شدهٔ شما را می‌خواند. | برای مدیریت زنده ضروری است. عملیات محلی بازبینی و خروجی گرفتن از وضعیت محلی مستندشدهٔ خود استفاده می‌کنند. |
| **ابزار آزمایش Xray → انتشارهای XTLS/Xray-core در GitHub** | اگر حافظهٔ نهان ابزار محلی کامل نباشد، تست اتصال آرشیو نسخهٔ ثابت برای سیستم‌عامل و معماری شما را می‌گیرد. | حافظهٔ نهان کامل از بارگیری دوباره جلوگیری می‌کند. تستی که به ابزار نیاز دارد گزینهٔ خاموش کردن بارگیری ندارد. |

### بررسی‌ها و نصب روی سرورها

| درخواست | زمان اجرا و دادهٔ ارسالی | اختیار شما |
|---------|-------------------------|------------|
| **آزمایش دسترسی، استتار و مسدودسازی → آدرس‌ها و سایت‌های آزمایش‌شده** | `check`، `test`، `--probe`، انتخاب SNI و بررسی استقرار از کامپیوتر یا سرورها درخواست TCP/TLS/HTTP می‌فرستند؛ SNI انتخابی، مسیر HTTP یا بایت‌های آزمایشی ارسال می‌شود. بررسی مستقیم و معکوس نام‌ها از DNS همان ماشین استفاده می‌کند. | آزمایش‌های اختیاری را هنگام نیاز اجرا کنید. استقرار به بررسی نیاز دارد؛ تعیین صریح SNI جست‌وجوی همسایه‌ها را حذف می‌کند، ولی خود سایت همچنان بررسی می‌شود. |
| **تست اتصال → سرویس‌های بازگرداندن IP** | HTTPS را از مسیر VPN به `api.ipify.org`، `ipv4.icanhazip.com` یا `v4.ident.me` می‌فرستد؛ برای IPv6 از `api6.ipify.org`، `ipv6.icanhazip.com` یا `v6.ident.me` استفاده می‌کند. سرویس IP خروجی را می‌بیند. پس از شکست ممکن است درخواست مستقیم تکرار شود و IP کامپیوتر مدیریت را نشان دهد. | `MERIDIAN_CONNECT_TEST_URL` را به مقصد خودتان که IP برمی‌گرداند تنظیم کنید. استقرار هم از این آزمایش ترافیک استفاده می‌کند. |
| **یافتن سایت استتار → GitHub و سایت‌های TLS همسایه** | `scan` و پیشنهاد خودکار SNI نسخهٔ ثابت RealiTLScanner را از XTLS/RealiTLScanner می‌گیرند، آدرس‌های همسایه را می‌سنجند و نام‌های گواهی را با DNS و TLS بررسی می‌کنند. سایت‌ها آزمایش‌های سرور را می‌بینند. | `--sni` را صریح تعیین کنید تا جست‌وجوی خودکار انجام نشود؛ اگر اسکن نمی‌خواهید، `scan` را اجرا نکنید. |
| **بسته‌های سیستم و به‌روزرسانی امنیتی → مخازن APT** | نصب، بسته‌ها را از مخازن تنظیم‌شدهٔ سیستم‌عامل می‌گیرد. آماده‌سازی پایه تازه‌سازی روزانهٔ فهرست بسته‌ها و به‌روزرسانی امنیتی خودکار را فعال می‌کند. اگر بستهٔ توزیع کافی نباشد، nginx را از `nginx.org` نصب می‌کند. درخواست‌ها توزیع، معماری و بسته‌ها را مشخص می‌کنند. | مدیر سرور منابع و زمان‌بندی APT را کنترل می‌کند؛ اعمال دوبارهٔ آماده‌سازی پایه تنظیمات به‌روزرسانی آن را برمی‌گرداند. `--no-harden` به‌روزرسانی بسته‌ها را خاموش نمی‌کند. |
| **نصب سرویس کنترل → GitHub و PyPI** | آرشیو نسخهٔ ثابت uv را از astral-sh/uv، Python مدیریت‌شده را با uv و نسخهٔ دقیق `meridian-vpn` با وابستگی‌ها را از PyPI یا نمایه‌های تنظیم‌شده می‌گیرد. در نصب توسعهٔ قابل ویرایش، wheel روی کامپیوتر مدیریت ساخته می‌شود؛ ساخت ممکن است وابستگی‌هایی از نمایهٔ بسته‌ها بگیرد، سپس wheel با SSH فرستاده می‌شود. | نصب به‌روز یا حافظهٔ نهان پر نیاز به بارگیری را حذف می‌کند. نصب معمول به منابع بسته‌ها نیاز دارد. |
| **نصب واسطه → انتشارهای zhboner/realm در GitHub** | هنگام نصب یا تغییر فایل اجرایی واسطه، آرشیو نسخهٔ ثابت Realm را می‌گیرد. فقط درخواست فایل عمومی ارسال می‌شود. | نسخهٔ نصب‌شدهٔ منطبق به بارگیری نیاز ندارد. |
| **ابزار گواهی → `raw.githubusercontent.com`** | اگر acme.sh وجود نداشته باشد، اسکریپت نسخهٔ ثابت را از acmesh-official/acme.sh می‌گیرد، بررسی می‌کند و نصب می‌کند. | نصب موجود دوباره استفاده می‌شود. |
| **صدور و تمدید گواهی → Let's Encrypt** | acme.sh درخواست ACME برای IP یا دامنهٔ سرور می‌فرستد؛ شناسه‌های گواهی، کلیدهای عمومی، اثبات حساب و ایمیل تماس در صورت ارائه ارسال می‌شوند. تمدید با cron اجرا می‌شود. شناسه‌های گواهی در گزارش‌های عمومی Certificate Transparency هم ثبت می‌شوند. | استقرار معمول به گواهی مورد اعتماد نیاز دارد. `MERIDIAN_ACME_SERVER` مرجع ACME دیگری را انتخاب می‌کند و گواهی را خاموش نمی‌کند. |

### سرویس کنترل و عامل‌های گره

| درخواست | زمان اجرا و دادهٔ ارسالی | اختیار شما |
|---------|-------------------------|------------|
| **آینهٔ فایل سرویس کنترل → منابع HTTPS، معمولاً انتشارهای Xray در GitHub** | هنگام شروع، تغییر مشخصات گره یا درخواست فایل غایب از طرف عامل، آرشیوهای لازم با نسخه و درهم‌سازی مشخص را می‌گیرد. پس از درخواست فایل غایب، تلاش ناموفق حداکثر یک‌بار در دقیقه تکرار می‌شود. فقط URL عمومی فایل ارسال می‌شود، بدون اطلاعات کاربر یا مصرف. | گزینهٔ خاموش کردن آینه وجود ندارد. فایل‌های بررسی‌شده در حافظهٔ نهان به منبع بیرونی نیاز ندارند. |
| **عامل گره → سرویس کنترل شما** | ثبت‌نام، باز کردن و تمدید نشست، دریافت سند و فرمان امضاشده، گزارش نسخهٔ اعمال‌شده و سلامت، ارسال مجموع ترافیک هر کاربر، تأیید فرمان و دریافت فایل‌های سرویس را انجام می‌دهد. توکن ثبت‌نام یا اثبات هویت، توکن نشست، اطلاعات گره و ساخت و گزارش‌ها ارسال می‌شوند. | برای مدیریت گره ضروری است. توقف عامل، اعمال تنظیمات و ارسال آمار را هم متوقف می‌کند. |
| **عامل گره → منابع HTTPS فایل‌های اجرایی ثابت، معمولاً GitHub** | سند امضاشده می‌تواند به آرشیو Xray نیاز داشته باشد. مشخصات تولیدشده اول GitHub و سپس آینهٔ سرویس را امتحان می‌کند. منبع URL فایل و شناسهٔ ساخت عامل در user-agent را می‌بیند، ولی توکن سرویس را دریافت نمی‌کند. | فایل اجرایی نصب‌شده و حافظهٔ نهان از بارگیری جلوگیری می‌کنند. آینه هنگام عدم دسترسی به GitHub جایگزین است؛ CLI گزینه‌ای برای ترجیح آن ندارد. |

**خود عامل، فایل اجرایی خودش را از GitHub نمی‌گیرد.** Wheel Meridian ساخت‌های ایستای musl برای x86_64 و aarch64 را همراه فایل مقدار درهم‌سازی و نسخهٔ ساخت دارد. کامپیوتر مدیریت آن‌ها را بررسی و برای نصب یا ارتقا با SSH ارسال می‌کند.

### ترافیک VPN و برنامه‌ها

| درخواست | زمان اجرا و دادهٔ ارسالی | اختیار شما |
|---------|-------------------------|------------|
| **خروجی → مقصدهای کاربر و سایت استتار Reality** | ترافیک درخواستی کاربران را منتقل می‌کند. Reality و مسیر استتار nginx هم برای استتار TLS و اتصال‌های بدون احراز هویت به سایت انتخابی وصل می‌شوند. سایت اتصال خروجی، SNI و ترافیک آزمون هدایت‌شده را می‌بیند. nginx نام سایت استتار را با حل‌کنندهٔ DNS میزبان پیدا می‌کند. | سایت استتار را شما انتخاب می‌کنید؛ self-steal از سایت محلی خودتان استفاده می‌کند. انتقال ترافیک مقصد کار اصلی VPN است. |
| **DNS خروجی → Cloudflare، Quad9 و Google** | نام مقصدها با DoH موازی در آدرس‌های در دسترس IPv4/IPv6 پرسیده می‌شود: Cloudflare `1.1.1.1` / `2606:4700:4700::1111`، Quad9 `9.9.9.10` / `2620:fe::10`، Google `8.8.8.8` / `2001:4860:4860::8888`؛ مسیر همه `/dns-query` است. هر اپراتوری که پرسش را دریافت کند نام‌ها و IP خروجی را می‌بیند. `check` یک پرسش نمونهٔ ثابت DNS هم به این مقصدها می‌فرستد. | گزینهٔ تغییر DNS در CLI وجود ندارد. اگر همه شکست بخورند، تبدیل نام مقصد شکست می‌خورد و به DNS ساده برنمی‌گردد. پرسش‌ها حتی با WARP مستقیم از میزبان می‌روند. |
| **WARP اختیاری → Cloudflare** | نصب، کلید و بسته را از `pkg.cloudflareclient.com` می‌گیرد؛ warp-cli سرور را ثبت و تونل WARP را باز می‌کند. ترافیک انتخاب‌شده از Cloudflare خارج می‌شود و آن شرکت ثبت سرور و مقصدهای خروجی را می‌بیند. | WARP اختیاری است؛ با فعال نکردنش نصب، ثبت‌نام و تونل هم انجام نمی‌شوند. اگر سرویس از قبل نصب باشد، برای پایان دادن به اتصال‌های خودش باید آن را روی سرور متوقف کنید. |
| **دروازهٔ مسیریابی اختیاری → DNS و URL آزمایش مجموعهٔ خروجی‌ها** | تنظیمات دروازه از Google DoH در `dns.google`، DNS ساده در `8.8.8.8` و حل‌کنندهٔ میزبان برای ترافیک مستقیم استفاده می‌کنند. مجموعهٔ خروجی‌ها هر 10 ثانیه از مسیر خروجی‌ها، به‌طور پیش‌فرض با `https://www.apple.com/library/test/success.html`، آزمایش می‌شود؛ سایت IP خروجی و درخواست HTTP را می‌بیند. | دروازه و مجموعهٔ خروجی اختیاری‌اند. در تنظیمات مجموعه که پیش از اعمال بازبینی می‌کنید، `probe_url` می‌تواند مقصد آزمایشی شما باشد. تضمین DNS صرفاً رمزنگاری‌شدهٔ خروجی برای دروازه برقرار نیست. |
| **واسطهٔ Realm → گام بعدی یا خروجی** | جریان TCP رمزنگاری‌شدهٔ کاربر را به مقصدهای تنظیمات بازبینی‌شده می‌فرستد. عامل، هستهٔ VPN یا ابزار جداگانهٔ تله‌متری اجرا نمی‌کند. | زنجیره و خروجی را شما انتخاب می‌کنید. |
| **برنامهٔ VPN → سرویس اشتراک، DNS و سایت آزمایش سلامت** | برنامهٔ انتخابی اشتراک را تازه می‌کند و ممکن است DNS و تست اتصال خودش را داشته باشد. پروفایل‌های Xray JSON در Meridian، DNS ساده در `1.1.1.1` / `8.8.8.8` و آزمایش صفحهٔ Apple هر دقیقه را تنظیم می‌کنند؛ گروه فعال جایگزین Mihomo همان صفحه را هر 5 دقیقه بررسی می‌کند؛ sing-box، Cloudflare DNS روی TLS و UDP و آزمایش صفحه هر 3 دقیقه را تنظیم می‌کند. سایت آزمایش IP خروجی مسیر را می‌بیند و اعتبارنامهٔ اشتراک را دریافت نمی‌کند. | رفتار برنامه جدا از صفحهٔ مرورگر است. DNS و آزمایش سلامت را در برنامه یا تنظیماتش مدیریت کنید. |

### صفحه‌های اتصال، پنل وب و وب‌سایت

- **صفحهٔ اتصال و پشتیبانی:** فقط مبدأ خود سرویس، برای صفحه و تنظیمات، وضعیت حساب، اشتراک، فایل‌های مشترک و آزمایش اختیاری ساعت یا انتقال داده. سرویس URL محرمانهٔ کاربر و سرآیندهای عادی مرورگر را می‌گیرد. ساخت QR و خروجی تصویر محلی‌اند. درخواست شخص ثالث وجود ندارد.
- **پنل وب:** فقط مبدأ خود سرویس، برای فایل‌ها، ورود، تازه‌سازی نشست، خواندن و نوشتن API و تازه‌سازی صفحهٔ قابل مشاهده. گذرواژه، کد احراز هویت، کوکی نشست و ویرایش‌ها به سرویس خودتان می‌روند. درخواست شخص ثالث وجود ندارد.
- **وب‌سایت:** فقط مبدأ خودش، شامل فونت‌ها، فایل جست‌وجو، نسخه‌های Markdown و فایل‌های نمایش آزمایشی. دموی پنل وب API را داخل مرورگر پاسخ می‌دهد. تحلیل رفتار، فونت خارجی، محتوای تعبیه‌شدهٔ بیرونی یا درخواست شخص ثالث وجود ندارد.

پیوند خارجی برنامه، مستندات یا پشتیبانی فقط با انتخاب شما باز می‌شود؛ صفحه آن سایت‌ها را در پس‌زمینه دریافت نمی‌کند.

## بررسی بارگیری‌ها

Xray، Realm، RealiTLScanner، acme.sh و راه‌اندازی uv روی سرور، نسخهٔ ثابت و **بررسی SHA-256 پیش از اجرا** دارند. نصب‌کنندهٔ CLI اسکریپت ثابت uv را هم بررسی می‌کند؛ آن اسکریپت مقادیر درهم‌سازی آرشیوها را دارد. انتشارهای Meridian فایل `SHA256SUMS` برای بررسی نصب‌کننده پیش از اجرا دارند. عدم تطابق نصب را متوقف می‌کند.

آینهٔ سرویس کنترل و عامل، **اندازهٔ دقیق و SHA-256** فایل را پیش از انتشار یا استخراج بررسی می‌کنند. عامل پیش از اعمال مقادیر ثابت، امضای سرویس روی وضعیت مطلوب را بررسی می‌کند. ساخت‌های ایستای musl عامل با فایل‌های درهم‌سازی wheel و پس از انتقال SSH بررسی می‌شوند. ارتقای سرورها انتشار تازهٔ Realm را تنها زمانی می‌پذیرد که GitHub برای همهٔ فایل‌های لازم SHA-256 منتشر کرده باشد.

سرویس کنترل نسخهٔ بستهٔ Meridian را ثابت نگه می‌دارد. وابستگی‌های Python از نمایه و بررسی یکپارچگی مدیر بسته و بسته‌های سیستم از مخازن امضاشدهٔ APT استفاده می‌کنند؛ اثر انگشت مورد انتظار کلید مخازن افزوده‌شدهٔ nginx و WARP نیز بررسی می‌شود. یکپارچگی بارگیری همچنان به اعتماد به منبع بسته یا انتشار که مقدار ثابت را عرضه می‌کند وابسته است.

## طراحی امنیتی

- **اعتبارنامه‌ها:** در `~/.config/meridian/cluster.yml` با مجوز `0600` و در پوشه‌ای با مجوز `0700` نگهداری می‌شوند. مقادیر محرمانه پیش از ورود به دستور شل با `shlex.quote()` ایمن می‌شوند و در خروجی `meridian doctor` پوشانده می‌شوند. هر برنامه‌ای با دسترسی کاربر شما می‌تواند فایل‌ها را بخواند؛ رمزنگاری فایل روی ماشین آلوده جلوی ثبت گذرواژه یا ربودن نشست SSH را نمی‌گیرد. از کامپیوتر مدیریت محافظت کنید.
- **دسترسی سرویس کنترل:** nginx سرویس را در مسیر محرمانهٔ HTTPS ارائه می‌کند؛ به تونل SSH نیاز نیست. صفحهٔ اتصال و اشتراک مسیر جدا دارند و مسیر مدیریت را فاش نمی‌کنند. CLI توکن مدیر را در `cluster.yml` نگه می‌دارد و اسکریپت‌ها توکن‌های مستقل با دسترسی محدود و قابل لغو می‌گیرند.
- **پنل وب:** یک مالک با گذرواژه و کد اختیاری احراز هویت دارد. نشست پس از 30 دقیقه بی‌کاری و حداکثر 12 ساعت پایان می‌یابد. ایجاد توکن یا تغییر حریم خصوصی نیازمند تأیید اخیر گذرواژه است. پنل وب کاربران، اعلان‌ها، زبان و حریم خصوصی را مدیریت می‌کند، توپولوژی سرورها را تغییر نمی‌دهد و کلید SSH ندارد. منابع خارجی بارگیری نمی‌کند و سیاست امنیت محتوا (CSP) سخت‌گیرانه دارد.
- **گره‌ها:** عامل‌ها با HTTPS به سرویس کنترل وصل می‌شوند و پورت مدیریت باز نمی‌کنند. هر گره با توکن ثبت‌نام یک‌بارمصرف وارد می‌شود و گواهی مرجع داخلی سرورها را می‌گیرد. سرویس اسناد را امضا می‌کند؛ عامل امضا را بررسی و سند قدیمی‌تر از وضعیت اعمال‌شده را رد می‌کند.
- **حریم خصوصی:** محدودیت دستگاه و تاریخچهٔ مصرف پیش‌فرض خاموش‌اند؛ سرویس مجموع ترافیک از آغاز و زمان آخرین فعالیت را نگه می‌دارد. ثبت اثر انگشت کلیددار دستگاه، جزئیات کامل یا ترافیک روزانه با نگهداری محدود اختیاری است. هیچ سطحی IP کاربران، گزارش اتصال یا مسیر درخواست‌ها را ذخیره نمی‌کند. پیامد تصرف سرور را در [حریم خصوصی](/fa/privacy/) ببینید.
- **پشتیبان‌ها:** [age](https://age-encryption.org/) هر تصویر پشتیبان را برای کلید کامپیوترهای مدیریت و کلید بازیابی که فقط شما بخش خصوصی آن را دارید رمزنگاری می‌کند. کلید امضا، نشست و گذرواژهٔ پنل وب در آن نیست؛ بازیابی آن‌ها را دوباره می‌سازد، پس سرور قبلی نمی‌تواند برای سرورهای بازیابی‌شده فرمان معتبر امضا کند.
- **SSH:** ورود با گذرواژه پیش‌فرض خاموش و fail2ban فعال است. `--no-harden` این دو و فایروال را برای سرور مشترک با سرویس‌های دیگر رد می‌کند.
- **فایروال:** UFW فقط پورت SSH و پورت‌های لازم نقش را باز می‌گذارد: TCP/443 برای VPN، TCP/80 برای صدور گواهی، UDP/443 فقط با Hysteria2 و پورت پذیرش اتصال واسطه.
- **DNS خروجی:** نام مقصدهای کاربر با DoH موازی به IPهای Cloudflare، Quad9 و Google حل می‌شود. این اپراتورها نام‌ها را می‌بینند؛ میزبان آن‌ها را در DNS ساده دریافت نمی‌کند. اگر هیچ‌کدام پاسخ ندهند، DNS ساده جایگزین نمی‌شود. بررسی نصب، نام استتار، DNS دروازه و DNS برنامه‌ها رفتار جداگانهٔ توضیح‌داده‌شده در بالا را دارند.
- **نسخه و یکپارچگی:** بارگیری بررسی‌شده، وضعیت مطلوب امضاشده و عامل ایستای musl همراه بسته، نصب را طبق توضیحات بالا محافظت می‌کنند. سرویس کنترل نسخهٔ دقیق بستهٔ Meridian را اجرا می‌کند.
- **TLS:** [acme.sh](https://github.com/acmesh-official/acme.sh) صدور و تمدید گواهی را با Let's Encrypt انجام می‌دهد و nginx آن را ارائه می‌کند.

## محدوده

Meridian سرورهای VPN را پیکربندی می‌کند و پروتکل رمزنگاری پیاده‌سازی نمی‌کند. امنیت زیربنایی به این پروژه‌ها وابسته است:

- [Xray-core](https://github.com/XTLS/Xray-core): پروتکل‌های VLESS+Reality، XHTTP، WSS و Hysteria2.
- [age](https://age-encryption.org/) از طریق pyrage: رمزنگاری پشتیبان‌ها.
- [nginx](https://nginx.org/): مسیریابی SNI و پایان‌دهی TLS.
- [acme.sh](https://github.com/acmesh-official/acme.sh): صدور و تمدید گواهی Let's Encrypt.
- [Realm](https://github.com/zhboner/realm): هدایت TCP روی واسطه‌ها.
