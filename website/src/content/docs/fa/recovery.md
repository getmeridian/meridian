## تشخیص

از ماشین محلی خود اجرا کنید (SSH مورد نیاز نیست):

```
meridian test IP
```

نتیجه منفی TCP/443 فقط می‌گوید آدرس از نقطه مشاهده فعلی در دسترس نیست و به‌تنهایی مسدودسازی را ثابت نمی‌کند؛ firewall، listener متوقف یا routing اپراتور نیز ممکن است علت باشد. از شبکه دیگری مقایسه و `meridian probe IP` را اجرا کنید. نبود شواهد کد `3` و یافته منفی تأییدشده کد `4` می‌دهد.

## راحتی فوری

اگر **حالت Domain** (`--domain`) دارید، مسیر WSS/CDN ممکن است از Cloudflare همچنان کار کند. از کاربران بخواهید اشتراک رسمی را refresh و مسیر در دسترس را انتخاب کنند؛ صفحه PWA جداگانه فقط در legacy و پس از شواهد مثبت استقرار وجود دارد.

اگر **relay** استقرار داده‌اید، کلاینت‌های متصل از طریق relay تحت تأثیر قرار نمی‌گیرند — آنها به IP خانگی relay متصل می‌شوند، نه IP خروج مسدود.

## گزینه‌های بازیابی

### گزینه A: افزودن خروجی جایگزین

سریع‌ترین راه هنگامی است که پنل فعلی هنوز در دسترس باشد:

```bash
# 1. VPS جدید از ارائه‌دهنده خود دریافت کنید (IP جدید)
# 2. آن را به فلیت فعلی اضافه کنید
meridian node add NEW_IP --name replacement
```

کلاینت‌های موجود پس از تازه‌سازی اشتراک، خروجی جایگزین را دریافت می‌کنند و نیازی به ایجاد دوباره حساب‌هایشان نیست.

### گزینه B: سرور خروج جدید + relay موجود

ترتیب دستوری زیر فقط برای relay قدیمی Realm است:

```bash
# 1. نود خروج جدید را اضافه کنید
meridian node add NEW_EXIT_IP --name replacement

# 2. relay را به خروج جدید تغییر دهید
meridian relay remove RELAY_IP --exit OLD_EXIT_IP
meridian relay deploy RELAY_IP --exit NEW_EXIT_IP

# کلاینت‌ها به طور خودکار دوباره متصل می‌شوند — IP relay بدون تغییر
```

در V4، `relay remove` و `node remove` برای منابع مدیریت‌شده رد می‌شوند. exit/relay chain را در intent با `meridian setup` تغییر دهید، plan را بازبینی و apply کنید و سپس مسیر رسمی end-to-end را با `meridian test` بسنجید؛ دسترس‌پذیری listener به‌تنهایی کافی نیست.

### گزینه C: افزودن حالت Domain برای fallback CDN

اگر قبلاً از حالت Domain استفاده نمی‌کردید، آن را اکنون اضافه کنید تا قطع‌های آینده را جلوگیری کنید:

```bash
meridian node add NEW_IP --domain proxy.example.com
```

با حالت Domain، اتصال WSS/CDN حتی زمانی‌که IP سرور مسدود است کار می‌کند — ترافیک از طریق Cloudflare مسیریابی می‌شود. راهنمای [حالت Domain](/docs/fa/domain-mode/) را برای راه‌اندازی Cloudflare ببینید.

`meridian node add` به در دسترس بودن پنل Remnawave فعلی نیاز دارد. اگر سرور ازدست‌رفته میزبان پنل هم بوده است، ابتدا آن میزبان را بازیابی کنید؛ مهاجرت خودکار پنل هنوز پشتیبانی نمی‌شود.

## دفاع فعال‌انه

قبل از مسدود شدن IP خود، تاب‌آوری را تنظیم کنید:

1. **Relay را استقرار دهید** — نقطه ورود خانگی برای کلاینت‌ها فراهم می‌کند. هنگامی‌که IP خروج مسدود شود، خروج را در پشت relay تعویض کنید بدون تغییر کلاینت‌ها:
   ```bash
   meridian relay deploy RELAY_IP --exit EXIT_IP
   ```

2. **حالت Domain را فعال کنید** — fallback WSS/CDN اضافه می‌کند که حتی اگر IP مسدود باشد کار می‌کند:
   ```bash
   meridian deploy EXIT_IP --domain proxy.example.com
   ```

3. **هر دو** — تاب‌آوری حداکثر. کلاینت‌ها سه مسیر دارند: relay (خانگی)، CDN (Cloudflare) و مستقیم (اگر مسدود نباشد).

## کلاینت‌ها و اشتراک‌ها

کلاینت‌ها متعلق به پنل Remnawave هستند، نه یک نود خروجی خاص. `meridian node add` و `meridian relay deploy` میزبان‌ها را به اشتراک‌های موجود اضافه می‌کنند، بنابراین نیازی به ایجاد دوباره کلاینت‌ها نیست.

از کاربران بخواهید اشتراک را تازه‌سازی کنند. `meridian client show NAME` همیشه URL اشتراک و کد QR را دوباره می‌دهد؛ PWA فقط با شواهد صفحه legacy مستقر نمایش داده می‌شود. صفحه گم‌شده legacy را می‌توان با `--repair-page` صریحاً تعمیر کرد.

اگر خود پایگاه‌داده پنل از دست رفته و از پشتیبان قابل بازیابی نیست، باید کلاستر جدید بسازید و هر کلاینت را دوباره ایجاد کنید؛ مهاجرت خودکار بین پنل‌ها هنوز وجود ندارد.

## بازیابی وضعیت محلی

`meridian fleet recover` بازیابی عمومی V4 نیست و فقط با تأیید صریح استقرار shared-profile قدیمی اجرا می‌شود:

```bash
meridian fleet recover --legacy --panel-url https://PANEL_HOST/SECRET_PATH
```

URL باید secret path کامل را داشته باشد. Recovery درباره profile، squad، panel node یا نگاشت مبهم WSS node-to-domain حدس نمی‌زند؛ `sub_path` و Reality key را با SSH بازیابی و نودها را در `servers.json` ثبت می‌کند. V4 intent باید از backup برگردد یا با `meridian setup` بازسازی شود.

## سرور قدیم را نگه دارید

سرور قدیم را فوری حذف نکنید — ممکن است بعد از روز یا هفته‌ها باز شود. می‌توانید به صورت دوره‌ای بررسی کنید:

```bash
meridian test OLD_IP
```

اگر بازگشت کند، سرور خروج احتیاطی شما آماده است.
