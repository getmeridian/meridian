## تشخیص

از ماشین خود اجرا کنید (SSH نیاز نیست):

```
meridian test 198.51.100.10
```

اگر بررسی TCP روی پورت 443 از شبکهٔ شما ناموفق باشد اما از جای دیگری کار کند (شبکهٔ دیگر یا یک VPN)، IP احتمالاً مسدود است. شکست TCP در همه‌جا معمولاً یعنی firewall ابری یا خاموش بودن سرور.

وقتی هیچ‌چیز روی یک خروجی از شبکهٔ شما پاسخ ندهد، `meridian test` در پایان دستور `node replace` را برای آن خروجی چاپ می‌کند (پایین‌تر)؛ با `--json` این دستور در `data.recovery` می‌آید.

برای اینکه ببینید دقیقاً چه چیزی مسدود شده، [`meridian test 198.51.100.10 --probe`](/fa/cli-reference/#نقطه-نظر-سانسورکننده-meridian-test---probe) را از داخل شبکهٔ سانسورشده اجرا کنید: گزارش می‌دهد که IP سرور یا SNI استتار مسدود به نظر می‌رسد. کسانی که CLI ندارند می‌توانند صفحهٔ اتصال خود را باز کنند؛ اگر در شبکهٔ آن‌ها بارگذاری شود، سرور کنترل از آنجا در دسترس است.

## تسکین فوری

اگر شما با **دامنه** deploy کردید (`--domain`) و رکورد از طریق Cloudflare proxied است، مسیرهای XHTTP و WSS همچنان کار می‌کنند — آن‌ها به Cloudflare می‌رسند نه IP مسدود شده. برنامه‌هایی که JSON Xray یا subscription Mihomo استفاده می‌کنند خود تعویض می‌کنند؛ برنامه‌های دیگر می‌توانند ورودی XHTTP یا WSS را به دستی انتخاب کنند.

اگر شما **relay** دارید، کلاینت‌هایی که از طریق آن متصل می‌شوند تاثیر نمی‌پذیرند تا relay خود می‌تواند دوباره خروجی را بدست آورد.

اگر دوستتان نمی‌تواند صفحهٔ دعوت را باز کند اما شما به پنل دسترسی دارید، در فهرست افراد حساب او را انتخاب کنید و یک اتصال تکی از طریق واسط را کپی کنید یا کد QR آن را نشان دهید. آن را خصوصی برای همان شخص بفرستید. برنامهٔ سازگار بدون باز کردن صفحهٔ دعوت از آن استفاده می‌کند. این اتصال تکی به‌روز نمی‌شود؛ وقتی صفحه دوباره در دسترس بود، به اشتراک برگردید.

## گزینه‌های بازیابی

### اضافه کردن خروجی جایگزین

سریع‌ترین مسیر، تا زمانی که سرور کنترل (سروری که سرویس کنترل را اجرا می‌کند) همچنان از ماشین شما قابل دسترس است:

```bash
# 1. یک VPS جدید از provider دریافت کنید (IP جدید)
# 2. آن را به ناوگان اضافه کنید
meridian node add 198.51.100.20 --name replacement
```

کلاینت‌ها حساب‌های خود را نگه می‌دارند. آن‌ها خروجی جدید را در بازخوانی subscription بعدی خود دریافت می‌کنند — اگر خود انجام نشود از کاربران بخواهید در برنامه refresh کنند.

### یا انتقال خروجی مسدود به سرور جدید

`node replace` خروجی را به سرور جدید منتقل می‌کند و ID، کلیدها، مسیرهای پروتکل و relayها را حفظ می‌کند، سپس سرور قدیم را پاکسازی می‌کند:

```bash
meridian node replace exit-1 198.51.100.20
```

کلاینت‌ها در بازخوانی subscription بعدی آدرس جدید را به‌دست می‌آورند. سرور کنترل به این روش نمی‌تواند منتقل شود: آدرس آن بخشی از هر URL اشتراک است.

اگر سرور قدیم از شبکهٔ خود شما هم مسدود باشد، انتقال باز هم ابتدا سرور جدید را مستقر می‌کند و کلاینت‌ها به آن منتقل می‌شوند؛ فقط پاک‌سازی سرور قدیم ناموفق می‌ماند. وقتی مسدودسازی برداشته شد، یا از شبکه‌ای که به سرور قدیم دسترسی دارد، با `meridian apply` آن را تمام کنید. اگر هرگز ممکن نشود (آن را نزد ارائه‌دهنده حذف کرده‌اید یا مسدود می‌ماند)، بگذارید Meridian آن را فراموش کند:

```bash
meridian apply --forget-unreachable
```

در این حالت Meridian از آن پاک‌سازی صرف‌نظر می‌کند؛ سرویس کنترل همچنان آنچه را نزد خود دارد فراموش می‌کند. هر آنچه روی سرور قدیم اجرا می‌شد به کاربران قبلی‌اش سرویس می‌دهد، از جمله کلاینت‌هایی که بعداً حذف می‌کنید، تا وقتی آن را نزد ارائه‌دهنده حذف یا پاک کنید. برای انجام همه در یک گام، `--forget-unreachable` را مستقیماً به `node replace` بدهید.

### اضافه کردن دامنه برای fallback CDN

اگر شما از دامنه استفاده نکردید، یکی به خروجی جدید اضافه کنید:

```bash
meridian node add 198.51.100.20 --domain vpn.example.com
```

مراحل Cloudflare را ببینید [حالت دامنه](/fa/domain-mode/).

### اضافه کردن relay

relay روی سرور خانگی به کاربران یک نقطه ورود می‌دهد که زمانی که IP خارجی مسدود شوند قابل دسترس می‌ماند:

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.20
```

برای اینکه relay را به خروجی دیگری وصل کنید، آن را با `meridian relay remove` حذف کنید و دوباره با `meridian relay add` اضافه کنید و در `--exit` خروجی جدید را بدهید.

### سرور کنترل از دست رفت

اگر سرور کنترل از دست رفته است (حذف شده، توقیف شده یا برای همیشه مسدود شده)، آن را از یک snapshot روی سرور جدیدی بازسازی کنید:

```bash
meridian restore --to 198.51.100.30
```

پس از تغییر از طریق CLI، نسخهٔ رمزنگاری‌شده روی همان رایانه‌ای ذخیره می‌شود که فرمان را اجرا کرده است. تغییرات بعدی پنل ممکن است هنوز در آن نسخه نباشند. در صفحهٔ نمای کلی ببینید آخرین بار چه زمانی یک دستگاه مدیریتی ذخیره را تأیید کرده و از آن زمان چند تغییر ثبت شده است. برای نگهداری وضعیت فعلی، روی رایانه‌ای جداگانه `meridian backup pull` را اجرا کنید یا نسخهٔ رمزنگاری‌شده را از پنل بگیرید. فایل را خارج از VPS و کلید بازیابی را جدا از فایل نگه دارید. شروع دانلود در مرورگر به معنای تأیید ذخیره نیست.

restore ابتدا کارهایی را که انجام خواهد داد برای بازبینی نشان می‌دهد، سپس سرویس کنترل را از همان snapshot روی سرور جدید نصب می‌کند و ناوگان را apply می‌کند: agent هر خروجی در سرور جدید ثبت می‌شود و کلاینت‌ها حساب، محدودیت‌ها و ترافیک خود را نگه می‌دارند.

restore اگر فایل‌های ناوگان روی این ماشین از نسخهٔ داخل snapshot قدیمی‌تر نباشند از همان‌ها استفاده می‌کند، و در غیر این صورت از نسخهٔ snapshot.

restore پیش از هر کاری روی سرور جدید، دو نوع snapshot را رد می‌کند، حتی با `--force`:

- **snapshot ناوگانی دیگر.** snapshot همین ناوگان را انتخاب کنید، یا ناوگان دیگر را در یک زمینهٔ جدید بازیابی کنید (`--context NAME`).
- **پروفایل‌های دسترسی متفاوت.** اگر پروفایل‌های snapshot با پروفایل‌های این ماشین فرق دارند، snapshotی را انتخاب کنید که با آن‌ها می‌خواند، یا در یک زمینهٔ جدید بازیابی کنید و سپس تغییر پروفایل‌ها را با `meridian apply` بازبینی کنید.

روی ماشینی که فایل‌های این ناوگان را نداشت، Meridian فایل‌هایی را که از snapshot خوانده نگه می‌دارد، حتی اگر در مرحلهٔ بازبینی متوقف شوید، تا اجرای بعدی از همان نقطه شروع شود.

- **لینک‌ها**: روی IP خالی، نشانی سرور کنترل بخشی از هر URL اشتراک است، پس همهٔ لینک‌ها عوض می‌شوند؛ restore لینک جدید همه را چاپ می‌کند تا برایشان بفرستید، از جمله کسانی که در پنل وب اضافه کرده‌اید. با دامنه، لینک‌ها همان می‌مانند، به محض اینکه رکورد DNS دامنه به سرور جدید اشاره کند؛ بازبینی نام این رکوردها را می‌آورد.
- **سرور قدیم**: تا وقتی سرور کنترل قدیم پاسخ می‌دهد، restore اجرا نمی‌شود، چون دو سرویس کنترل ناوگان را دو تکه می‌کنند. اگر پاسخ می‌دهد ولی دیگر به آن اعتماد ندارید (مثلاً توقیف شده)، `--force` را بدهید. اگر پیکربندی وب Meridian روی سرور قدیمیِ در دسترس به‌طور ایمن پاک نشد، علت گزارش‌شده را برطرف و همان فرمان بازیابی را دوباره اجرا کنید. داده‌های بازیابی‌شده روی سرور جایگزین باقی می‌مانند.
- **کلیدها**: سرور جدید مرجع صدور گواهی و کلیدهای امضای تازه می‌گیرد، پس سرور توقیف‌شده نمی‌تواند چیزی امضا کند که گره‌های شما بپذیرند. پنل وب بازیابی‌شده هنوز مالکی ندارد، پس restore در پایان یک لینک راه‌اندازی یک‌بارمصرف برای انتخاب رمز عبور تازه چاپ می‌کند (اگر بدون استفاده منقضی شود، `meridian panel` لینک دیگری می‌دهد). سپس کلیدهای پشتیبان رایانه‌های دیگر را فهرست می‌کند و پیشنهاد می‌دهد هر کدام را که دیگر در اختیار ندارید، مثلاً کلید لپ‌تاپ گم‌شده، باطل کنید.
- **ماشین دیگر**: روی ماشینی که ناوگان را ندارد، فایل snapshot را کپی کنید و `meridian restore --to NEW_IP --snapshot FILE` را اجرا کنید؛ اگر این ماشین کلید پشتیبان خودش را نداشته باشد، کلید بازیابی را می‌پرسد. snapshot فایل‌های خود ناوگان را همراه دارد؛ آن ماشین همچنان به دسترسی SSH به سرور جدید و خروجی‌های شما نیاز دارد.

کلید بازیابی فقط یک بار، در پایان اولین deploy، نشان داده می‌شود؛ `meridian backup recovery-key` کلید تازه‌ای می‌سازد. آن را آفلاین و دور از ماشین‌هایی که ناوگان را مدیریت می‌کنند نگه دارید. ببینید [`meridian restore`](/fa/cli-reference/#meridian-restore).

## مدیریت از بیش از یک ماشین

تمام چیزی که Meridian دربارهٔ ناوگان می‌داند در `~/.config/meridian/` روی ماشینی که از آن deploy می‌کنید نگهداری می‌شود. برای مدیریت ناوگان از ماشین دوم، آن دایرکتوری را بدون `device.key` و `snapshots/` کپی کنید تا ماشین دوم در اولین تغییر کلید پشتیبان خودش را بگیرد. پس از هر تغییری که در جای دیگری انجام می‌دهید دوباره کپی کنید. `meridian backup devices` ماشین‌هایی را که snapshot دریافت می‌کنند فهرست می‌کند و `meridian backup revoke` ماشینی را که دیگر استفاده نمی‌کنید حذف می‌کند.

نمی‌توانید به‌طور تصادفی کار ماشین دیگری را خنثی کنید. سرویس کنترل سابقهٔ آخرین تغییر اعمال‌شده را نگه می‌دارد. پیش از هر تغییر، Meridian نسخهٔ شما را با این سابقه مقایسه می‌کند و اگر apply رد شود، `meridian plan` از قبل هشدار می‌دهد:

- **"Another machine changed this fleet"**: نسخهٔ محلی شما قدیمی است. `~/.config/meridian/` را از ماشینی که آخرین تغییر را اعمال کرده کپی کنید و دوباره دستور را اجرا کنید.
- **"Another apply is running"**: همین حالا کسی در حال تغییر ناوگان است. صبر کنید تا کارش تمام شود. اگر آن اجرا از کار افتاده باشد، قفل آن ظرف ۳۰ دقیقه منقضی می‌شود؛ اجرای از کار افتاده روی ماشین خودتان اصلاً جلوی شما را نمی‌گیرد.
- **"This control server belongs to a different copy of the fleet"**: این `~/.config/meridian/` هرگز از ماشینی که این ناوگان را مدیریت می‌کند کپی نشده است.

### اگر رایانهٔ مدیریت گم شد

روی رایانه‌ای مطمئن `meridian backup devices` را اجرا کنید و دستگاه گم‌شده را با `meridian backup revoke ID` لغو کنید. این کار فقط از نسخه‌های بعدی محافظت می‌کند؛ نسخه‌های قبلی پاک نمی‌شوند و دسترسی SSH یا API لغو نمی‌شود.

اگر کل پوشهٔ تنظیمات را روی آن رایانه کپی کرده بودید، فرض کنید اعتبارنامهٔ مشترک مدیر و کلیدهای SSH آن پوشه روی آن بوده‌اند. نخست روی هر سرور ورود با یک کلید مدیریتی دیگر را بررسی کنید و سپس کلید گم‌شده را از تمام حساب‌هایی که آن را می‌پذیرفتند بردارید. توکن‌های محدود API ذخیره‌شده روی آن رایانه را لغو کنید. اعتبارنامهٔ مشترک مدیر را نمی‌توان مانند توکن دستگاه لغو کرد؛ با بازیابی یک نسخهٔ مطمئن روی سرور کنترل جایگزین طبق دستور بالا، اعتبارنامهٔ جدیدی صادر می‌شود. تنظیمات رایانه‌های مدیریتی دیگر را از یک نسخهٔ مطمئن به‌روز کنید. اگر کلید بازیابی روی رایانهٔ گم‌شده بوده، آن را با `meridian backup recovery-key` عوض کرده و یک نسخهٔ رمزنگاری‌شدهٔ تازه ذخیره کنید.

## آماده‌سازی قبل از مسدودسازی

1. **relay اضافه کنید** روی سرور خانگی: `meridian relay add RELAY_IP --exit EXIT_IP`
2. **دامنه استفاده کنید** برای fallback CDN: با `--domain vpn.example.com` deploy کنید
3. **هر دو** — کلاینت‌ها سپس سه راه ورود دارند: relay (خانگی)، CDN (Cloudflare) و مستقیم
4. **کلید بازیابی را آفلاین نگه دارید** — با آن و یک snapshot، `meridian restore` سرور کنترل از دست رفته را بازسازی می‌کند
5. **از `~/.config/meridian/` نسخهٔ پشتیبان بگیرید** — همین است که اجازه می‌دهد ناوگان را از ماشین دیگری مدیریت کنید

## سرور قدیم را نگاه دارید

سرور مسدود شده را فوری حذف نکنید — مسدودسازی‌ها گاهی پس از روز یا هفته برداشته می‌شوند. گاهی بررسی کنید:

```bash
meridian test 198.51.100.10
```

وقتی دیگر نیاز ندارید، آن را با `meridian node remove` حذف کنید.
