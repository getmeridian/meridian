یک دستور، یک VPS تازه را به سرور پراکسی امن و مقاوم تبدیل می‌کند و یک لینک برای اشتراک‌گذاری به شما می‌دهد. این راهنما شما را در چند دقیقه از صفر به یک اتصال آماده می‌رساند.

کسی برایتان لینک فرستاده است؟ به هیچ‌یک از این‌ها نیازی ندارید: [اتصال](/fa/connecting/) را ببینید.

## پیش‌نیازها

شما به این موارد نیاز دارید:
- یک **VPS** با Debian یا Ubuntu که بتوانید با کلید SSH به آن وصل شوید (به‌عنوان `root` یا کاربری با `sudo` بدون گذرواژه)
- یک **ترمینال** روی کامپیوتر خودتان (macOS، Linux یا [WSL روی Windows](/fa/wsl/))

## نصب CLI

```
curl -sSf https://getmeridian.org/install.sh | bash
```

این اسکریپت فرمان `meridian` را با [uv](https://docs.astral.sh/uv/) (یا pipx به‌عنوان جایگزین) نصب می‌کند. برای روش‌های دیگر [نصب](/fa/installation/) را ببینید.

Meridian را روی کامپیوتر خودتان اجرا کنید، نه روی VPS: ابزار از طریق SSH متصل می‌شود، اطلاعات دسترسی را روی دستگاه شما نگه می‌دارد و به `meridian test` اجازه می‌دهد سرور را از بیرون بررسی کند.

> از Meridian 3.x می‌آیید؟ Meridian 4 ارتقای درجا **نیست**. ابتدا [ارتقا از 3.x](/fa/installation/#ارتقا-از-3x) را بخوانید.

## استقرار

```
meridian deploy 198.51.100.10
```

اگر `meridian deploy` را بدون IP اجرا کنید، آدرس را از شما می‌پرسد. اگر مستقیم با کاربر `root` وارد خود VPS شده‌اید، `meridian deploy local` بدون SSH اجرا می‌شود.

## چه اتفاقی می‌افتد

1. **مقاوم‌سازی سرور** — ورود SSH فقط با کلید، fail2ban، فایروال UFW که فقط پورت‌های موردنیاز را باز می‌کند، و کنترل ازدحام BBR
2. **نصب بخش کنترل** — سرویس کنترل Meridian، که کاربران شما را نگه می‌دارد و اشتراک‌هایشان را ارائه می‌کند، و یک agent گره که Xray را اجرا می‌کند. بدون Docker
3. **انتخاب هدف استتار** — ابتدا به دنبال یک سایت مناسب با TLS 1.3 در شبکهٔ خود سرور می‌گردد، و اگر پیدا نشد به سراغ `www.google.com`، `dl.google.com` و `www.cloudflare.com` می‌رود (با `--sni` می‌توانید سایت دلخواهتان را بدهید)
4. **پیکربندی روش‌های اتصال** — VLESS+Reality و XHTTP روی TCP 443 پشت nginx با گواهی Let's Encrypt برای IP سرور، و Hysteria2 روی UDP 443
5. **تأیید ترافیک واقعی** — پیش از نمایش «Done»، ترافیک واقعی را از اشتراک تحویل‌شده عبور می‌دهد و اگر ترافیک نگذرد، هدف استتار بعدی را امتحان می‌کند
6. **انتشار صفحهٔ اتصال** برای اولین کلاینت
7. **نمایش یک‌بارهٔ کلید بازیابی** — آن را آفلاین نگه دارید؛ با آن می‌توان سرور کنترل از دست رفته را بازسازی کرد (ببینید [پشتیبان](/fa/deploy/#پشتیبان))

فرآیند استقرار دارای نقاط ذخیره (checkpoint) است. اگر ارتباط قطع شود، همان دستور را دوباره اجرا کنید تا از همان‌جا ادامه دهد.

## اتصال

پس از پایان استقرار، خروجی شامل این موارد است:

- **لینک صفحهٔ اتصال** همراه با کد QR — این لینک را برای فردی که می‌خواهد وصل شود بفرستید. صفحه شامل لینک دانلود برنامه‌ها، کدهای QR و دکمه‌های افزودن با یک ضربه است.
- **نشانی اشتراک (Subscription URL)** — برای وارد کردن در هر برنامهٔ Xray/V2Ray. برنامه‌ها آن را خودکار به‌روز می‌کنند، بنابراین سرورها و relayهای جدید خودکار اضافه می‌شوند.

برنامه‌های پیشنهادی:

| برنامه | پلتفرم‌ها |
|-----|-----------|
| [Happ](https://happ.su/) | iOS، Android، Windows، macOS، Linux |
| [FlClashX](https://github.com/pluralplay/FlClashX/releases/latest) | Android، Windows، macOS، Linux |
| [Clash Mi](https://clashmi.app/download) | iOS، Android، Windows، macOS، Linux |
| [Throne](https://github.com/throneproj/Throne/releases/latest) | Windows، macOS، Linux |

صفحهٔ اتصال ابتدا این برنامه‌ها را نشان می‌دهد و برای هر پلتفرم لینک برنامه‌های بیشتری دارد.

در هر زمان می‌توانید سرور را از کامپیوتر خودتان آزمایش کنید:

```
meridian test 198.51.100.10
```

## افزودن افراد بیشتر

```
meridian client add alice
```

هر نفر کلید اختصاصی، صفحهٔ اتصال و نشانی اشتراک خودش را می‌گیرد. `meridian client list` فهرست همه را نشان می‌دهد و `meridian client disable alice` دسترسی یک نفر را فوراً قطع می‌کند. [مدیریت کلاینت](/fa/client-management/) را ببینید.

## هر چیز کجا ذخیره می‌شود

| چه چیزی | کجا |
|------|-------|
| توپولوژی، دسترسی سرویس کنترل و کلیدها | `~/.config/meridian/cluster.yml` روی کامپیوتر شما |
| سرورهای ذخیره‌شدهٔ SSH | `~/.config/meridian/servers.json` روی کامپیوتر شما |
| snapshotهای رمزنگاری‌شدهٔ سرویس کنترل | `~/.config/meridian/snapshots/` روی کامپیوتر شما |
| کاربران، محدودیت‌ها و ترافیک | سرویس کنترل روی VPS |
| سرویس‌های پراکسی | Xray، nginx و agent گره روی VPS |

دستورهای `client` با API سرویس کنترل که در `cluster.yml` ثبت شده کار می‌کنند و نیازی به SSH ندارند. `meridian panel` همین افراد را در کنسول وب باز می‌کند. از پوشهٔ `~/.config/meridian/` نسخهٔ پشتیبان بگیرید — Meridian از طریق این پوشه سرورهای شما را مدیریت می‌کند.

## بیش از یک سرور

`meridian deploy` یک سرور را راه‌اندازی می‌کند. برای چند سرور خروجی، relay روی سرور داخلی، یا دروازه‌های مسیریابی، از ویزارد تعاملی استفاده کنید:

```
meridian setup
```

همچنین می‌توانید سرورها را گام‌به‌گام با `meridian node add` و `meridian relay add` اضافه کنید. هر تغییر از همان توپولوژی بازبینی‌شده می‌گذرد؛ `meridian plan` تغییرات را نشان می‌دهد و `meridian apply` آن‌ها را اعمال می‌کند.

## ناوگان‌های جدا

برای جدا نگه داشتن ناوگان‌ها، مثلاً یکی برای خانواده و یکی برای کار، به هر کدام یک زمینهٔ جدا بدهید. اولین deploy در زمینهٔ تازه آن را می‌سازد؛ `context use` آن را زمینهٔ فعلی می‌کند و `--context` یک دستور را روی ناوگان دیگری اجرا می‌کند:

```
meridian deploy 203.0.113.5 --context work
meridian context list
meridian context use work
meridian --context default client list
```

اولین ناوگان شما زمینهٔ `default` است و در `~/.config/meridian/` می‌ماند؛ هر زمینهٔ دیگر `cluster.yml` و سرورهای ذخیره‌شدهٔ خودش را در `~/.config/meridian/contexts/NAME/` نگه می‌دارد. کلید SSH ‏Meridian مشترک است و هر سرور در هر زمان فقط به یک ناوگان تعلق دارد. `MERIDIAN_CONTEXT=NAME` زمینه را برای یک پوسته انتخاب می‌کند؛ `MERIDIAN_HOME` یک ناوگان را ثابت می‌کند و زمینه‌ها را خاموش می‌کند. ببینید: [meridian context](/fa/cli-reference/#meridian-context).
