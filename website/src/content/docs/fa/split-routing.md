## مسئله

Meridian به‌طور پیش‌فرض **server-side geo-blocking** را روشن می‌کند: exit ترافیک را به دامنه‌های روسی (`geosite:category-ru`) و محدوده‌های IP روسی (`geoip:ru`) رها می‌کند. این IP VPS شما را از لاگ‌های خدمات روسی دور می‌کند، جایی که می‌تواند شناخته و مسدود شود.

مشکل: وب‌سایت‌های روسی وقتی VPN روشن است باز نمی‌شوند. کاربران برای دسترسی به Yandex، VK، Gosuslugi و سایر سرویس‌های داخلی باید قطع کنند.

## راه‌حل: split routing روی دستگاه

Split routing ترافیک روسی را **مستقیم** از دستگاه می‌فرستد و سایر ترافیک را از طریق VPN:

```
سایت‌های روسی    → دستگاه → مستقیم → اینترنت (ISP محلی)
سایر ترافیک      → دستگاه → Proxy → VPS → اینترنت
```

شما هر دو را می‌گیرید:
- **محافظت VPS** — server-side block به عنوان شبکه ایمنی می‌ماند
- **سایت‌های روسی کار می‌کنند** — دستگاه آن‌ها را مستقیم می‌فرستد، هرگز از طریق پروکسی نه

## نحوه راه‌اندازی

Split routing در برنامه کلاینت پیکربندی شده است. Meridian هنوز split routing را در subscriptions خود حمل نمی‌کند.

- **Hiddify** — در تنظیمات، منطقه را روی **روسیه** تنظیم کنید. Hiddify سپس سایت‌های روسی را مستقیم می‌فرستد.
- **v2rayNG, v2RayTun, v2rayN و سایر برنامه‌های Xray** — تنظیمات مسیریابی برنامه را باز کنید و قوانین **direct** برای `geosite:category-ru` و `geoip:ru` اضافه کنید.
- **برنامه‌های Mihomo / Clash Meta** — بازخوانی subscription config را جایگزین می‌کند، بنابراین این قوانین را از طریق override برنامه یا merge feature اضافه کنید، بالای قانون `MATCH` نهایی:
  ```yaml
  - GEOSITE,category-ru,DIRECT
  - GEOIP,RU,DIRECT
  ```

نام‌های منو بین برنامه‌ها و نسخه‌ها متفاوت است؛ برای "Routing"، "Region" یا "Bypass" جستجو کنید.

### چرا template را در پنل ویرایش نکنید؟

Meridian template JSON Xray و subscription خود را در Remnawave مدیریت می‌کند — آن‌ها fallback خودکار بین exits و relays شما را حمل می‌کند. Meridian آن‌ها را در هر apply (شامل redeploys و `client add`، `node add`، `relay deploy`) restore می‌کند، بنابراین قوانین اضافه‌شده در پنل آنجا دوام نخواهند داشت. جایگزینی بخش‌های مسیریابی آن‌ها می‌تواند fallback خودکار را نیز خراب کند.

## چگونه لایه‌ها با هم کار می‌کنند

| لایه | آنچه انجام می‌دهد | از چه محافظت می‌کند |
|-------|-------------|-----------------|
| **server-side geo-block** | ترافیک روسی را در exit رها می‌کند | IP VPS در لاگ‌های سرویس روسی ظاهر می‌شود |
| **split routing روی دستگاه** | ترافیک روسی را مستقیم می‌فرستد | سایت‌های روسی شکسته، بار proxy غیرضروری |

با split routing روشن، ترافیک روسی هرگز سرور را نمی‌رسد. اگر دستگاهی قوانین را نداشته باشد (برنامه قدیمی، تلفن جدید)، سرور همچنان مقصد روسی را مسدود می‌کند، بنابراین IP VPS محافظ می‌مانند.

اگر کاربران شما سایت‌های روسی را از طریق VPN نیاز دارند، با `--no-geo-block` deploy کنید.

## ملاحظات DNS

با split routing، دومنه‌های روسی باید از DNS محلی و سایر همه چیز از طریق proxy resolve شود، برای جلوگیری از leaks. برنامه‌هایی که preset منطقه یا bypass دارند معمولاً این را مدیریت می‌کنند. اگر برنامه شما تنظیم DNS جداگانه دارد، DNS leak protection آن را برای ترافیک proxied فعال کنید.
