## مشکل

Meridian به‌طور پیش‌فرض **مسدودسازی جغرافیایی سمت سرور** را فعال می‌کند: سرور Xray ترافیک مقصد دامنه‌ها و IPهای روسی را با قواعد مسیریابی `geosite:category-ru` و `geoip:ru` مسدود می‌کند. این کار از ظاهر شدن IP سرور VPS شما در لاگ سرویس‌های روسی جلوگیری می‌کند.

اما در نتیجه، وب‌سایت‌های روسی از طریق VPN کار نمی‌کنند. کاربران برای دسترسی به Yandex، VK، Gosuslugi و دیگر سرویس‌های داخلی باید اتصال VPN را قطع کنند.

## راه‌حل: مسیریابی تفکیکی سمت کلاینت

مسیریابی تفکیکی، ترافیک مقصد روسیه را **مستقیماً** از کلاینت به اینترنت می‌فرستد (بدون عبور از پروکسی) و سایر ترافیک را از VPN عبور می‌دهد:

```
Russian sites  → Client → Direct → Internet (via local ISP)
Everything else → Client → Proxy → VPS → Internet
```

به این ترتیب، هر دو مزیت را خواهید داشت:
- **محافظت از VPS** — مسدودسازی جغرافیایی سمت سرور به‌عنوان یک لایه ایمنی فعال می‌ماند
- **دسترسی به سایت‌های روسی** — کلاینت ترافیک آن‌ها را مستقیم می‌فرستد و هرگز به پروکسی نمی‌رساند

## نحوه پیکربندی

Meridian از سیستم قالب اشتراک Remnawave استفاده می‌کند. قالب اشتراک تعیین می‌کند کلاینت‌ها هنگام وارد کردن اتصال، کدام قواعد مسیریابی را دریافت کنند.

### گام ۱: باز کردن پنل Remnawave

به URL پنل خود بروید (پس از اجرای `meridian deploy` نمایش داده می‌شود) و وارد شوید.

### گام ۲: ویرایش قالب اشتراک

1. به **Subscription Settings** → **Templates** بروید
2. قالب **Xray JSON** را پیدا کنید (یا یک قالب جدید بسازید)
3. بخش‌های routing/DNS را با پیکربندی مسیریابی تفکیکی زیر جایگزین کنید

### قالب Xray JSON

این بخش‌ها را به قالب اشتراک Xray JSON خود اضافه کنید. بلوک `dns` باعث می‌شود دامنه‌های روسی با سرور DNS محلی حل شوند و بلوک `routing` ترافیک مقصد روسیه را مستقیم می‌فرستد:

```json
{
    "log": {
        "loglevel": "warning"
    },
    "dns": {
        "servers": [
            {
                "address": "https://dns.google/dns-query",
                "domains": ["geosite:geolocation-!cn"]
            },
            "8.8.8.8",
            {
                "address": "localhost",
                "domains": [
                    "geosite:category-ru",
                    "domain:.ru",
                    "domain:.su",
                    "domain:.рф"
                ],
                "expectIPs": ["geoip:ru"]
            }
        ]
    },
    "routing": {
        "domainStrategy": "IPIfNonMatch",
        "rules": [
            {
                "type": "field",
                "domain": ["geosite:private"],
                "outboundTag": "direct"
            },
            {
                "type": "field",
                "ip": ["geoip:private"],
                "outboundTag": "direct"
            },
            {
                "type": "field",
                "domain": [
                    "geosite:category-ru",
                    "domain:.ru",
                    "domain:.su",
                    "domain:.рф"
                ],
                "outboundTag": "direct"
            },
            {
                "type": "field",
                "ip": ["geoip:ru"],
                "outboundTag": "direct"
            }
        ]
    }
}
```

یک نسخه مرجع از این قالب در مسیر `src/meridian/data/subscription-templates/xray-split-ru.json` در کد منبع Meridian قرار دارد.

### قالب Mihomo / Clash

برای کلاینت‌هایی که از Mihomo (Clash Meta) استفاده می‌کنند، این قواعد را به قالب اشتراک اضافه کنید:

```yaml
rules:
  - DOMAIN-SUFFIX,.ru,DIRECT
  - DOMAIN-SUFFIX,.su,DIRECT
  - DOMAIN-SUFFIX,.рф,DIRECT
  - GEOSITE,category-ru,DIRECT
  - GEOIP,RU,DIRECT
  - MATCH,PROXY
```

نسخه مرجع: `src/meridian/data/subscription-templates/mihomo-split-ru.yaml`.

## نحوه همکاری دو لایه

این دو لایه مکمل یکدیگر هستند:

| لایه | کارکرد | در برابر چه چیزی محافظت می‌کند |
|-------|-------------|-----------------|
| **مسدودسازی جغرافیایی سمت سرور** (مسیریابی Xray) | ترافیک مقصد روسیه را در سرور مسدود می‌کند | افشای IP سرور VPS در لاگ سرویس‌های روسی |
| **مسیریابی تفکیکی سمت کلاینت** (قالب اشتراک) | ترافیک مقصد روسیه را مستقیم می‌فرستد و پروکسی را دور می‌زند | از کار افتادن سایت‌های روسی و بار غیرضروری پروکسی |

اگر مسیریابی تفکیکی پیکربندی شده باشد، ترافیک مقصد روسیه هرگز به سرور نمی‌رسد و کلاینت آن را مستقیم می‌فرستد. مسدودسازی جغرافیایی سمت سرور نقش لایه ایمنی را دارد: اگر کلاینتی قالب را اعمال نکند (برنامه قدیمی یا پیکربندی دستی)، سرور همچنان مقصدهای روسی را مسدود می‌کند.

## سازگاری کلاینت

مسیریابی تفکیکی به کلاینت‌هایی نیاز دارد که از قواعد مسیریابی Xray پشتیبانی کنند:

| کلاینت | پلتفرم | پشتیبانی از مسیریابی تفکیکی |
|--------|----------|----------------------|
| v2rayNG | Android | بله (Xray JSON) |
| Hiddify | Android، iOS | بله (Xray JSON) |
| Streisand | iOS | بله (Xray JSON) |
| V2Box | iOS | بله (Xray JSON) |
| Nekoray / Nekobox | دسکتاپ | بله (Xray JSON) |
| Clash Meta / Mihomo | همه | بله (Mihomo YAML، قالب متفاوت) |

کلاینت‌هایی که قواعد مسیریابی را پردازش نمی‌کنند، تمام ترافیک را از پروکسی عبور می‌دهند. سایت‌های روسی از طریق پروکسی کار نخواهند کرد (زیرا مسدودسازی جغرافیایی سمت سرور ترافیک آن‌ها را مسدود می‌کند)، اما IP سرور VPS همچنان محافظت می‌شود.

## ملاحظات نشت DNS

برخی کلاینت‌ها به‌طور پیش‌فرض درخواست‌های DNS را از پروکسی عبور نمی‌دهند. در مسیریابی تفکیکی، این رفتار برای دامنه‌های روسی مطلوب است، زیرا باید با DNS محلی حل شوند. بااین‌حال، درخواست‌های DNS دامنه‌های غیرروسی باید از DNS پروکسی عبور کنند تا از نشت جلوگیری شود.

قالب بالا این کار را با بخش `dns` انجام می‌دهد: دامنه‌های روسی به‌صورت محلی حل می‌شوند (`address: "localhost"`) و سایر دامنه‌ها از DNS-over-HTTPS (`dns.google`) استفاده می‌کنند.

اگر کلاینت شما بخش `dns` را نادیده می‌گیرد (برخی کلاینت‌های سبک چنین رفتاری دارند)، قابلیت داخلی محافظت در برابر نشت DNS را برای ترافیک غیرروسی فعال کنید.
