title: 选择托管
description: 在长期投入前，如何为出口或中继挑选并测试 VPS。
---

Meridian 能正确配置服务器，但无法改变服务器所在的网络位置。即使 Reality 配置得再完美，如果服务器地址被用户所在网络封锁，依然无法连接。本页帮助你在花大钱之前挑选并测试合适的主机商。

你会租用两类服务器，它们的需求不同：

- **出口（Exit）**：把所有流量送往开放互联网，应位于审查国家之外。
- **中继（Relay）**：位于出口前方的小型 TCP 转发器，详见[中继节点](/zh/relay/)。它只需要一个用户能连上的干净地址，对配置要求很低。

## 选型要点

**地址与网络信誉。** 审查方可以封锁或限速单个 IP、整个子网，甚至某家主机商的整片网络。大型知名主机商最容易遭到整段封锁；俄罗斯的部署者反馈，有时连从未运行过代理的同网段邻居也会被一并封禁。位置相对冷门的小型主机商往往更耐用，但一旦某家被到处推荐，也就不再冷门。事先无法凭经验判断，只能实测（见下文）。另外，移动网络比家庭宽带更严格：同一个 IP 可能在家用宽带上正常，却在所有移动运营商网络下无法连接。

**位置与延迟。** 选择到用户网络路由良好、延迟较低的国家。请从用户自己的网络环境测速，而不是从你身在海外的电脑测速。部署前可以用 `meridian check` 查看服务器到伪装目标的连接情况。

**带宽与公平使用条款。** 标称“不限流量”的套餐通常带有公平使用条款（常见为每月数 TB），有些廉价或免费套餐还会限制端口速率。请仔细阅读条款并确认实际端口带宽。中继服务器承载的流量与用户通过它发送的流量完全相等，因此流量额度要与出口同等规划。

**IPv4。** 请确保有公网 IPv4 地址（部分主机商需额外付费）。许多客户端网络仍不支持 IPv6，而且 `meridian scan` 等工具只支持 IPv4。

**付款与账户。** 选择付款方式和注册验证要求适合你的服务商；如果注重隐私，请将账户信息与个人身份隔离。**按小时计费**比包月小幅折扣划算得多，因为它可以让你低成本测试和更换 IP。

**干净的系统与 root 权限。** Meridian 需要全新的 Debian 或 Ubuntu 服务器并支持 SSH 密钥登录。避免选择预装了控制面板或自带未知防火墙规则的镜像。

## 大额投入前先测试 IP

1. 租用支持**按小时计费**或有退款期限的最低配套餐。
2. 运行 `meridian check IP` 进行部署前检查：伪装目标、端口 443、外部可达性、操作系统、磁盘空间和系统时钟。
3. 完成部署后，**从用户所在的网络内部**（分别在家庭宽带和移动网络下）运行 `meridian test` 和 `meridian test --probe`。`--probe` 还会报告看起来被封锁的是服务器 IP 还是伪装 SNI。从审查网络外部测试几乎没有参考价值。
4. 让服务器运行几天后再测一次。有些地址刚开通时可用，几天后才会被限速或封锁。
5. 如果测试失败，销毁该服务器并换一个新地址重新测试。按小时计费能让试错成本降到最低。

如果原本正常的服务器突然无法连接，请参见 [IP 封锁恢复](/zh/recovery/)。

## 不要把出口放在哪里

把出口放在俄罗斯境内非常脆弱：当地主机商受本地法规管辖，可以看到并干预你的服务器，已有不少关于俄罗斯主机商要求身份验证并关停代理服务器的报告。请把出口放在境外；境内服务器只适合作为中继，仅转发加密字节流，**且不运行任何代理软件**。

## 境内中继的风险

当境外 IP 被封锁时，境内主机上的中继很有帮助，但租用中继的人需要承担相应风险：服务器是以其名义在当地法律下租用的，主机商可能要求实名核验或终止服务。中继本身只转发客户端与出口之间端到端加密的 TCP 流量，因此境内主机商只能看到发往出口地址的连接和流量大小，看不到明文内容；针对用户访问内容的滥用投诉也会发往境外出口所在的主机商。以上不构成法律建议：在为他人租用境内中继前，请先了解当地法规与主机商条款。

## 不要依赖单一路径

封锁策略变化很快，建议提前准备多条路径：

- 使用默认设置部署（Reality、XHTTP 和 Hysteria2），并启用[域名模式](/zh/domain-mode/)，让 XHTTP 和 WSS 经由 Cloudflare 传输。
- 在不同主机商和不同网络下准备第二个出口（`meridian node add`），避免单个地址段被封导致全军覆没。
- 为封锁出口地址的网络添加中继。

每个客户端的订阅都包含上述所有路径，使用 Xray JSON 或 Mihomo 订阅的应用会自动在可用路径间切换。

## 伪装目标

主机所在的网络也决定了最佳伪装目标。应选择支持 TLS 1.3、且所在网络与你的服务器放在一起显得自然的知名网站：`meridian scan` 可以在服务器同网段内寻找候选站点。不要手动选择 `apple.com` 或 `icloud.com`（它们的自有网络与 VPS 主机商不匹配），也不要选择 `www.microsoft.com`（其证书链超过 Reality 的限制，会导致部署成功却无法通过任何流量）。详见[选择伪装目标](/zh/deploy/#选择伪装目标)。
