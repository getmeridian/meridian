Meridian 能正确配置服务器，但无法改变服务器所在的网络位置。即使 Reality 配置得再完美，如果服务器地址被用户所在网络封锁，依然无法连接。本页帮助你在花大钱之前挑选并测试合适的主机商。

你会租用两类服务器，它们的需求不同：

- **出口（Exit）**：把所有流量送往开放互联网，应位于审查国家之外。
- **中继（Relay）**：位于出口前方的小型 TCP 转发器，详见[中继节点](/zh/relay/)。它只需要一个用户能连上的干净地址，对配置要求很低。

## 小规模私有 VPN 为什么往往更持久

大型 VPN 服务会因流量特征和所用子网被封锁。小规模私有 VPN 往往能维持更久：用户少、动静小，配合合适的 Reality 伪装目标，看起来像普通 HTTPS 网站。不过，一旦托管子网被整体封锁，其中的所有地址都可能受影响。

## 选型要点

**地址与网络信誉。** 审查方可以封锁或限速单个 IP、整个子网，甚至某家主机商的全部网络。俄罗斯在 2026 年 9 月的一轮封锁中封禁了整个托管子网，连从未运行 VPN 的邻居也受牵连。同网段其他客户的行为可能让你的地址一起失效。位置较冷门的小型主机商往往更持久，但广泛推荐也会引来关注。请测试实际分配的地址，不能只凭主机商名称判断。移动网络通常比家庭宽带更严格：同一 IP 可能在家中正常，却在所有移动运营商网络下无法连接。

**位置与延迟。** 选择到用户网络路由良好、延迟较低的国家。请从用户自己的网络环境测速，而不是从你身在海外的电脑测速。部署前可以用 `meridian check` 查看服务器到伪装目标的连接情况。

**带宽与公平使用条款。** 标称“不限流量”的套餐通常带有公平使用条款（常见为每月数 TB），有些廉价或免费套餐还会限制端口速率。请仔细阅读条款并确认实际端口带宽。中继服务器承载的流量与用户通过它发送的流量完全相等，因此流量额度要与出口同等规划。

**IPv4。** 请计划使用公网 IPv4 地址，并预计部分主机商可能对此额外收费。一些工具（例如 `meridian scan`）仅支持 IPv4。

**付款与账户。** 选择付款方式和注册验证要求适合你的服务商；如果注重隐私，请将账户信息与个人身份隔离。按小时计费比小幅折扣更有价值，因为它能让你低成本地测试。

**干净的系统与 root 权限。** Meridian 需要全新的 Debian 或 Ubuntu 服务器并支持 SSH 密钥登录。避免选择会预装控制面板或你无法掌控的防火墙的主机商。

## 大额投入前先测试 IP

1. **付款前**向主机商索取测试地址。若没有，就租用支持**按小时计费**或有退款期限的最低配套餐，拿到地址后立即测试。
2. 运行 `meridian check IP` 进行部署前检查：伪装目标、端口 443、外部可达性、操作系统、磁盘空间和系统时钟。
3. 完成部署后，**从用户所在的网络内部**（分别在家庭宽带和移动网络下）运行 `meridian test` 和 `meridian test --probe`。`--probe` 还会报告看起来被封锁的是服务器 IP 还是伪装 SNI。从审查网络外部测试几乎没有参考价值。
4. 对比从**同一台服务器**加载小型 HTTPS 页面和下载**超过 32 KB** 的文件。在被封的子网里，TLS 握手可能正常，小页面也能打开，但大文件传输会在约 **16 KB** 后卡住。握手成功或 ping 通都不能排除这种情况。购买前可用主机商的测试页面，部署后则立即测试自己的服务器。
5. 让服务器运行几天后再测一次。有些地址刚开通时可用，几天后才会被限速或封锁。
6. 如果失败，换一个子网或主机商，再重复测试。同一被封子网内的新地址可能仍然有相同问题。

公共多城市 ping 服务可以辅助检查从俄罗斯境内到服务器的可达性。服务会获知你测试的地址，而 ping 不能证明 TLS 传输正常。请直接把地址提交给测试服务，绝不要在公开聊天中发布服务器 IP。

如果原本正常的服务器突然无法连接，请参见 [IP 封锁恢复](/zh/recovery/)。

| 报告可用的出口 | **Webdock**、**noez**、**FirstVDS 荷兰**。noez 的地址被报告为可用，但同网段的其他客户仍可能导致整个子网被封。 |

| 已有人使用的哈萨克斯坦候选 | **hoster.kz**、**Selectel**。请分别检查用户到服务器、中继到服务器的路由。 |

## 不要把出口放在哪里

俄罗斯境内的出口较脆弱：主机商受本地规则约束，可以查看、干预或停止服务器，已有身份核验和关停 VPN 服务器的报告。请把出口放在境外。Meridian 的境内中继使用 Realm 做端口转发，只传递加密字节，**不运行 VPN 软件**。

## 境内中继的风险

境内中继有助于应对境外 IP 封锁，但租用者承担相应风险：服务器以其名义按当地规则租用，主机商可能要求身份核验或终止服务。中继只转发客户端与出口之间端到端加密的 TCP 流量；主机商能看到客户端地址、出口地址和流量大小，看不到明文内容。针对用户互联网活动的滥用投诉会发往出口主机商。

**2026 年 10 月 1 日**公布的“Antifraud 3.0”草案拟要求俄罗斯主机商核验客户身份并询问服务器用途，同时禁止 VPN 托管商使用俄罗斯托管服务一年；提议的最早生效时间为 **2028 年 3 月**。

## 不要依赖单一路径

封锁策略变化很快，建议提前准备多条路径：

- 使用默认设置部署（Reality、XHTTP 和 Hysteria2），并启用[域名模式](/zh/domain-mode/)，让 XHTTP 和 WSS 经由 Cloudflare 传输。
- 在不同主机商和不同网络下准备第二个出口（`meridian node add`），避免单个地址段被封导致全军覆没。
- 为封锁出口地址的网络添加中继。

每个客户端的订阅都包含上述所有路径，使用 Xray JSON 或 Mihomo 订阅的应用会自动在可用路径间切换。

## 伪装目标

托管网络会影响伪装目标的选择。请选择支持 TLS 1.3 和 HTTP/2、在 VPS 附近出现也合理的普通网站；`meridian scan` 会在服务器邻近网络寻找候选站点。Meridian 拒绝 `apple.com` 和 `icloud.com`，因为它们的自治系统（ASN）与 VPS 主机商不匹配；也拒绝 `www.microsoft.com`，因为其证书链过大，Reality 无法传输流量。避免使用 `max.ru` 这类显眼或带玩笑意味的 SNI。详见[选择伪装目标](/zh/deploy/#选择伪装目标)。
