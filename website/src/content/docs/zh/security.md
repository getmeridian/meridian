Meridian **没有遥测、分析或广告**，也不会上传诊断报告。连接页、支持页、网页面板和网站使用自己提供的脚本、样式、字体、图标和 QR 生成工具，**不加载第三方资源**。打开应用商店、支持联系方式或其他外部链接由你决定。

安装、证书续期、DNS 和连接测试需要访问网络。下面列出这些请求及其数据，便于你决定使用哪些服务。

## 报告漏洞

如果你在 Meridian 中发现安全漏洞：

1. **请勿提交公开 issue。**
2. 通过 [GitHub 私密漏洞报告](https://github.com/getmeridian/meridian/security/advisories/new)提交。
3. 附上复现步骤与潜在影响。

我们力争在 48 小时内响应，并在修复说明中致谢报告者。

## 出站请求

接收方都能看到连接机器的 IP 和正常协议头。表格列出额外发送的数据。服务器配置、VPN 客户端凭据和用量记录只发送给你自己的控制服务和服务器。没有一个开关能让整个部署过程离线完成。下载可能跟随来源的重定向，包括 GitHub 发布文件的托管主机。安装器和主机检查使用连接机器配置的 DNS 解析名称。

### 管理电脑上的请求

| 请求 | 何时发生及发送的数据 | 如何控制 |
|------|----------------------|----------|
| **CLI 安装 → `getmeridian.org`、GitHub 与包来源** | 你下载 `https://getmeridian.org/install.sh`。若 uv 尚未安装，安装器会从 astral-sh/uv 获取固定版本脚本及匹配的二进制归档，然后从通常为 PyPI 的包来源安装 Meridian 与依赖，必要时获取托管 Python。发送脚本、文件、包版本和平台请求。 | 只在运行安装器时发生；已有 uv 会跳过自身的引导下载。 |
| **更新通知 → PyPI**（`pypi.org/pypi/meridian-vpn/json`） | 普通文本输出的 CLI 调用最多每分钟查询一次软件包发布列表。请求标识包名，不含服务器配置。JSON 输出和 `serve` 命令跳过查询。 | 设置 `MERIDIAN_DISABLE_UPDATE_CHECK=1`，可关闭后台通知；它不会禁用显式的 `meridian update`。 |
| **`meridian update` → PyPI 和包下载来源** | 查询版本后，通过 uv、pipx 或 pip 安装选定版本及依赖。包管理器向配置的索引发送包名、版本和平台请求，通常访问 PyPI 与 `files.pythonhosted.org`；uv 也可能从 GitHub 下载托管 Python。 | 在需要更新时运行。索引、缓存和离线设置由包管理器控制。 |
| **`meridian fleet upgrade` → GitHub 发布 API** | 存在中继时，读取 Realm 发布及其公布的 SHA-256。发送公开仓库请求；若设置了 `GITHUB_TOKEN`，也会发送该令牌。 | `meridian fleet upgrade --tested` 保留已测试的固定版本，跳过发布查询；安装仍可能需要下载。 |
| **国家建议 → IANA 与对应区域互联网注册机构（RIR）的 RDAP 服务** | 添加出口时，先下载 IANA 的 IPv4/IPv6 注册机构映射，再查询服务器 IP 的注册记录。RIR 会获知该 IP，IANA 只收到映射文件请求。 | 为 `deploy` 或 `node add` 指定 `--country` 可跳过查询。setup 向导在没有已保存地区时也会查询建议。 |
| **本机公网 IP 检测 → `ifconfig.me`、`api.ipify.org` 或 `api64.ipify.org`** | 解析新的 `local` 目标时，向 IP 回显服务查询本机公网地址，失败后尝试备用服务。 | 使用已保存目标或明确的服务器地址，可避免重新检测。 |
| **品牌图片 → 你指定的图片 URL** | 图片图标在管理电脑上下载一次，随后保存为内嵌图片数据。图片主机会收到请求 URL 和 Meridian user-agent 头。 | 使用 emoji 或已有的内嵌图片数据。浏览器不下载原始图片 URL。 |
| **集群管理 → 你自己的服务器与控制服务** | 在线操作发送 SSH 身份验证、命令和文件，或 HTTPS API 令牌以及该操作所需的设置、凭据、命令和备份请求。迁移只读取你指定的旧面板。 | 在线管理所必需；本地审查和导出操作使用各自文档说明的本地状态。 |
| **Xray 测试工具 → GitHub 上的 XTLS/Xray-core 发布** | 本地测试工具缓存不完整时，连接测试会下载对应操作系统和架构的固定版本归档。 | 完整缓存可避免重复下载。需要该工具的测试没有禁用下载的选项。 |

### 检查与服务器安装

| 请求 | 何时发生及发送的数据 | 如何控制 |
|------|----------------------|----------|
| **可达性、伪装和封锁检查 → 被测地址与网站** | `check`、`test`、`--probe`、SNI 选择和部署验证从管理电脑或服务器发送 TCP/TLS/HTTP 请求，携带选定 SNI、HTTP 路径或测试字节。正向和反向域名检查使用机器自身的 DNS 解析器。 | 按需运行可选诊断。部署必须进行验证；指定 SNI 可避免自动扫描邻近网络，但仍会测试该网站。 |
| **连接测试 → IP 回显服务** | 经被测 VPN 隧道向 `api.ipify.org`、`ipv4.icanhazip.com` 或 `v4.ident.me` 发送 HTTPS 请求；IPv6 使用 `api6.ipify.org`、`ipv6.icanhazip.com` 或 `v6.ident.me`。服务看到出口 IP。失败时可能直接重试，使服务也看到管理电脑 IP。 | 将 `MERIDIAN_CONNECT_TEST_URL` 设置为你控制、返回 IP 地址的端点。部署同样使用这些流量测试。 |
| **伪装目标发现 → GitHub 和邻近 TLS 网站** | `scan` 与自动 SNI 建议下载 XTLS/RealiTLScanner 的固定版本，再探测邻近地址，通过 DNS 和 TLS 验证证书名称。网站看到来自服务器的探测。 | 明确指定 `--sni` 可避免自动发现；不需要扫描时不要运行 `scan`。 |
| **系统包与安全更新 → APT 仓库** | 安装从操作系统配置的仓库下载包。基础准备会启用每日包列表刷新和无人值守安全更新，发行版 nginx 不足时从 `nginx.org` 安装。请求标识发行版、架构和软件包。 | 服务器管理员控制 APT 来源和计划；重新应用基础准备会恢复其更新设置。`--no-harden` 不关闭包更新。 |
| **控制服务安装 → GitHub 和 PyPI** | 从 astral-sh/uv 下载固定版本 uv，使用 uv 下载托管 Python，再从 PyPI 或配置的索引获取确切版本的 `meridian-vpn` 及依赖。可编辑开发安装会先在管理电脑上构建 wheel，可能从包索引获取构建依赖，再通过 SSH 上传该 wheel。 | 已是目标版本或缓存齐全时无需下载。正常安装需要包来源。 |
| **中继安装 → GitHub 上的 zhboner/realm 发布** | 安装或更改中继二进制时，下载固定版本 Realm 归档，只发送公开文件请求。 | 已安装匹配版本时无需下载。 |
| **证书工具 → `raw.githubusercontent.com`** | acme.sh 不存在时，从 acmesh-official/acme.sh 下载固定版本脚本，验证后安装。 | 已有安装会被复用。 |
| **证书签发与续期 → Let's Encrypt** | acme.sh 为服务器 IP 或域名发送 ACME 请求，包括证书标识、公钥、账户证明和你提供的联系邮箱。cron 执行续期。证书标识也进入公开的 Certificate Transparency 日志。 | 正常部署需要受信任证书。`MERIDIAN_ACME_SERVER` 可选择其他 ACME CA，不会禁用证书。 |

### 控制服务与节点 agent

| 请求 | 何时发生及发送的数据 | 如何控制 |
|------|----------------------|----------|
| **控制服务文件镜像 → HTTPS 归档来源，通常是 GitHub 上的 Xray 发布** | 启动、节点规格变化或 agent 请求缺失文件时，下载缺少的固定归档。缺失文件请求触发的失败重试最多每分钟一次。仅发送公开文件 URL，不含用户或用量数据。 | 没有禁用镜像的设置。缓存中已有验证过的文件时不访问上游。 |
| **节点 agent → 你的控制服务** | 注册、建立和续期会话、轮询签名文档和命令、报告应用的修订与健康状态、发送每位用户的累计流量、确认命令及获取服务文件。发送注册令牌或身份凭证、会话令牌、节点与构建信息及报告。 | agent 管理节点时必需。停止 agent 也会停止配置管理与流量报告。 |
| **节点 agent → 固定二进制的 HTTPS 来源，通常是 GitHub** | 签名的目标状态文档可能要求下载 Xray 归档。生成的规格先尝试 GitHub，再尝试控制服务镜像。上游看到文件 URL 和 user-agent 中的 agent 构建版本，永远不会收到控制服务令牌。 | 已安装的二进制与归档缓存可避免下载。GitHub 不可达时可用服务镜像；CLI 没有优先使用镜像的开关。 |

**agent 本身不会在节点上从 GitHub 下载自己的二进制。** Meridian wheel 包含 x86_64 和 aarch64 的静态 musl 构建，以及摘要和构建版本文件。管理电脑验证内含构建，再通过 SSH 安装或升级。

### VPN 流量与客户端应用

| 请求 | 何时发生及发送的数据 | 如何控制 |
|------|----------------------|----------|
| **出口 → 用户访问的目标与 Reality 伪装网站** | 转发用户请求的流量。Reality 和 nginx 的伪装回退也会访问选定网站，用于借用 TLS 伪装和处理未认证连接。网站看到出口连接、SNI 和转发的探测流量。nginx 通过主机 DNS 解析伪装目标的名称。 | 你选择伪装网站；self-steal 使用自己的本地网站。访问用户目标是 VPN 的基本功能。 |
| **出口 DNS → Cloudflare、Quad9 与 Google** | 用户目标域名通过可达的 IPv4/IPv6 端点并行发送 DoH 查询：Cloudflare `1.1.1.1` / `2606:4700:4700::1111`，Quad9 `9.9.9.10` / `2620:fe::10`，Google `8.8.8.8` / `2001:4860:4860::8888`，路径均为 `/dns-query`。收到查询的运营商能看到域名和出口 IP。`check` 还会发送固定的示例 DNS 查询。 | CLI 没有 DNS 切换选项。全部失败时，出口域名解析失败，不回退到明文 DNS。即使启用 WARP，这些查询也从主机直接发出。 |
| **可选 WARP → Cloudflare** | 安装从 `pkg.cloudflareclient.com` 获取签名密钥和软件包，warp-cli 注册服务器并建立 WARP 隧道。分配给 WARP 的流量从 Cloudflare 出口访问互联网，Cloudflare 能看到服务器注册信息和出站目标。 | WARP 是可选项；不启用即可避免其安装、注册和隧道。若守护进程已安装，还需在服务器上停止它，才能结束它自身的网络连接。 |
| **可选路由网关 → DNS 服务与出口池测试 URL** | 网关配置使用 `dns.google` 的 Google DoH、`8.8.8.8` 的明文 DNS，并为直连流量使用主机解析器。出口池每 10 秒经出口测试一次，默认访问 `https://www.apple.com/library/test/success.html`；测试网站看到出口 IP 和 HTTP 请求。 | 网关与出口池可选。审查过的出口池配置可将 `probe_url` 指向自有测试端点。网关 DNS 不具备出口的仅加密解析保证。 |
| **Realm 中继 → 下一跳或出口** | 将客户端的加密 TCP 流转发到审查过的配置所指定的目标。不运行 agent、VPN 内核或独立遥测客户端。 | 你选择中继链和出口。 |
| **VPN 应用 → 订阅服务、DNS 与健康测试网站** | 你选择的应用刷新订阅，也可能发起自己的 DNS 和连接测试。Meridian 的 Xray JSON 配置设置 `1.1.1.1` / `8.8.8.8` 明文 DNS，并每分钟探测 Apple 测试页；活动中的 Mihomo 回退组每 5 分钟测试同页；sing-box 配置 Cloudflare 的 TLS 和 UDP DNS，并每 3 分钟测试同页。测试网站看到路径的出口 IP，不收到订阅凭据。 | 应用行为与浏览器页面分开。在应用或其配置中管理 DNS 与健康检查。 |

### 连接页、网页面板与网站

- **连接页和支持页：**只访问自己控制服务的来源，获取页面与配置、账户状态、订阅、共享资源，以及可选的时钟和传输检查。服务收到用户的秘密 URL 与正常浏览器头。QR 生成和图片导出在本地完成，没有第三方请求。
- **网页面板：**只访问自己的服务来源，用于本地资源、登录、会话刷新、API 读写和可见页面刷新。密码、验证器代码、会话 cookie 和编辑内容发送到你的服务，没有第三方请求。
- **网站：**只访问自身来源，包括字体、搜索文件、Markdown 副本和演示资源。网页面板演示在浏览器内回答 API 请求，没有分析、外部字体、第三方嵌入或第三方请求。

应用、文档和支持的外部链接只在你主动点击时打开，不会让页面在后台访问这些网站。

## 下载验证

Xray、Realm、RealiTLScanner、acme.sh 和服务器 uv 安装使用固定版本，并在**执行前校验 SHA-256**。CLI 安装器也会验证固定版本的 uv 安装脚本，该脚本内含归档校验和。Meridian 发布文件提供 `SHA256SUMS`，供运行前验证安装器。摘要不匹配会停止安装。

控制服务镜像和 agent 在发布或解压归档前检查**确切大小与 SHA-256**。agent 在应用固定值前验证控制服务对目标状态的签名。内含静态 musl agent 会对照 wheel 的摘要文件验证，并在 SSH 传输后再次校验。集群升级只有在 GitHub 为所有必需文件公布 SHA-256 时才接受新版 Realm。

控制服务固定 Meridian 包版本。Python 依赖使用包管理器的索引与完整性验证，系统包使用 APT 签名仓库；额外添加的 nginx 和 WARP 仓库还会检查预期签名密钥指纹。下载完整性仍依赖对提供固定摘要的软件包或发布来源的信任。

## 安全设计

- **凭据：**以 `0600` 权限保存于 `~/.config/meridian/cluster.yml`，目录权限为 `0700`。秘密值传入 shell 时使用 `shlex.quote()`，并在 `meridian doctor` 输出中脱敏。以你的系统用户运行的任何程序都能读取这些文件；在已遭入侵的机器上，加密文件也无法防止口令记录或 SSH 会话劫持。请保护管理电脑。
- **控制服务访问：**nginx 在秘密 HTTPS 路径反向代理控制服务，不需要 SSH 隧道。连接页和订阅使用独立路径，不暴露管理路径。CLI 将管理员令牌保存于 `cluster.yml`，脚本使用独立、可撤销且权限受限的令牌。
- **网页面板：**只有一个所有者，使用密码与可选的验证器代码。会话闲置 30 分钟后过期，最长 12 小时。创建令牌或更改隐私需要近期密码确认。网页面板管理用户、通知、语言和隐私，不修改服务器拓扑、不保存 SSH 密钥；它不加载外部内容，并使用严格的内容安全策略（CSP）。
- **节点：**agent 主动通过 HTTPS 连接控制服务，不开放管理端口。节点使用一次性注册令牌加入，持有集群自身 CA 签发的证书。控制服务签署文档，agent 验证签名并拒绝早于已应用状态的文档。
- **隐私：**设备限制和用量历史默认关闭，服务保留累计流量与最后活跃时间。带密钥的设备指纹、完整设备信息或有限保留期的每日流量可主动启用。任何级别都不保存客户端 IP、连接日志或请求路径。参见[隐私](/zh/privacy/)了解服务器被夺取后的后果。
- **备份：**[age](https://age-encryption.org/) 将快照加密给各管理机器的密钥，以及只有你持有私钥的恢复密钥。快照不含签名密钥、会话或网页面板密码；恢复会重新生成，因此旧控制服务器无法签发恢复后集群接受的内容。
- **SSH：**默认禁用密码认证、启用 fail2ban。`--no-harden` 会跳过这两项及防火墙，适用于与其他服务共享的服务器。
- **防火墙：**UFW 只开放 SSH 端口和角色必需端口：TCP/443 用于 VPN 流量，TCP/80 用于证书签发，启用 Hysteria2 时开放 UDP/443，以及中继监听端口。
- **出口 DNS：**用户目标通过 Cloudflare、Quad9 和 Google 的 IP 并行发送 DoH 查询。这些服务商能看到域名，主机商不会在明文 DNS 中收到它们。全部失败时不回退到明文解析。安装检查、伪装域名、网关和应用 DNS 按上文描述的独立方式工作。
- **版本和完整性：**经过验证的二进制下载、签名目标状态及内含静态 musl agent 按上述方式保护安装。控制服务运行确切版本的 Meridian 包。
- **TLS：**[acme.sh](https://github.com/acmesh-official/acme.sh) 通过 Let's Encrypt 签发和续期证书，由 nginx 提供。

## 范围

Meridian 配置 VPN 服务器，本身不实现密码协议。底层安全依赖：

- [Xray-core](https://github.com/XTLS/Xray-core)：VLESS+Reality、XHTTP、WSS 和 Hysteria2。
- [age](https://age-encryption.org/)（通过 pyrage）：快照加密。
- [nginx](https://nginx.org/)：SNI 路由与 TLS 终止。
- [acme.sh](https://github.com/acmesh-official/acme.sh)：Let's Encrypt 证书签发与续期。
- [Realm](https://github.com/zhboner/realm)：中继上的 TCP 转发。
