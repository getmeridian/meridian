## 中继节点解决的问题

当出口服务器的 IP 被封锁时，用户会失去访问权限。中继为他们提供一个更难被封锁的境内入口点：

```
Client → Relay (domestic IP) → Exit server (abroad) → Internet
```

审查者看到的是发往境内 IP 的流量。中继把原始 TCP 流量转发到出口；加密在客户端和出口之间端到端完成，因此中继永远看不到明文。

## 中继如何工作

中继运行 [Realm](https://github.com/zhboner/realm)，一个轻量的零拷贝 TCP 转发器。它监听端口 443（可配置），并将连接转发到出口的 Reality 监听端口。中继服务器上不运行 Docker，也不运行面板。

中继只承载 **Reality** 流量。XHTTP、WSS 和 Hysteria2 仍使用出口自己的地址和域名，并保留在同一份订阅中作为备用方式。

## 部署中继

先部署出口服务器，再将中继指向它：

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.10
```

Meridian 会把中继添加到你的拓扑并应用：
1. 准备中继服务器（系统软件包、BBR、SSH 加固，以及仅开放 SSH 和中继监听端口的防火墙）
2. 将 Realm（版本固定并通过 SHA-256 校验）安装为 systemd 服务
3. 将中继指向出口的 Reality 监听端口
4. 将中继发布到每个客户端的订阅中

### 标志

| 标志 | 默认 | 说明 |
|------|---------|-------------|
| `--exit/-e EXIT` | （必需） | 出口服务器 IP 或名称 |
| `--name NAME` | （自动） | 中继的易记名称（例如 `ru-moscow`） |
| `--port/-p PORT` | 443 | 中继服务器上的监听端口 |
| `--sni HOST` | 出口的目标 | 此中继的 Reality 伪装目标；省略时沿用出口的目标 |
| `--user/-u USER` | root | 中继上的 SSH 用户 |
| `--ssh-port PORT` | 22 | 中继服务器的 SSH 端口 |
| `--yes/-y` | | 跳过确认提示 |

### 包含所有选项的示例

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.10 --name ru-moscow \
  --port 443 --sni dl.google.com --user ubuntu --ssh-port 2222 --yes
```

## 客户端如何连接

现有客户端会在下次订阅刷新时收到该中继，他们的连接页面也会列出它。新增客户端则会自动包含它：

```bash
meridian client add alice   # 自动包含中继
```

## 管理中继

```bash
meridian relay list                       # 所有中继
meridian relay list --exit 198.51.100.10  # 指定出口的中继
```

检查中继各跳的状态——每个 Realm 服务是否在运行、每一跳能否连通下一跳、公开入口是否接受连接——然后对整条路由进行端到端真实流量测试：

```bash
meridian check 203.0.113.10
meridian test
```

`check` 还会测量每一段链路：从每一跳通过下一跳下载出口的伪装网站，发送与客户端相同的 SNI，并报告连接耗时、首字节时间（TTFB）以及接收到的字节数。如果传输在约 8 到 32 KB 之间卡住，这是该段链路被限速的典型特征，会作为警告报告；通常的解决办法是换用另一家主机商（另一个网络或 ASN）的中继服务器。如果伪装网站首页本身小于 32 KB，该段链路检查会判定为“不确定”，而不会算作通过。

要给中继换一个伪装 SNI（例如 `meridian test --probe` 报告其 SNI 被封锁时），可以原地更改。Meridian 会检查出口能否访问新站点，显示审查并应用；旧名称立即失效，应用在下次订阅刷新（每 6 小时）或手动刷新时切换。传入出口自己的 SNI 可让中继重新跟随出口：

```bash
meridian relay sni 203.0.113.10 dl.google.com
```

要停用中继，删除通过它的链。Meridian 显示它将删除什么，请求确认并清理 Realm 服务、防火墙规则和已发布的入口点；现有客户端在下次订阅刷新时丢失中继：

```bash
meridian relay remove 203.0.113.10
```

## 多个中继

将多个中继连接到一个出口，例如在不同的城市或网络：

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.10 --name ru-moscow
meridian relay add 203.0.113.11 --exit 198.51.100.10 --name ru-spb
```

客户端在他们的订阅中收到每个中继。对于超过一个跳的中继链，使用 `meridian setup`。

## 移动网络白名单

在俄罗斯某些移动网络限制期间，运营商只放行白名单内的网站和地址。具体情况因运营商、地区和时间而异，且没有任何运营商会公开白名单。Meridian 不会自动检测或追踪白名单；本节介绍你目前可以配置的方式，以及哪些部分仍需手动确认。

### 部署者反馈的情况

- **不同网络策略不同。** 有些网络似乎只检查连接声明的服务器名称（SNI），有些还会同时检查目标 IP。在只检查名称的网络下，使用白名单内 SNI 的直连 Reality 路径可能就能通过；而在同时检查 IP 的网络下，第一跳必须是白名单内的地址。
- **境内云主机地址通常作为第一跳。** 同一家云厂商并非所有地址都在白名单内：常有人反馈同一家云厂商的某个子网可用，而另一个子网不可用。云厂商还可能限制个人用户、限制重建实例的频率或限制带宽。
- **境外 CDN 地址通常不在移动网络白名单内。** 请把基于 Cloudflare 的[域名模式](/zh/domain-mode/)当作家庭宽带的备用方案，而不是应对移动白名单的办法。
- **中继到出口的链路也可能受阻。** 即使中继本身能被用户连上，它到境外出口的连接仍可能中断。

### 在白名单地址上部署中继

在地址处于用户移动网络白名单内的境内云厂商租用一台小型服务器。社区有人维护可用网段列表，但只有在限制生效期间用真实移动网络实测才能确认。将其添加为中继并指定一个白名单内的域名：

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.10 --name ru-mobile --sni allowed.example.com
```

使用 `--sni` 时，只有该中继在订阅中的条目宣布这个名称。Meridian 在出口上为中继提供一个只能从中继最后一跳访问的专用侦听器，以及一个模仿该名称的 Reality 侦听器（相同密钥）。它只把该名称路由到 Reality，其余流量都发往该站点，因此没有有效密钥而到达中继的探测会看到该站点的真实证书，而不是代理应答。出口自己的伪装目标和其他条目不变。出口必须能以 TLS 1.3 和 HTTP/2 访问该名称；以后可用 `meridian relay sni RELAY NEW_SNI` 更改。

然后检查中继，并在目标移动网络下实测：

```bash
meridian check 203.0.113.10
meridian test
```

在你自己电脑上运行 `meridian test` 无法判断白名单移动网络放行了什么，请在处于该网络下的真实设备上测试。

### 选择出口 SNI

`meridian deploy` 和 `meridian node add` 上的 `--sni` 用于设置出口直连 Reality 路径的伪装目标。目标必须是出口能通过 TLS 1.3 访问的网站，部署时会验证真实流量能否通过，不通则会停止。部署前可用 `meridian check IP --sni HOST` 检查候选网站。在只检查域名的网络中，白名单内的名称可能让直连路径直接通过，但具体哪个名称可用取决于运营商，需要逐一测试。

### Meridian 不做的事

- 不会判断中继 IP 是否在某个运营商的白名单内，也不会检测当前是否处于白名单限制期间。
- 不支持通过境内 CDN 做前置中转。域名模式仅针对 Cloudflare 构建和测试。
- 中继只承载 Reality 流量；XHTTP、WSS 和 Hysteria2 仍直接连接出口。
- 不会通过第三方通话或即时通讯软件建立隧道。

## 故障排查

### 端口冲突

中继服务器上的监听端口已被其他服务占用。可用 `ss -tlnp sport = :443` 查看并停止占用进程，或用 `--port 8443` 换用其他端口。

### 防火墙拦截

请确保中继端口不仅在服务器本机 UFW 中开放，也已在云厂商的安全组或云防火墙中放行。

### 无法连接出口

中继必须能够访问出口的 Reality 端口。运行 `meridian test` 进行端到端测试，并运行 `meridian check EXIT` 检查出口本身的状态。

### 中继服务未运行

在中继服务器上列出转发服务并查看日志。中继主机使用中性名称（`netfwd-*` 服务单元与 `/etc/netfwd/` 配置文件），因此主机上不会出现 Meridian、Realm 或 relay 等字样：

```bash
systemctl list-units 'netfwd-*'
journalctl -u 'netfwd-*' --no-pager -n 20
```
