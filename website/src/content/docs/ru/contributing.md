## Как сообщить о проблеме

- **Нашли ошибку в работе?** Воспользуйтесь [шаблоном отчёта об ошибке](https://github.com/getmeridian/meridian/issues/new?template=bug_report.yml) — перед этим запустите `meridian doctor`
- **Не устанавливается соединение?** Воспользуйтесь [шаблоном проблемы с подключением](https://github.com/getmeridian/meridian/issues/new?template=connection_issue.yml) — предварительно выполните `meridian test` и `meridian check`
- **Хотите предложить улучшение?** Заполните [шаблон предложения функции](https://github.com/getmeridian/meridian/issues/new?template=feature_request.yml)
- **Обнаружили уязвимость безопасности?** См. раздел [Безопасность](/ru/security/) — **не** создавайте публичный issue

## Настройка окружения

```bash
git clone https://github.com/getmeridian/meridian.git && cd meridian

# Установить CLI в режиме разработки со всеми зависимостями
make install

# Установить git-хук pre-push (быстрые проверки перед отправкой изменений)
make hooks

# Запустить полный набор проверок CI локально
make ci

# Отдельные проверки:
make test              # pytest
make lint              # ruff check
make format-check      # ruff format --check
make typecheck         # mypy
make templates         # проверка рендеринга шаблонов Jinja2
```

## Структура проекта

CLI представляет собой пакет Python (`src/meridian/`), публикуемый в PyPI под именем `meridian-vpn`.

Основные модули:
- `cli.py` — приложение Typer и регистрация команд
- `commands/` — отдельные модули реализации подкоманд
- `cluster.py` + `cluster_persistence.py` — типизированная модель состояния `cluster.yml` и атомарное сохранение на диск
- `servers.py` — реестр сохранённых серверов (`ServerRegistry`)
- `setup/` — черновик мастера `meridian setup` и общая среда выполнения для `deploy`, `setup` и `apply`
- `compiler/` — чистый компилятор топологии в детерминированный список ресурсов с хешем плана (без операций ввода-вывода)
- `reconciler/` — сверка и пошаговое применение скомпилированных ресурсов с сохранением контрольных точек
- `provision/` — базовые шаги подготовки сервера (системные пакеты, защита SSH и файрвола, сервис управления, Realm)
- `control/` — сервис управления (`meridian serve`): пользователи, выдача подписок, подписанные документы для узлов, резервные копии и веб-панель
- `backup/` — шифрование снимков состояния, ключи устройств и команда `meridian restore`

Агент узла (`netagent`) написан на Rust и находится в каталоге `agent/` в корне репозитория; статические бинарные сборки поставляются внутри пакета Python.

## Оформление Pull Request

1. Сделайте форк репозитория и создайте ветку от `main`
2. Делайте изменения компактными и посвящёнными одной задаче
3. Убедитесь, что локальный прогон `make ci` проходит без ошибок
4. По возможности проверьте работу на реальном VPS
5. Откройте PR с чётким описанием задачи и принятого решения

## Ключевые правила кода

- **Все аргументы внешних команд экранируются через `shlex.quote()`** — никогда не подставляйте необработанные строки в вызовы `conn.run()`
- **Синхронизация каталога приложений PWA** (`templates/pwa/` и `website/src/data/apps.json` проверяются в CI)
- **Файлы конфигурации nginx** создаются отдельно для каждого ресурса под именами `meridian-v4-*.conf` в `/etc/nginx/stream.d/` и `/etc/nginx/sites-available/`
- **Шаги подготовки сервера (`provision/`)** идемпотентны и возвращают типизированный `StepResult` (`ok`/`changed`/`skipped`/`failed`)

## Тестирование

В CI автоматически проверяются модульные и интеграционные тесты Python, линтер и форматтер `ruff`, типизация `mypy`, рендеринг шаблонов, контракты и документация CLI/API. Для сквозной проверки многоузлового развёртывания в контейнерах Docker используйте `make system-lab`, а для тестирования на реальных облачных серверах — `make real-lab`.
