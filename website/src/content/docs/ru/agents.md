Meridian создавался с расчётом не только на людей, но и на ИИ-агентов. Агент может разворачивать серверы, добавлять пользователей, проверять состояние узлов и разбирать причины сбоев теми же командами, которыми пользуетесь вы.

## Познакомьте агента с Meridian

Попросите агента перед началом работы выполнить команду:

```bash
meridian help agents
```

Она выводит краткое руководство для агентов в формате Markdown: что делает Meridian, как устроена конфигурация серверов, где хранится состояние, правила безопасной работы с CLI, коды возврата и типовые сценарии. Это же руководство доступно по адресу [getmeridian.org/agents.md](https://getmeridian.org/agents.md).

Чтобы агент помнил об этом всегда, добавьте строку в файл инструкций вашего проекта (`AGENTS.md`, `CLAUDE.md` или аналогичный файл для вашего инструмента):

```markdown
Наши VPN-серверы управляются через Meridian. Перед работой с ним выполните `meridian help agents`.
```

## Что CLI даёт агентам

- **Работа без интерактивных вопросов.** Все команды, вносящие изменения, поддерживают флаг `--yes`. Пошаговому мастеру `setup` нужен интерактивный терминал, поэтому агенты используют команды `deploy`, `node add`, `relay add` и `client add` либо запускают `setup --intent FILE --yes`.
- **Единый JSON-конверт.** При указании `--json` команды выводят в `stdout` один JSON-объект в формате `meridian.output/v1` (в том числе при ошибках). Ход выполнения и предупреждения направляются в `stderr`.
- **Машиночитаемые контракты.** Команда `meridian api commands` перечисляет все команды, у которых есть формальный контракт, а `meridian api schema NAME` выводит соответствующую JSON Schema.
- **Понятные коды возврата.** `0` — успешно, `2` — ошибка во входных параметрах, `3` — не удалось получить необходимые данные (по SSH, от сервиса управления или из локальных файлов), `4` — проверка завершилась и обнаружила неполадки. Подробности по каждой команде приведены в [справочнике CLI](/ru/cli-reference/).
- **Проверка перед применением.** `meridian plan` показывает, что именно изменится, а `meridian apply --yes` применяет ровно этот проверенный план.

## Что документация даёт агентам

- **Каждая страница доступна в Markdown.** Достаточно добавить `.md` к адресу любой страницы, например [/ru/relay.md](/ru/relay.md). Ссылка на Markdown-версию также указана в теге `<head>` каждой страницы.
- **Кнопки «Скопировать страницу» и «Открыть в…».** Под заголовком любой страницы можно скопировать её текст в формате Markdown или сразу открыть в ChatGPT или Claude.
- **Индекс `llms.txt`.** По адресу [/llms.txt](/llms.txt) находится оглавление документации для языковых моделей, а в файле [/llms-full.txt](/llms-full.txt) собрана вся документация целиком.

## Не отправляйте секреты в общие чаты

Страницы подключения и ссылки на подписку дают полный доступ к вашему VPN любому, у кого они есть. В руководстве для агентов явно указано передавать персональные ссылки только тому человеку, для которого они созданы, и никогда не выводить ссылку для настройки веб-консоли без вашей прямой просьбы. Не вставляйте рабочие ссылки в чаты, к которым есть доступ у посторонних. Для публикации отчётов об ошибках используйте `meridian doctor` — эта команда автоматически скрывает все секретные данные.
