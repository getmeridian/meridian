Одна команда превращает свежий VPS в затвердённый, необнаруживаемый прокси и даёт вам ссылку для обмена. Это руководство берёт вас от нуля к рабочему подключению за несколько минут.

## Предусловия

Вам нужны:
- **VPS** работающий Debian или Ubuntu, которого вы можете достичь по SSH с ключом, как root или пользователь с passwordless sudo
- **Терминал** на вашей собственной машине (macOS, Linux или [WSL на Windows](/docs/ru/wsl/))

## Установить CLI

```
curl -sSf https://getmeridian.org/install.sh | bash
```

Это устанавливает команду `meridian` с [uv](https://docs.astral.sh/uv/) (или pipx как возврат). См. [Installation](/docs/ru/installation/) для других вариантов.

Запустите Meridian на вашей собственной машине вместо на VPS: он подключается по SSH, сохраняет учётные данные на вашем устройстве и позволяет `meridian test` проверить сервер снаружи.

> Приходит из Meridian 3.x? 4.0 не является обновлением на месте. Прочитайте [Upgrading from 3.x](/docs/ru/installation/#upgrading-from-3x) сначала.

## Развернуть

```
meridian deploy 198.51.100.10
```

Запустите `meridian deploy` без IP и он спросит его. Если вы вошли на VPS сами как root, `meridian deploy local` пропускает SSH.

## Что происходит

1. **Затвердевает сервер** — SSH только по ключу, fail2ban, UFW брандмауэр, который открывает только то, что требуется развёртыванию, BBR управление перегруженностью
2. **Устанавливает контроль-план** — панель [Remnawave](https://remna.st/), плюс узел работающий Xray, всё в Docker
3. **Выбирает цель маскировки** — сервер пытается `www.google.com`, `dl.google.com` и `www.cloudflare.com` и использует первый, который может достичь (передайте `--sni` для выбора вашей собственной)
4. **Конфигурирует VLESS+Reality** на портс 443 позади nginx, с сертификатом Let's Encrypt для IP сервера
5. **Проверяет реальный трафик** — Meridian пропускает трафик через доставленную подписку перед тем как сказать "Done" и переходит к следующей цели маскировки если трафик не проходит
6. **Публикует страницу подключения** для первого клиента

Развёртывание проверяется контрольными точками. Если оно прервано, запустите ту же команду снова и оно завершится там, где остановилось.

## Подключить

Когда развёртывание завершится, оно выводит:

- **Ссылку на страницу подключения** с QR кодом — отправьте это человеку, который будет подключаться. Страница содержит ссылки загрузки приложения, QR коды и однокасание "Open in app" кнопки.
- **URL подписки** — вставьте его в любое приложение Xray/V2Ray. Приложения обновляют её, поэтому новые серверы и ретрансляторы появляются автоматически.

Рекомендуемые приложения:

| Платформа | Приложение |
|----------|-----|
| iOS | [v2RayTun](https://apps.apple.com/app/v2raytun/id6476628951) |
| Android | [v2rayNG](https://github.com/2dust/v2rayNG/releases/latest) |
| Windows | [v2rayN](https://github.com/2dust/v2rayN/releases/latest) |
| Все платформы | [Hiddify](https://github.com/hiddify/hiddify-app/releases/latest) |

Проверьте сервер с вашей машины в любой момент:

```
meridian test 198.51.100.10
```

## Добавить больше людей

```
meridian client add alice
```

Каждый человек получает свой собственный ключ, страницу подключения и URL подписки. `meridian client list` показывает всех, и `meridian client disable alice` отключает кого-то немедленно. См. [Client management](/docs/ru/client-management/).

## Где вещи живут

| Что | Где |
|------|-------|
| Топология, доступ к панели и ключи | `~/.meridian/cluster.yml` на вашей машине |
| Сохранённые SSH серверы | `~/.meridian/servers.json` на вашей машине |
| Сервисы прокси | Docker, Xray, nginx на VPS |

Команды client говорят с API панели Remnawave записанным в `cluster.yml`; они не требуют SSH. Сделайте резервную копию `~/.meridian/` — это то, как Meridian управляет вашими серверами.

## Более одного сервера

`meridian deploy` охватывает одиночный сервер. Для нескольких выходов, ретрансляторов через внутренний сервер или маршрутизирующих шлюзов, используйте пошаговый мастер:

```
meridian setup
```

Вы также можете расти развёртывание одном шагом за раз с `meridian node add` и `meridian relay deploy`. Каждое изменение проходит через ту же рассмотренную топологию; `meridian plan` показывает, что будет изменено и `meridian apply` применяет это.
