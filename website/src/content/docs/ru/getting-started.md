Одна команда превращает чистый VPS в защищённый VPN-сервер и выдаёт готовую ссылку для подключения. Это руководство поможет пройти весь путь от установки до рабочего VPN за несколько минут.

Вам прислали готовую ссылку для подключения? Настраивать сервер не нужно — сразу переходите к инструкции [Подключение](/ru/connecting/).

## Что понадобится

- **Виртуальный сервер (VPS)** с чистой ОС Debian или Ubuntu и доступом по SSH (от имени `root` или пользователя с беспарольным `sudo`)
- **Терминал** на вашем компьютере (macOS, Linux или [WSL в Windows](/ru/wsl/))

## Установка CLI

```
curl -sSf https://getmeridian.org/install.sh | bash
```

Скрипт установит утилиту `meridian` с помощью [uv](https://docs.astral.sh/uv/) (или `pipx`). Другие варианты установки описаны в разделе [Установка](/ru/installation/).

Устанавливайте и запускайте Meridian на своём компьютере, а не на самом VPS: так ключи управления останутся у вас, а команда `meridian test` сможет проверять доступность сервера снаружи, глазами реального клиента.

> Пользовались Meridian 3.x? Четвёртая версия не ставится поверх 3.x. Сначала ознакомьтесь с разделом [Обновление с 3.x](/ru/installation/#обновление-с-3x).

## Развёртывание сервера

```
meridian deploy 198.51.100.10
```

Если запустить `meridian deploy` без аргументов, команда сама спросит IP-адрес сервера. Если вы всё же запустили Meridian прямо на VPS под пользователем `root`, укажите `meridian deploy local`, чтобы пропустить подключение по SSH.

## Что происходит при развёртывании

1. **Базовая защита сервера** — отключение входа по паролю в SSH, настройка fail2ban, закрытие всех лишних портов в файрволе UFW и включение алгоритма управления перегрузкой BBR
2. **Установка сервиса управления и агента** — на сервер ставятся сервис управления Meridian (хранит пользователей и выдаёт подписки) и агент узла, управляющий Xray. Никакого Docker и громоздких сторонних панелей
3. **Подбор сайта для маскировки (SNI)** — Meridian ищет подходящий сайт с поддержкой TLS 1.3 в собственной подсети сервера, а если не находит, проверяет `www.google.com`, `dl.google.com` и `www.cloudflare.com` (выбрать свой сайт можно флагом `--sni`)
4. **Настройка протоколов подключения** — поднимаются VLESS+Reality и XHTTP на порту TCP 443 за nginx (с автоматическим выпуском сертификата Let's Encrypt для IP-адреса сервера), а также Hysteria2 на порту UDP 443
5. **Проверка реального прохождения трафика** — прежде чем сообщить об успешном завершении, Meridian прогоняет тестовый трафик через созданную подписку и при неудаче автоматически переключается на следующий сайт маскировки
6. **Публикация страницы подключения** для первого пользователя
7. **Вывод ключа восстановления** — показывается один раз в конце установки; сохраните его в надёжном месте, чтобы при потере сервера управления можно было развернуть копию на новом IP (см. [Резервные копии](/ru/deploy/#резервные-копии))

Каждый шаг установки сохраняется в контрольных точках: если соединение оборвётся, повторный запуск той же команды продолжит настройку с места остановки.

## Как подключиться

По завершении настройки в терминале появятся:

- **Ссылка на страницу подключения** и QR-код — отправьте эту ссылку человеку, которому нужен VPN. На странице есть ссылки на скачивание приложений, QR-код и кнопка добавления профиля в одно нажатие.
- **Ссылка на подписку** — та же самая ссылка подходит для прямого добавления в любое приложение с поддержкой Xray, Mihomo или sing-box. Приложения сами периодически обновляют подписку и подхватывают новые серверы.

Рекомендуемые клиентские приложения:

| Приложение | Платформы |
|-----|-----------|
| [Happ](https://happ.su/) | iOS, Android, Windows, macOS, Linux |
| [FlClashX](https://github.com/pluralplay/FlClashX/releases/latest) | Android, Windows, macOS, Linux |
| [Clash Mi](https://clashmi.app/download) | iOS, Android, Windows, macOS, Linux |
| [Throne](https://github.com/throneproj/Throne/releases/latest) | Windows, macOS, Linux |

На странице подключения эти приложения предложены первыми, а в выпадающем списке доступны и другие популярные клиенты.

Проверить работу сервера со своего компьютера можно в любой момент:

```
meridian test 198.51.100.10
```

## Как добавить других людей

```
meridian client add alice
```

Для каждого человека создаются персональный ключ и личная страница подключения. Команда `meridian client list` выводит список всех пользователей, а `meridian client disable alice` мгновенно приостанавливает доступ. Подробнее см. в разделе [Управление клиентами](/ru/client-management/).

## Где что хранится

| Данные | Расположение |
|------|-------|
| Топология серверов, адрес и токен сервиса управления, ключи | `~/.config/meridian/cluster.yml` на вашем компьютере |
| Список сохранённых SSH-серверов | `~/.config/meridian/servers.json` на вашем компьютере |
| Зашифрованные резервные снимки сервиса управления | `~/.config/meridian/snapshots/` на вашем компьютере |
| База пользователей, лимиты и статистика трафика | Сервис управления на VPS |
| Прокси-сервисы и маршрутизация | Xray, nginx и агент узла на VPS |

Команды `meridian client ...` общаются с сервисом управления по HTTPS API из `cluster.yml` и не требуют подключения по SSH. Команда `meridian panel` выводит ссылку на веб-консоль владельца, где можно управлять пользователями из браузера. Рекомендуем сохранить резервную копию папки `~/.config/meridian/`.

## Расширение до нескольких серверов

Команда `meridian deploy` предназначена для быстрой настройки одного сервера. Если вам нужно объединить несколько выходных серверов в разных странах, добавить промежуточные серверы внутри страны или настроить шлюз маршрутизации, запустите пошаговый мастер:

```
meridian setup
```

Расширять существующую конфигурацию можно и отдельными командами `meridian node add` и `meridian relay add`. Любые изменения проходят через единую проверку плана: `meridian plan` показывает предстоящие изменения, а `meridian apply` применяет их.

## Несколько независимых наборов серверов (контексты)

Если вы обслуживаете несколько не связанных друг с другом VPN (например, один для семьи, другой для рабочей команды), разделите их по контекстам. Первое развёртывание с флагом `--context` создаёт новый контекст, команда `context use` переключает активный контекст, а флаг `--context` позволяет выполнить разовую команду для другого набора серверов:

```
meridian deploy 203.0.113.5 --context work
meridian context list
meridian context use work
meridian --context default client list
```

Основной набор серверов называется `default` и хранится в `~/.config/meridian/`, а дополнительные контексты располагаются в `~/.config/meridian/contexts/NAME/`. Управляемый SSH-ключ у всех контекстов общий, но каждый физический сервер в один момент времени может входить только в один контекст. Переменная окружения `MERIDIAN_CONTEXT=NAME` переключает контекст в рамках текущей сессии терминала, а `MERIDIAN_HOME` привязывает CLI к одному каталогу и отключает переключение контекстов. Подробнее см. [`meridian context`](/ru/cli-reference/#meridian-context).
