Одна команда превращает чистый VPS в защищённый VPN-сервер и выдаёт ссылку, которой можно поделиться. Это руководство проведёт вас от нуля до рабочего подключения за несколько минут.

Вам прислали ссылку? Всё это вам не нужно: см. [Подключение](/ru/connecting/).

## Что понадобится

Вам понадобятся:
- **VPS** с Debian или Ubuntu, к которому можно подключиться по SSH с ключом — от имени `root` или пользователя с `sudo` без пароля
- **Терминал** на вашем компьютере (macOS, Linux или [WSL в Windows](/ru/wsl/))

## Установка CLI

```
curl -sSf https://getmeridian.org/install.sh | bash
```

Скрипт устанавливает команду `meridian` через [uv](https://docs.astral.sh/uv/) (или pipx как запасной вариант). Другие способы описаны в разделе [Установка](/ru/installation/).

Запускайте Meridian на своём компьютере, а не на VPS: он подключается по SSH, хранит учётные данные на вашем устройстве и позволяет команде `meridian test` проверять сервер снаружи.

> Переходите с Meridian 3.x? Meridian 4 не обновляет серверы 3.x на месте. Сначала прочитайте раздел [Обновление с 3.x](/ru/installation/#обновление-с-3x).

## Развёртывание

```
meridian deploy 198.51.100.10
```

Если запустить `meridian deploy` без IP-адреса, команда спросит его. Если вы уже вошли на сам VPS под `root`, команда `meridian deploy local` выполнит установку без SSH.

## Что происходит

1. **Защищает сервер** — вход по SSH только по ключу, fail2ban, файрвол UFW (открывает только нужные порты) и алгоритм управления перегрузкой BBR
2. **Устанавливает компоненты управления** — сервис управления Meridian, который хранит ваших пользователей и отдаёт их подписки, и агент узла, который запускает Xray. Без Docker
3. **Выбирает сайт для маскировки** — сначала ищет подходящий сайт с TLS 1.3 в собственной сети сервера, а если не находит, пробует `www.google.com`, `dl.google.com` и `www.cloudflare.com` (передайте `--sni`, чтобы выбрать свой)
4. **Настраивает способы подключения** — VLESS+Reality и XHTTP на TCP 443 за nginx с сертификатом Let's Encrypt для IP-адреса сервера, а также Hysteria2 на UDP 443
5. **Проверяет реальный трафик** — прежде чем вывести «Done», Meridian пропускает трафик через готовую подписку и переключается на следующую цель маскировки, если трафик не проходит
6. **Публикует страницу подключения** для первого клиента
7. **Один раз показывает ключ восстановления** — храните его офлайн: с ним можно восстановить потерянный сервер управления (см. [Резервные копии](/ru/deploy/#резервные-копии))

Развёртывание сохраняет контрольные точки. Если оно прервалось, запустите ту же команду ещё раз — она продолжит с места остановки.

## Подключение

Когда развёртывание завершится, команда выведет:

- **Ссылку на страницу подключения** с QR-кодом — отправьте её человеку, который будет подключаться. На странице есть ссылки для скачивания приложений, QR-коды и кнопки подключения в одно касание.
- **URL подписки** — его можно вставить в любое приложение для Xray/V2Ray. Приложения сами обновляют подписку, поэтому новые серверы и промежуточные серверы появляются автоматически.

Рекомендуемые приложения:

| Приложение | Платформы |
|-----|-----------|
| [Happ](https://happ.su/) | iOS, Android, Windows, macOS, Linux |
| [FlClashX](https://github.com/pluralplay/FlClashX/releases/latest) | Android, Windows, macOS, Linux |
| [Clash Mi](https://clashmi.app/download) | iOS, Android, Windows, macOS, Linux |
| [Throne](https://github.com/throneproj/Throne/releases/latest) | Windows, macOS, Linux |

Страница подключения показывает эти приложения первыми и даёт ссылки на другие приложения для каждой платформы.

Проверить сервер со своего компьютера можно в любой момент:

```
meridian test 198.51.100.10
```

## Добавление пользователей

```
meridian client add alice
```

Каждый человек получает собственный ключ, страницу подключения и URL подписки. `meridian client list` показывает всех пользователей, а `meridian client disable alice` сразу отключает доступ. Подробнее — в разделе [Управление клиентами](/ru/client-management/).

## Где что хранится

| Что | Где |
|------|-------|
| Топология, доступ к сервису управления и ключи | `~/.config/meridian/cluster.yml` на вашем компьютере |
| Сохранённые серверы SSH | `~/.config/meridian/servers.json` на вашем компьютере |
| Зашифрованные снимки сервиса управления | `~/.config/meridian/snapshots/` на вашем компьютере |
| Пользователи, лимиты и трафик | Сервис управления на VPS |
| Сервисы VPN | Xray, nginx и агент узла на VPS |

Команды `client` обращаются к API сервиса управления, записанному в `cluster.yml`; SSH им не нужен. `meridian panel` открывает тех же людей в веб-консоли. Сохраните резервную копию `~/.config/meridian/` — через эту папку Meridian управляет вашими серверами.

## Несколько серверов

`meridian deploy` настраивает один сервер. Если вам нужно несколько выходов, промежуточные серверы внутри страны или маршрутизирующие шлюзы, используйте пошаговый мастер:

```
meridian setup
```

Добавлять серверы можно и по одному с помощью `meridian node add` и `meridian relay add`. Каждое изменение проходит через ту же одобренную топологию: `meridian plan` показывает, что изменится, а `meridian apply` применяет план.

## Отдельные наборы серверов

Чтобы держать серверы раздельно, например для семьи и для работы, заведите для каждого набора свой контекст. Первый `deploy` в новый контекст создаёт его, `context use` делает его текущим, а `--context` выполняет одну команду для другого набора:

```
meridian deploy 203.0.113.5 --context work
meridian context list
meridian context use work
meridian --context default client list
```

Ваши первые серверы — это контекст `default`, и они остаются в `~/.config/meridian/`; каждый другой контекст хранит свой `cluster.yml` и сохранённые серверы в `~/.config/meridian/contexts/NAME/`. SSH-ключ Meridian общий, а один сервер одновременно принадлежит только одному набору. `MERIDIAN_CONTEXT=NAME` выбирает контекст для одной оболочки; `MERIDIAN_HOME` закрепляет один набор серверов и отключает контексты. Подробнее: [meridian context](/ru/cli-reference/#meridian-context).
