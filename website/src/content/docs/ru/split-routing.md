## Проблема

По умолчанию Meridian включает **геоблокировку на стороне сервера**: выходной сервер отбрасывает трафик к российским доменам (`geosite:category-ru`) и российским диапазонам IP (`geoip:ru`). Это не даёт IP-адресу вашего VPS попасть в логи российских сервисов, где его могут заметить и заблокировать.

Обратная сторона: российские сайты не открываются через сам VPN. Без раздельной маршрутизации пользователям приходилось бы выключать VPN, чтобы зайти на Яндекс, ВК, Госуслуги и другие российские сайты.

## Решение: раздельная маршрутизация на устройстве

Раздельная маршрутизация отправляет российский трафик **напрямую** с устройства, а всё остальное — через VPN:

```
Российские сайты → Устройство → Напрямую → Интернет (местный провайдер)
Всё остальное    → Устройство → Прокси → VPS → Интернет
```

Вы получаете сразу оба преимущества:
- **Защита VPS** — блокировка на сервере остаётся включённой как страховка
- **Работающие российские сайты** — устройство открывает их напрямую, мимо VPN

## Как это работает в Meridian

По умолчанию на устройствах выбран режим **`ru-split`**. Подписки Xray JSON, Mihomo и Stash направляют напрямую:

- адреса локальной сети (`geosite:private`, `geoip:private`)
- домены `.ru`, `.su` и `.рф`, а также `geosite:category-ru`
- российские диапазоны IP (`geoip:ru`)

sing-box использует тот же режим, но только встроенные правила для частных IP-адресов и трёх российских доменных зон. Он не загружает списки geosite и geoip, поэтому другие российские домены и IP-диапазоны могут идти через VPN.

Оба режима блокируют QUIC (UDP 443) после правил прямого доступа, чтобы приложения переходили на TCP. В обоих также сохранено **правило прямого подключения для BitTorrent в Xray JSON**, чтобы уменьшить число жалоб на выходные серверы. Оно срабатывает только для распознанных соединений с пирами: зашифрованные соединения и UDP DHT/uTP могут идти через VPN. В Mihomo, Stash и sing-box правила распознавания BitTorrent нет.

### Выберите режим

| Режим | Маршрутизация на устройстве |
|-------|----------------------------|
| `ru-split` (по умолчанию) | Частные адреса, локальные сети и российские направления, совпавшие с правилами, идут напрямую; остальное — через VPN |
| `full` | Интернет-трафик, включая российские направления, идёт через VPN; частные адреса и локальные сети — напрямую |

```bash
meridian fleet routing
meridian fleet routing full --dry-run
meridian fleet routing full --yes
meridian fleet routing ru-split --yes
```

Команда без аргумента показывает текущий режим и объясняет оба варианта. Изменение правит топологию, показывает проверку и после подтверждения применяет ровно её. Без терминала или с `--json` передайте `--yes`; сочетание `--dry-run --json` возвращает проверку без применения. Приложения получат правила при следующем обновлении подписки (по умолчанию раз в шесть часов, интервал задаёт `delivery.update_interval_hours`) или после обновления вручную. Мастер настройки сохраняет `ru-split` без дополнительного вопроса.

`fleet export` и `fleet import` сохраняют `delivery.client_routing: full`. Значение по умолчанию `ru-split` в файл не записывается; удаление поля из экспортированного файла возвращает этот режим. В настройках веб-консоли режим показан только для чтения, вместе с командой CLI для его изменения.

Приложения, импортирующие простой список ссылок Base64, не получают правил маршрутизации. Настройте раздельную или полную маршрутизацию в таком приложении либо используйте подписку с конфигурацией. Hiddify получает конфигурацию sing-box и следует её встроенным правилам.

### Откуда берутся правила

Сервис управления собирает все подписки с конфигурацией из одного списка клиентских правил и выбранного в топологии режима. Маршрутизацию на устройствах меняет [`meridian fleet routing`](/ru/cli-reference/#meridian-fleet). [`meridian route`](/ru/cli-reference/#meridian-route) управляет исходящим трафиком на выходных серверах, а у [шлюза маршрутизации](#через-шлюз-маршрутизации) свои серверные правила.

## Как эти два уровня работают вместе

| Уровень | Что делает | От чего защищает |
|-------|-------------|-----------------|
| **Геоблокировка на сервере** | Отбрасывает российский трафик на выходе | Попадание IP вашего VPS в логи российских сервисов |
| **Раздельная маршрутизация на устройстве** | Пускает российский трафик напрямую | Неработающие российские сайты и лишняя нагрузка на сервер |

В режиме `ru-split` российские направления, совпавшие с прямыми правилами на устройстве, не доходят до выходного сервера. Если правил нет (импорт по Base64 или старое приложение), включённая геоблокировка на выходе продолжает блокировать российские направления.

`full` меняет только маршрутизацию на устройствах. Для доступа к российским сайтам через выходной сервер он тоже должен разрешать эти направления: разверните его с `--no-geo-block`. Выбор клиентского режима не меняет геоблокировку на сервере.

## Через шлюз маршрутизации

Шлюз маршрутизации (настраивается в `meridian setup`) — это Xray на сервере перед вашими выходами, который по правилам выбирает, откуда выйдет трафик. Правило отправляет подходящий трафик на выход, в пул выходов, **напрямую со шлюза** или никуда. Если шлюз стоит в России, правило «напрямую» открывает российские сайты с его собственного российского адреса — даже в приложениях, которые не получают правил маршрутизации:

Выберите `full`, если этот трафик должен попасть под правила шлюза. В режиме `ru-split` совпавшие с правилами российские направления уже идут напрямую с устройства.

```
Российские сайты → Устройство → Шлюз (в России) → Интернет
Всё остальное    → Устройство → Шлюз → Выход (за рубежом) → Интернет
```

На шаге маршрутизации в мастере добавьте правила по зонам `ru, su, рф` (все сайты в них), по списку сайтов `category-ru` (российские сервисы в других зонах) и по стране `RU` (российские диапазоны IP — для приложений, которые подключаются по адресу) и каждый раз на вопрос, куда отправлять трафик, выбирайте **напрямую со шлюза**. Правила по зонам и спискам сверяют имя сайта как есть, а для правила по стране шлюз сначала узнаёт адрес по имени. В файле топологии прямое правило — это `"action": "direct"` без `target_ref`; зоны задаются правилом `"match": "domain"`, списки — правилом `"match": "geosite"`. Правила проверяются по порядку, срабатывает первое подходящее; в сводке перед применением каждое правило показано вместе с направлением.

Такой трафик не доходит до выхода, поэтому геоблокировка на выходе остаётся как есть. В отличие от промежуточного сервера, шлюз сам выпускает этот трафик в интернет: российские сервисы видят его адрес, и жалобы на этот трафик приходят его хостеру (см. [Выбор хостинга](/ru/hosting/)).

## Особенности DNS

В подписках Xray JSON домены, не попавшие под прямые правила, разрешаются через прокси, поэтому DNS-запросы к зарубежным сайтам не утекают местному провайдеру. В режиме `ru-split` подписки Mihomo проверяют российские IP-диапазоны только для подключений по IP и не вызывают локального DNS-разрешения остальных доменов. Если в вашем приложении есть отдельная настройка защиты от утечек DNS, включите её для проксируемого трафика.
