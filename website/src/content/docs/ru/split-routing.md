## Проблема

Meridian включает **блокировку по географическому принципу на стороне сервера** по умолчанию: выход отбрасывает трафик к российским доменам (`geosite:category-ru`) и российские диапазоны IP (`geoip:ru`). Это держит ваш IP VPS вне логов российских сервисов, где его можно обнаружить и заблокировать.

Проблема: российские веб-сайты не открываются, пока VPN включен. Пользователи должны отключиться для достижения Yandex, VK, Gosuslugi и других отечественных сервисов.

## Решение: раздельная маршрутизация на устройстве

Раздельная маршрутизация отправляет российский трафик **прямо** с устройства и всё остальное через VPN:

```
Российские сайты → Устройство → Прямой → Internet (местный ISP)
Всё остальное  → Устройство → Прокси → VPS → Internet
```

Вы получаете оба:
- **Защита VPS** — блок на стороне сервера остаётся как подстраховка
- **Работающие российские сайты** — устройство отправляет их прямо, никогда через прокси

## Как установить

Раздельная маршрутизация конфигурируется в приложении клиента. Meridian ещё не поставляет раздельную маршрутизацию в своих подписках.

- **Hiddify** — в параметрах установите регион на **Russia**. Hiddify затем отправляет российские сайты прямо.
- **v2rayNG, v2RayTun, v2rayN и другие приложения Xray** — откройте параметры маршрутизации приложения и добавьте **direct** правила для `geosite:category-ru` и `geoip:ru`.
- **Mihomo / Clash Meta приложения** — обновления подписки заменяют конфигурацию, поэтому добавьте эти правила через переопределение приложения или функцию слияния, выше финального правила `MATCH`:
  ```yaml
  - GEOSITE,category-ru,DIRECT
  - GEOIP,RU,DIRECT
  ```

Названия меню отличаются между приложениями и версиями; ищите "Routing", "Region" или "Bypass".

### Почему не редактировать шаблон в панели?

Meridian управляет своим собственным JSON Xray и Mihomo шаблонами подписки в Remnawave — они несут автоматический возврат между вашими выходами и ретрансляторами. Meridian восстанавливает их при каждом применении (включая переразворачивания и `client add`, `node add`, `relay deploy`), поэтому правила добавленные там в панели не продержатся. Замена их разделов маршрутизации может также сломать автоматический возврат.

## Как слои работают вместе

| Слой | Что он делает | Защищает от |
|-------|-------------|-----------------|
| **Блокировка по географическому принципу на стороне сервера** | Отбрасывает трафик, направленный в Россию, на выходе | IP VPS, показывающийся в логах российских сервисов |
| **Раздельная маршрутизация на устройстве** | Отправляет российский трафик прямо | Сломанные российские сайты, ненужная нагрузка на прокси |

С включённой раздельной маршрутизацией, российский трафик никогда не достигает сервер. Если устройство не имеет правил (старое приложение, новый телефон), сервер всё ещё блокирует российские направления, поэтому IP VPS остаётся защищённым.

Если ваши пользователи нуждаются в российских сайтах через VPN вместо этого, разверните с `--no-geo-block`.

## Соображения DNS

С раздельной маршрутизацией, российские домены должны разрешаться через локальный DNS и всё остальное через прокси, для избежания утечек. Приложения с предустановкой региона или обхода обычно это обрабатывают. Если ваше приложение имеет отдельный параметр DNS, включите защиту от утечек DNS для трафика через прокси.
