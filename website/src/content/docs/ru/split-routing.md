## Проблема

Meridian по умолчанию включает **серверную геоблокировку**: сервер Xray отбрасывает трафик, направленный к российским доменам и IP-адресам (с помощью правил маршрутизации `geosite:category-ru` и `geoip:ru`). Благодаря этому IP-адрес вашего VPS не попадает в журналы российских сервисов.

Но из-за этого российские сайты не работают через VPN. Для доступа к Яндексу, VK, Госуслугам и другим российским сервисам пользователям приходится отключаться от VPN.

## Решение: раздельная маршрутизация на стороне клиента

При раздельной маршрутизации российский трафик отправляется **напрямую** с клиента (минуя прокси), а весь остальной трафик проходит через VPN:

```
Russian sites  → Client → Direct → Internet (via local ISP)
Everything else → Client → Proxy → VPS → Internet
```

Это даёт сразу два преимущества:
- **Защита VPS** — серверная геоблокировка остаётся дополнительным уровнем защиты
- **Доступ к российским сайтам** — клиент направляет трафик к ним напрямую, не затрагивая прокси

## Настройка

Meridian использует систему шаблонов подписок Remnawave. Шаблон подписки определяет, какие правила маршрутизации получают клиенты при импорте подключения.

### Шаг 1. Откройте панель Remnawave

Перейдите по URL-адресу панели (он отображается после выполнения `meridian deploy`) и войдите в систему.

### Шаг 2. Измените шаблон подписки

1. Перейдите в **Subscription Settings** → **Templates**
2. Найдите шаблон **Xray JSON** (или создайте новый)
3. Замените разделы маршрутизации и DNS приведённой ниже конфигурацией раздельной маршрутизации

### Шаблон Xray JSON

Добавьте следующие разделы в шаблон подписки Xray JSON. Блок `dns` обеспечивает разрешение российских доменов через локальный DNS-сервер, а блок `routing` направляет российский трафик напрямую:

```json
{
    "log": {
        "loglevel": "warning"
    },
    "dns": {
        "servers": [
            {
                "address": "https://dns.google/dns-query",
                "domains": ["geosite:geolocation-!cn"]
            },
            "8.8.8.8",
            {
                "address": "localhost",
                "domains": [
                    "geosite:category-ru",
                    "domain:.ru",
                    "domain:.su",
                    "domain:.рф"
                ],
                "expectIPs": ["geoip:ru"]
            }
        ]
    },
    "routing": {
        "domainStrategy": "IPIfNonMatch",
        "rules": [
            {
                "type": "field",
                "domain": ["geosite:private"],
                "outboundTag": "direct"
            },
            {
                "type": "field",
                "ip": ["geoip:private"],
                "outboundTag": "direct"
            },
            {
                "type": "field",
                "domain": [
                    "geosite:category-ru",
                    "domain:.ru",
                    "domain:.su",
                    "domain:.рф"
                ],
                "outboundTag": "direct"
            },
            {
                "type": "field",
                "ip": ["geoip:ru"],
                "outboundTag": "direct"
            }
        ]
    }
}
```

Эталонная копия этого шаблона включена в исходный код Meridian по пути `src/meridian/data/subscription-templates/xray-split-ru.json`.

### Шаблон Mihomo / Clash

Для клиентов, использующих Mihomo (Clash Meta), добавьте в шаблон подписки следующие правила:

```yaml
rules:
  - DOMAIN-SUFFIX,.ru,DIRECT
  - DOMAIN-SUFFIX,.su,DIRECT
  - DOMAIN-SUFFIX,.рф,DIRECT
  - GEOSITE,category-ru,DIRECT
  - GEOIP,RU,DIRECT
  - MATCH,PROXY
```

Эталонная копия: `src/meridian/data/subscription-templates/mihomo-split-ru.yaml`.

## Как взаимодействуют два уровня

Два уровня дополняют друг друга:

| Уровень | Назначение | От чего защищает |
|---------|------------|------------------|
| **Серверная геоблокировка** (маршрутизация Xray) | Отбрасывает на сервере трафик к российским ресурсам | Раскрытие IP-адреса VPS в журналах российских сервисов |
| **Раздельная маршрутизация на стороне клиента** (шаблон подписки) | Направляет российский трафик напрямую, минуя прокси | Недоступность российских сайтов и лишняя нагрузка на прокси |

Если раздельная маршрутизация настроена, российский трафик не достигает сервера: клиент отправляет его напрямую. Серверная геоблокировка служит дополнительной защитой: если клиент не применяет шаблон (например, из-за устаревшего приложения или ручной конфигурации), сервер по-прежнему блокирует российские адреса назначения.

## Совместимость клиентов

Для раздельной маршрутизации нужны клиенты, поддерживающие правила маршрутизации Xray:

| Клиент | Платформа | Поддержка раздельной маршрутизации |
|--------|-----------|------------------------------------|
| v2rayNG | Android | Да (Xray JSON) |
| Hiddify | Android, iOS | Да (Xray JSON) |
| Streisand | iOS | Да (Xray JSON) |
| V2Box | iOS | Да (Xray JSON) |
| Nekoray / Nekobox | Настольные ОС | Да (Xray JSON) |
| Clash Meta / Mihomo | Все платформы | Да (Mihomo YAML, другой формат) |

Клиенты, которые не обрабатывают правила маршрутизации, будут направлять через прокси весь трафик. Российские сайты через прокси работать не будут (их блокирует серверная геоблокировка), но IP-адрес VPS останется защищённым.

## Особенности утечек DNS

Некоторые клиенты по умолчанию не направляют DNS-запросы через прокси. Для российских доменов при раздельной маршрутизации это желательно: они должны разрешаться через локальный DNS. Однако DNS-запросы для остальных доменов должны проходить через DNS-сервер прокси, чтобы избежать утечек.

Приведённый выше шаблон обеспечивает это с помощью раздела `dns`: российские домены разрешаются локально (`address: "localhost"`), а для остальных используется DNS-over-HTTPS (`dns.google`).

Если клиент игнорирует раздел `dns` (так делают некоторые минималистичные клиенты), включите встроенную защиту клиента от утечек DNS для нероссийского трафика.
