## Проблема

По умолчанию Meridian включает **геоблокировку на стороне сервера**: выходной сервер отбрасывает трафик к российским доменам (`geosite:category-ru`) и российским диапазонам IP (`geoip:ru`). Это не даёт IP-адресу вашего VPS попасть в логи российских сервисов, где его могут заметить и заблокировать.

Обратная сторона: российские сайты не открываются через сам VPN. Без раздельной маршрутизации пользователям приходилось бы выключать VPN, чтобы зайти на Яндекс, ВК, Госуслуги и другие российские сайты.

## Решение: раздельная маршрутизация на устройстве

Раздельная маршрутизация отправляет российский трафик **напрямую** с устройства, а всё остальное — через VPN:

```
Российские сайты → Устройство → Напрямую → Интернет (местный провайдер)
Всё остальное    → Устройство → Прокси → VPS → Интернет
```

Вы получаете сразу оба преимущества:
- **Защита VPS** — блокировка на сервере остаётся включённой как страховка
- **Работающие российские сайты** — устройство открывает их напрямую, мимо VPN

## Как это работает в Meridian

Meridian сразу включает правила раздельной маршрутизации в подписки **Xray JSON** и **Mihomo**, поэтому в большинстве приложений ничего настраивать не нужно. Каждая подписка направляет напрямую:

- адреса локальной сети (`geosite:private`, `geoip:private`)
- домены `.ru`, `.su` и `.рф`, а также `geosite:category-ru`
- российские диапазоны IP (`geoip:ru`)

Для остальных направлений подписка блокирует QUIC (UDP 443), чтобы приложения переходили на TCP, где прокси маршрутизирует соединения по доменному имени.

Приложения, которые импортируют только простой список ссылок (Base64), правил маршрутизации из подписки не получают. В таких приложениях добавьте правила **direct** для `geosite:category-ru` и `geoip:ru` в настройках маршрутизации или используйте приложение с поддержкой Xray JSON либо Mihomo. В Hiddify достаточно выбрать регион **Россия**.

### Почему не стоит править шаблон в панели?

Meridian сам формирует шаблоны подписок Xray JSON и Mihomo в Remnawave: в них прописаны автопереключение между вашими выходами и промежуточными серверами и описанные выше правила маршрутизации. При каждом применении плана (включая повторный `deploy`, `client add`, `node add`, `relay add`) Meridian восстанавливает свои шаблоны, поэтому ручные правки шаблонов в панели перезапишутся.

## Как эти два уровня работают вместе

| Уровень | Что делает | От чего защищает |
|-------|-------------|-----------------|
| **Геоблокировка на сервере** | Отбрасывает российский трафик на выходе | Попадание IP вашего VPS в логи российских сервисов |
| **Раздельная маршрутизация на устройстве** | Пускает российский трафик напрямую | Неработающие российские сайты и лишняя нагрузка на сервер |

В нормальном режиме российский трафик вообще не доходит до сервера. А если на каком-то устройстве правила маршрутизации не применились (импорт по Base64 или старое приложение), сервер всё равно заблокирует обращение к российским ресурсам и защитит свой IP.

Если же вашим пользователям нужно открывать российские сайты через VPN, разверните сервер с флагом `--no-geo-block`.

## Через шлюз маршрутизации

Шлюз маршрутизации (настраивается в `meridian setup`) — это Xray на сервере перед вашими выходами, который по правилам выбирает, откуда выйдет трафик. Правило отправляет подходящий трафик на выход, в пул выходов, **напрямую со шлюза** или никуда. Если шлюз стоит в России, правило «напрямую» открывает российские сайты с его собственного российского адреса — даже в приложениях, которые не получают правил маршрутизации:

```
Российские сайты → Устройство → Шлюз (в России) → Интернет
Всё остальное    → Устройство → Шлюз → Выход (за рубежом) → Интернет
```

На шаге маршрутизации в мастере добавьте правила по зонам `ru, su, рф` (все сайты в них), по списку сайтов `category-ru` (российские сервисы в других зонах) и по стране `RU` (российские диапазоны IP — для приложений, которые подключаются по адресу) и каждый раз на вопрос, куда отправлять трафик, выбирайте **напрямую со шлюза**. Правила по зонам и спискам сверяют имя сайта как есть, а для правила по стране шлюз сначала узнаёт адрес по имени. В файле топологии прямое правило — это `"action": "direct"` без `target_ref`; зоны задаются правилом `"match": "domain"`, списки — правилом `"match": "geosite"`. Правила проверяются по порядку, срабатывает первое подходящее; в сводке перед применением каждое правило показано вместе с направлением.

Такой трафик не доходит до выхода, поэтому геоблокировка на выходе остаётся как есть. В отличие от промежуточного сервера, шлюз сам выпускает этот трафик в интернет: российские сервисы видят его адрес, и жалобы на этот трафик приходят его хостеру (см. [Выбор хостинга](/ru/hosting/)).

## Особенности DNS

В подписках Xray JSON домены, не попавшие под прямые правила, разрешаются через прокси, поэтому DNS-запросы к зарубежным сайтам не утекают местному провайдеру. В подписках Mihomo проверка российских IP-диапазонов применяется только к подключениям по IP и не вызывает локального DNS-разрешения остальных доменов. Если в вашем приложении есть отдельная настройка защиты от утечек DNS, включите её для проксируемого трафика.
