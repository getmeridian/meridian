---
title: Настройка в Windows (WSL)
description: Как установить и запускать Meridian в Windows с помощью подсистемы Windows для Linux (WSL).
---

Meridian рассчитан на работу в Unix-подобном терминале. На компьютерах с Windows используйте подсистему Windows для Linux (WSL) и выполняйте все команды Meridian внутри окружения Linux.

Запуск напрямую из PowerShell, стандартной командной строки (`cmd.exe`), Git Bash или Cygwin не рекомендуется: в WSL вы получаете полноценную оболочку Linux, стандартный клиент OpenSSH и корректные права доступа к файлам ключей.

## 1. Установите WSL

Откройте PowerShell от имени администратора и выполните команду:

```powershell
wsl --install
```

Если система попросит перезагрузить компьютер, перезагрузите его, а затем откройте установленный дистрибутив Linux (по умолчанию — Ubuntu) из меню «Пуск».

Рекомендуем использовать именно Ubuntu или Debian: все примеры команд и названия пакетов `apt` в документации приведены для них.

Убедитесь, что ваш дистрибутив работает на базе WSL 2:

```powershell
wsl --list --verbose
```

Если в столбце `VERSION` указана `1`, переведите дистрибутив на вторую версию:

```powershell
wsl --set-version Ubuntu 2
```

## 2. Подготовьте окружение в WSL

Внутри терминала WSL обновите списки пакетов и установите базовые утилиты:

```bash
sudo apt update
sudo apt install -y curl openssh-client ca-certificates
```

Установите Meridian:

```bash
curl -sSf https://getmeridian.org/install.sh | bash
```

Если команда `meridian` не распознаётся сразу после установки, перезапустите оболочку:

```bash
exec "$SHELL" -l
```

Проверьте, что CLI установлен:

```bash
meridian --version
```

## 3. Настройте SSH-ключ

Meridian подключается к вашему VPS по SSH изнутри WSL. Сгенерируйте SSH-ключ в терминале WSL:

```bash
ssh-keygen -t ed25519 -C "meridian-wsl"
```

Выведите открытую часть ключа и скопируйте её:

```bash
cat ~/.ssh/id_ed25519.pub
```

Добавьте этот открытый ключ в панели управления вашего VPS-провайдера или в файл `~/.ssh/authorized_keys` пользователя на сервере.

Проверьте вход по SSH перед запуском развёртывания:

```bash
ssh root@198.51.100.10
```

Если на сервере используется обычный пользователь с беспарольным `sudo`, проверьте вход под ним и укажите его во флаге `--user`:

```bash
meridian deploy 198.51.100.10 --user ubuntu
```

## 4. Использование `ssh-agent` (если ключ защищён парольной фразой)

Если при создании SSH-ключа вы задали парольную фразу (passphrase), запустите `ssh-agent` в терминале WSL:

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

Добавляйте эти команды в `~/.profile` или `~/.bashrc`, только если понимаете связанные с этим компромиссы безопасности. Для большинства первых развёртываний достаточно запустить агент вручную.

Не смешивайте SSH-агенты самой Windows и WSL: пока вы осваиваетесь и настраиваете сервер, храните ключ и запускайте агент непосредственно внутри окружения WSL.

## 5. Развёртывание и управление сервером

Запустите пошаговое или быстрое развёртывание из терминала WSL:

```bash
meridian deploy
```

Или сразу укажите IP-адрес сервера:

```bash
meridian deploy 198.51.100.10
```

Конфигурация серверов, токены и резервные снимки сохраняются в каталоге `~/.config/meridian/` внутри файловой системы WSL. Все последующие команды выполняйте из того же дистрибутива WSL:

```bash
meridian client add alice
meridian client list
meridian test 198.51.100.10
```

## Работа через VS Code (Remote — WSL)

Если вы пользуетесь редактором VS Code, установите расширение **WSL** и открывайте рабочую папку из терминала Linux:

```bash
code .
```

Храните рабочие файлы внутри домашнего каталога Linux (например, в `~/projects`), а не на дисках Windows, примонтированных через `/mnt/c/`.

## Частые вопросы и проблемы в WSL

### Интерактивный запрос в терминале пропускается или некорректно реагирует на клавиши

В некоторых терминалах под WSL интерактивные списки могут работать нестандартно. Если мастер развёртывания не принимает ввод должным образом, передайте параметры явно через флаги:

```bash
meridian deploy 198.51.100.10 --sni www.cloudflare.com
```

Также можно предварительно проверить сервер:

```bash
meridian check 198.51.100.10
```

### Ошибка `Permission denied` при подключении по SSH

Убедитесь, что SSH-ключ находится именно внутри WSL, а не только в Windows:

```bash
ls -la ~/.ssh
ssh -v root@198.51.100.10
```

Закрытый ключ должен быть доступен для чтения только вашему пользователю в WSL:

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
```

### Команда `meridian` не найдена после установки

Перезапустите оболочку:

```bash
exec "$SHELL" -l
```

Если команда по-прежнему не находится, проверьте наличие исполняемого файла в `~/.local/bin`:

```bash
ls ~/.local/bin
```

И при необходимости добавьте этот каталог в `~/.bashrc`:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
exec "$SHELL" -l
```

### Ошибки прав доступа при хранении файлов на диске `C:` (`/mnt/c/`)

Храните SSH-ключи, учётные данные Meridian и файлы проектов внутри файловой системы WSL:

```bash
cd ~
mkdir -p projects
```

Не размещайте каталоги `~/.ssh` или `~/.config/meridian` внутри `/mnt/c/`: у путей, примонтированных из Windows, права доступа отличаются от стандартных прав Linux, из-за чего SSH отказывается использовать ключи.
