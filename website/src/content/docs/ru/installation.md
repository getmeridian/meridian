## Быстрая установка

```
curl -sSf https://getmeridian.org/install.sh | bash
```

Этот скрипт:
1. Устанавливает [uv](https://docs.astral.sh/uv/), если его ещё нет, либо использует pipx или pip как запасной вариант. Установщик uv закреплён по версии и проверяется по SHA-256 перед запуском.
2. Устанавливает `meridian-vpn` из PyPI (задайте `MERIDIAN_VERSION=4.0.0`, чтобы установить конкретный выпуск)
3. При необходимости добавляет каталог с инструментом в ваш `PATH`
4. Создаёт `/usr/local/bin/meridian`, только если доступен `sudo` без пароля

## Проверенная установка

К каждому [выпуску на GitHub](https://github.com/getmeridian/meridian/releases) приложены `install.sh` и его `SHA256SUMS`. Чтобы проверить скрипт перед запуском, скачайте оба файла из выпуска и сверьте их:

```
VERSION=4.0.0
curl -fLO https://github.com/getmeridian/meridian/releases/download/v$VERSION/install.sh
curl -fLO https://github.com/getmeridian/meridian/releases/download/v$VERSION/SHA256SUMS
sha256sum -c SHA256SUMS          # macOS: shasum -a 256 -c SHA256SUMS
less install.sh                  # optional: read it
MERIDIAN_VERSION=$VERSION bash install.sh
```

Чтобы проверить копию с getmeridian.org, сравните `curl -sSf https://getmeridian.org/install.sh | sha256sum` с `SHA256SUMS` выпуска; они совпадают, если скрипт не менялся после этого выпуска. Если новейший выпуск является бета-версией, копия на сайте по умолчанию устанавливает именно её, и из-за этой одной строки её контрольная сумма отличается от суммы файла из выпуска.

## Ручная установка

С uv (рекомендуется):
```
uv tool install meridian-vpn
```

С pipx:
```
pipx install meridian-vpn
```

## Обновление

```
meridian update
```

Meridian время от времени проверяет PyPI перед интерактивными командами и выводит уведомление, когда выходит новая версия. Он никогда не устанавливает обновления сам. `meridian update` обновляет пакет через тот менеджер пакетов, которым он был установлен, и проверяет, что команда `meridian` сообщает новую версию. Чтобы отключить фоновую проверку в скриптах и CI, задайте `MERIDIAN_DISABLE_UPDATE_CHECK=1`.

Обновление CLI ничего не меняет на ваших серверах. Если сервер работает, спешить не нужно: прочитайте [список изменений](https://github.com/getmeridian/meridian/releases), а затем запустите ту же команду `meridian deploy` (или `meridian apply`), когда будете готовы применить новую версию.

## Обновление с 3.x

Meridian 4 **не обновляет серверы 3.x на месте**. Он заменяет панель 3x-ui собственным сервисом управления, а ссылки с сервера 3.x перенести нельзя: каждому пользователю понадобится новая ссылка.

Ваши серверы 3.x продолжают работать. У вас есть два варианта:

- **Продолжать управлять ими через 3.x.** Установите CLI версии 3.x:
  ```
  uv tool install 'meridian-vpn<4'
  ```
  (или `pipx install 'meridian-vpn<4'`). Начиная с версии 3.17.3, `meridian update` остаётся на ветке 3.x, пока вы явно не укажете `--major`.
- **Перейти на Meridian 4.**
  1. Разверните новый сервер с Meridian 4: `meridian deploy NEW_IP`
  2. Отправьте пользователям новые страницы подключения (`meridian client add NAME` для каждого человека)
  3. Когда все перейдут, удалите старый сервер командой `meridian teardown OLD_IP` — `teardown` в Meridian 4 удаляет и 3x-ui

Meridian 4 хранит своё состояние в `~/.config/meridian/` и никогда не читает и не меняет состояние 3.x в `~/.meridian/`, поэтому обе версии могут сосуществовать на одном компьютере; команды управления серверами, обнаружившие только состояние 3.x, подскажут эти варианты.

Серверы, развёрнутые более ранним выпуском Meridian 4, работают на панели Remnawave. Их можно перевести на месте, сохранив все ссылки: см. [Переход с Remnawave](/ru/deploy/#переход-с-remnawave).

Эта документация описывает Meridian 4. [Документация Meridian 3.17.3](https://github.com/getmeridian/meridian/tree/v3.17.3/website/src/content/docs/ru) остаётся на GitHub для серверов, которые вы оставляете на 3.x.

## Требования

- **Python 3.11+** (uv устанавливает его и управляет им сам)
- **Доступ по SSH** к вашему серверу от имени `root` или пользователя с `sudo` без пароля. Лучше всего вход по ключу; если сервер принимает только пароль, `meridian deploy` и `meridian setup` предложат создать ключ для Meridian и один раз установить его с помощью этого пароля (см. [Серверы только с паролем](/ru/deploy/#серверы-только-с-паролем))

QR-коды в терминале отрисовываются встроенным пакетом `segno`; дополнительные системные зависимости не нужны.
