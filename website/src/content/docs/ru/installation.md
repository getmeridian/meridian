## Быстрая установка

```
curl -sSf https://getmeridian.org/install.sh | bash
```

Что делает установочный скрипт:
1. Устанавливает менеджер пакетов [uv](https://docs.astral.sh/uv/), если он ещё не установлен (либо использует `pipx` или `pip` как запасной вариант). Установщик `uv` привязан к конкретной версии и перед запуском проверяется по контрольной сумме SHA-256.
2. Устанавливает пакет `meridian-vpn` из PyPI (чтобы поставить конкретную версию, задайте переменную `MERIDIAN_VERSION=4.0.0`).
3. При необходимости добавляет каталог с исполняемыми файлами в переменную `PATH` вашей оболочки.
4. Создаёт симлинк `/usr/local/bin/meridian`, если в системе настроен беспарольный `sudo`.

## Установка с проверкой контрольной суммы

К каждому [релизу на GitHub](https://github.com/getmeridian/meridian/releases) приложены скрипт `install.sh` и файл контрольных сумм `SHA256SUMS`. Чтобы проверить скрипт перед запуском, скачайте оба файла и сверьте хеш:

```
VERSION=4.0.0
curl -fLO https://github.com/getmeridian/meridian/releases/download/v$VERSION/install.sh
curl -fLO https://github.com/getmeridian/meridian/releases/download/v$VERSION/SHA256SUMS
sha256sum -c SHA256SUMS          # на macOS: shasum -a 256 -c SHA256SUMS
less install.sh                  # при желании просмотрите код скрипта
MERIDIAN_VERSION=$VERSION bash install.sh
```

Чтобы проверить копию скрипта на сайте `getmeridian.org`, сравните вывод `curl -sSf https://getmeridian.org/install.sh | sha256sum` с файлом `SHA256SUMS` из релиза — суммы совпадут, если скрипт не обновлялся после выхода релиза (когда последним вышедшим релизом является бета-версия, скрипт на сайте по умолчанию ставит её, и из-за этой строки его хеш отличается от файла в релизе).

## Ручная установка

Через `uv` (рекомендуется):
```
uv tool install meridian-vpn
```

Через `pipx`:
```
pipx install meridian-vpn
```

## Обновление CLI

```
meridian update
```

Перед запуском интерактивных команд Meridian периодически проверяет наличие новых версий на PyPI и выводит подсказку, если вышло обновление. Сам по себе он ничего не обновляет автоматически. Команда `meridian update` обновляет пакет через тот менеджер (`uv`, `pipx` или `pip`), которым он был установлен, и проверяет, что активная команда `meridian` действительно переключилась на новую версию. Чтобы отключить фоновую проверку обновлений в скриптах и CI, задайте переменную окружения `MERIDIAN_DISABLE_UPDATE_CHECK=1`.

Обновление CLI на вашем компьютере никак не затрагивает работающие серверы. Если сервер работает стабильно, спешить с обновлением серверной части не обязательно: ознакомьтесь со [списком изменений](https://github.com/getmeridian/meridian/releases) и запустите ту же команду `meridian deploy` (или `meridian apply`), когда будете готовы обновить серверы.

## Обновление с 3.x

Meridian 4 **не обновляет серверы версии 3.x поверх старой установки**. В четвёртой версии сторонняя панель 3x-ui заменена собственным сервисом управления Meridian, поэтому старые ссылки с серверов 3.x перенести нельзя — каждому пользователю потребуется новая ссылка.

Ваши существующие серверы 3.x продолжат работать как прежде. Вы можете выбрать один из двух вариантов:

- **Продолжать управлять старыми серверами через ветку 3.x.** Установите CLI версии 3.x:
  ```
  uv tool install 'meridian-vpn<4'
  ```
  (или `pipx install 'meridian-vpn<4'`). Начиная с версии 3.17.3 команда `meridian update` остаётся в пределах ветки 3.x, пока вы явно не укажете флаг `--major`.
- **Перейти на Meridian 4.**
  1. Разверните чистый сервер с помощью Meridian 4: `meridian deploy NEW_IP`
  2. Создайте доступы и отправьте пользователям новые страницы подключения (`meridian client add NAME`)
  3. Когда все перейдут на новый сервер, очистите старый сервер командой `meridian teardown OLD_IP` — в Meridian 4 она корректно удаляет в том числе панель 3x-ui

Meridian 4 хранит свои файлы в `~/.config/meridian/` и никогда не изменяет файлы версии 3.x в `~/.meridian/`, поэтому обе версии не мешают друг другу. Если запустить команду Meridian 4 на компьютере, где есть только конфигурация 3.x, CLI подскажет описанные выше варианты.

Если ваши серверы были развёрнуты ранними выпусками Meridian 4 на базе панели Remnawave, их можно перевести на встроенный сервис управления без переустановки и с сохранением всех пользовательских ссылок — см. раздел [Переход с Remnawave](/ru/deploy/#переход-с-remnawave).

Настоящая документация относится к Meridian 4. Документация для серверов на базе [Meridian 3.17.3](https://github.com/getmeridian/meridian/tree/v3.17.3/website/src/content/docs/ru) сохранена в репозитории на GitHub.

## Системные требования

- **Python 3.11+** (`uv` скачивает и настраивает нужную версию Python автоматически)
- **Доступ к серверу по SSH** от имени `root` или пользователя с беспарольным `sudo`. Рекомендуется вход по SSH-ключу; если новый сервер принимает только пароль, интерактивные команды `meridian deploy` и `meridian setup` сами предложат сгенерировать ключ и один раз установят его на сервер по паролю (см. [Серверы только с паролем](/ru/deploy/#серверы-только-с-паролем))

QR-коды в терминале формируются встроенной библиотекой `segno` и не требуют установки системных утилит.

## Проверка установки

```
meridian --version
```
