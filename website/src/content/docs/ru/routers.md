VPN-клиент, запущенный прямо на домашнем роутере, защищает сразу все устройства в доме — включая Smart TV, игровые приставки и гостевые телефоны, на которые неудобно или невозможно поставить приложение. В этом руководстве разобраны два самых популярных в России решения: **podkop** для роутеров с OpenWrt и **XKeen** для роутеров Keenetic. Оба проекта активно развиваются сообществом, поэтому перед установкой рекомендуем свериться с их актуальной документацией.

## Шаг 1. Создайте отдельный доступ для роутера

Выделите роутеру отдельную учётную запись, чтобы при необходимости его можно было перезапустить или отключить, не затрагивая телефоны и ноутбуки:

```
meridian client add home-router
meridian client show home-router
```

Команда `client show` выведет адрес страницы подключения и ссылку на подписку. Откройте страницу подключения в браузере и разверните блок **Отдельные подключения**: у каждого маршрута (Reality, XHTTP, WSS и маршрутов через промежуточные серверы) есть кнопка копирования отдельной ссылки вида `vless://…`.

Какую именно ссылку выбрать для роутера:

- **Начните с Reality.** Это основной и самый быстрый протокол, который поддерживают все описанные ниже роутерные клиенты.
- **XHTTP** требует свежего ядра Xray на роутере (совместимого с версией Xray на сервере). Стандартная сборка sing-box, которую использует podkop, не поддерживает транспорт XHTTP; в XKeen используется Xray, поэтому там XHTTP работает.
- **Маршруты через промежуточный сервер (`via relay`)** — это такие же ссылки `vless://` с протоколом Reality. Если роутер находится в России, а прямой IP зарубежного выходного сервера заблокирован вашим домашним провайдером, скопируйте ссылку промежуточного сервера.
- **Hysteria2** работает поверх UDP и не проходит через промежуточные серверы — используйте его, только если клиент на роутере поддерживает Hysteria2, а все TCP-маршруты недоступны.

Учитывайте, что одиночная ссылка `vless://` не обновляется сама: в отличие от ссылки на подписку, в podkop нет автообновления подписок по расписанию, поэтому при смене IP-адреса сервера или добавлении нового промежуточного сервера новую ссылку `vless://` нужно будет вставить в настройки роутера вручную.

### Совместимость версий клиентов

Новые версии Xray по умолчанию отвергают подключения от некоторых сборок sing-box (podkop) и Mihomo из-за устаревшего номера версии протокола, который передают эти клиенты. В Meridian эта проверка специально ослаблена на всех выходных серверах, поэтому такие роутеры подключаются без проблем. Если же `meridian test` на компьютере проходит успешно, а роутер всё равно не соединяется, обновите прокси-ядро на самом роутере (на Keenetic ядро Xray обновляется командой `xkeen -ux`).

## Роутеры с OpenWrt и пакетом podkop

Пакет [podkop](https://podkop.net/) направляет через VPN только выбранные списки доменов и сервисов, а весь остальной трафик пускает напрямую через провайдера. Для домашнего роутера в России это оптимальный режим: российские сайты и онлайн-банки открываются напрямую без лишних задержек.

**Требования** (согласно [документации podkop](https://podkop.net/docs/install)): прошивка OpenWrt 24.10 (или 25.12 с пакетным менеджером `apk`) и около 20 МБ свободного места во flash-памяти (если пакет `sing-box` ещё не установлен, потребуется около 40 МБ свободного места в разделе `/overlay`; при нехватке памяти авторы podkop рекомендуют облегчённую сборку `sing-box-tiny`).

**Установка** по SSH на роутере:

```
sh <(wget -O - https://raw.githubusercontent.com/itdoginfo/podkop/refs/heads/main/install.sh)
```

Если GitHub с роутера не открывается, на странице установки podkop приведена команда для загрузки через зеркало.

**Настройка** в веб-интерфейсе LuCI (раздел Services → Podkop):

1. На вкладке `Main` выберите **Connection Type**: `Proxy`.
2. В поле **Configuration Type** выберите `Connection URL` и вставьте скопированную ссылку Reality (`vless://…`).
3. Отметьте нужные списки доменов сообщества или добавьте собственные домены для маршрутизации через VPN.
4. Нажмите **Save & Apply**, затем перейдите на вкладку **Diagnostics** и проверьте статус (открывайте интерфейс роутера из локальной сети, а не через проброс портов извне).

Если вы хотите настроить автоматическое переключение между прямым зарубежным сервером и промежуточным сервером внутри страны, выберите тип конфигурации **URLTest** и добавьте обе ссылки `vless://` — sing-box будет сам проверять оба маршрута и направлять трафик через рабочий.

## Роутеры Keenetic со связкой Entware и XKeen

Проект [XKeen](https://github.com/jameszeroX/XKeen) устанавливает и настраивает ядро Xray (а в актуальном форке — также Mihomo) на роутерах Keenetic поверх среды Entware.

**Требования:** подключённый к роутеру USB-накопитель с разделом EXT4 и установленной средой Entware, а также установленные в настройках KeeneticOS компоненты ядра Netfilter. В документации XKeen также рекомендуется создать на накопителе раздел подкачки (swap) и отключить сжатие оперативной памяти (zram) в настройках роутера.

**Установка** в SSH-терминале Entware от имени `root`:

```
opkg update && opkg upgrade && opkg install curl tar && cd /tmp
sh -c "$(curl -sSL https://raw.githubusercontent.com/jameszeroX/XKeen/main/install.sh)"
```

**Настройка** конфигурационных файлов Xray в каталоге `/opt/etc/xray/configs/`. Перенесите параметры из вашей ссылки Reality `vless://` в файл `04_outbounds.json`:

```json
{
  "outbounds": [
    {
      "tag": "vless-reality",
      "protocol": "vless",
      "settings": {
        "vnext": [{
          "address": "198.51.100.10",
          "port": 443,
          "users": [{ "id": "UUID", "flow": "xtls-rprx-vision", "encryption": "none" }]
        }]
      },
      "streamSettings": {
        "network": "tcp",
        "security": "reality",
        "realitySettings": {
          "fingerprint": "chrome",
          "serverName": "www.google.com",
          "publicKey": "PBK",
          "shortId": "SID"
        }
      }
    }
  ]
}
```

Все нужные значения находятся прямо в тексте ссылки `vless://`: перед символом `@` указан `UUID`, сразу после него — адрес сервера (`address`) и порт (`port`). В параметрах после знака `?` значение `pbk` подставляется в `publicKey`, `sid` — в `shortId`, `sni` — в `serverName`, а `fp` — в `fingerprint`. Поле `flow` оставьте равным `"xtls-rprx-vision"`, если оно присутствует в ссылке.

Затем настройте правила маршрутизации в файле `05_routing.json`. В руководстве XKeen описаны два подхода: направлять в туннель только выбранные списки доменов/IP либо отправлять домены `.ru`, `.su` и `.рф` напрямую, а весь остальной трафик — через туннель. После сохранения проверьте конфигурацию и запустите службу:

```
xkeen -xtest
xkeen -start
```

## Почему российские сайты должны идти напрямую

По умолчанию на выходных серверах Meridian включена геоблокировка российских доменов и IP-адресов (`--geo-block`). Если роутер попытается отправить вообще весь трафик домашней сети в VPN-туннель, российские сайты открываться не будут. Настраивайте на роутере раздельную маршрутизацию: в podkop она включена по умолчанию, а в XKeen задаётся правилами в `05_routing.json`. Подробнее об устройстве маршрутизации рассказано в разделе [Маршрутизация на устройствах](/ru/split-routing/).

## Частые подводные камни

- **Нехватка памяти и производительность процессора.** Пакету podkop требуется место во flash-памяти под бинарный файл `sing-box` — если память роутера заполнена, установка оборвётся. Кроме того, шифрование трафика нагружает процессор роутера: на бюджетных моделях скорость через VPN на роутере может быть заметно ниже скорости вашего тарифа.
- **Сбитые часы после перезагрузки роутера.** У многих роутеров нет батарейки часов реального времени, поэтому сразу после включения питания время сбрасывается, пока роутер не свяжется с NTP-сервером. С неверным системным временем проверка сертификатов TLS для XHTTP, WSS и скачивания списков завершится ошибкой — если что-то не запускается, первым делом проверьте дату и время в системном журнале роутера.
- **Обход роутерного DNS на устройствах.** Поскольку podkop направляет трафик в туннель на основе DNS-запросов, все домашние устройства должны использовать в качестве DNS-сервера сам роутер, а в браузерах на компьютерах и телефонах должен быть отключён сторонний «Безопасный DNS» (DoH). Если браузер разрешит домен через сторонний DNS в обход роутера, роутер не узнает о необходимости направить этот IP в туннель — именно поэтому чаще всего возникает ситуация «на одном устройстве сайт открывается, а на другом нет».
- **Включённый VPN на самом телефоне или ноутбуке.** Если на устройстве одновременно запущено собственное VPN-приложение, его трафик пойдёт поверх роутера в обход правил podkop/XKeen.
- **Отключённая учётная запись.** Если вы приостановили доступ командой `meridian client disable home-router`, возобновите его через `meridian client enable home-router`.

## Как проверить работу

Откройте любой сайт проверки IP-адреса с устройства, подключённого к Wi-Fi роутера (при проверке списков в podkop откройте сайт из выбранного списка): должен отображаться IP-адрес вашего выходного сервера. Если сайт не открывается, выполните на компьютере `meridian test` и `meridian check`, чтобы убедиться, что сам сервер исправен, или загляните в раздел [Решение проблем](/ru/troubleshooting/).
