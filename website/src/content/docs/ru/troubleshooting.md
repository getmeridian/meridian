## Какой инструмент использовать

```
ДО УСТАНОВКИ           → meridian check IP
  "Будет ли этот сервер работать с Meridian?"
  Проверяет: SNI доступность, порт 443, DNS, ОС, диск.

ПОСЛЕ УСТАНОВКИ, ЗДОРОВ ЛИ? → meridian check
  "Сервис управления, агенты, промежуточные серверы, порты и сертификаты в порядке?"
  Проверяет каждый сервер по ролям, по SSH.

ПОСЛЕ УСТАНОВКИ, НЕ МОГУ ПОДКЛЮЧИТЬСЯ → meridian test IP
  "Доступен ли VPN отсюда?"
  Проверяет: настроенные слушатели, TLS/SNI, каноническую подписку и VPN-трафик.
  SSH не нужен — запускается с клиентского устройства.

ПОСЛЕ УСТАНОВКИ, ПРОВЕРИТЬ ЭКСПОЗИЦИЮ → meridian test IP --probe
  "Раскрывает ли развёртывание VPN или интерфейс управления?"
  Проверяет: публичные порты, TLS/HTTP, пути, SNI, DNS и политику топологии.
  SSH не нужен — запускается с клиентского устройства.

ПОСЛЕ УСТАНОВКИ, ЧТО-ТО СЛОМАЛОСЬ → meridian doctor IP
  "Собрать всё для отладки."
  Собирает: ОС сервера, сервисы Meridian, логи агента и nginx, порты, файрвол, SNI, DNS.
```

Добавьте `--ai` к check или doctor для готовой к AI диагностической подсказки.

## Не может подключиться вообще

### Порт 443 не доступен

**Причины:**
1. Файрвол облачного провайдера / группа безопасности блокирует входящий порт 443
2. ISP или сетевая блокировка IP-адреса сервера целиком
3. Сервер не работает или VPN не запущен
4. UFW на сервере не разрешает порт 443

**Решения:**
1. Проверьте консоль облачного провайдера — убедитесь, что 443/TCP разрешен входящему трафику
2. Попробуйте с другой сети (мобильные данные, другой Wi-Fi)
3. Подключитесь к серверу по SSH и проверьте: `systemctl status ctld netagent netcore nginx` (все ли активны?), `ss -tlnp sport = :443`
4. Проверьте UFW: `ufw status` — должно показать 443/tcp ALLOW

### TLS handshake не пройден

**Причины:**
1. Xray (`netcore`) не работает
2. Порт 443 занят другим сервисом
3. Целевой SNI Reality недоступен с сервера

**Решения:**
1. Проверьте Xray: `meridian logs IP -c node -n 20`
2. Проверьте порт: `ss -tlnp sport = :443` — должен быть nginx
3. Протестируйте SNI: `meridian check IP --sni HOST`

### Домен не доступен

**Причины:**
1. DNS не указывает на IP сервера
2. nginx не работает или не получил TLS сертификат
3. nginx не маршрутизирует SNI домена правильно

**Решения:**
1. Проверьте DNS: `dig +short yourdomain.com @8.8.8.8`
2. Проверьте nginx: `systemctl status nginx`
3. Проверьте файлы маршрутизации nginx: `ls /etc/nginx/stream.d/ /etc/nginx/sites-enabled/` (файлы Meridian начинаются с `meridian-v4-`) и `nginx -t`

## Соединение прерывается через несколько секунд

**Причины:**
1. Проблемы с MTU на сетевом пути
2. ISP сбрасывает долгоживущие TLS сессии

**Решения:**
1. Попробуйте другую сеть
2. Используйте маршрут XHTTP или WSS (режим домена)

## Установка не удалась

### «No traffic passes through it»

Сервер развернулся, но реальный трафик через выбранный с `--sni` сайт маскировки не прошёл. Выберите другую цель (`meridian scan IP` найдёт подходящие сайты в собственной сети сервера) и запустите команду развёртывания ещё раз с новым `--sni`. Без `--sni` Meridian сам по очереди пробует `www.google.com`, `dl.google.com` и `www.cloudflare.com`.

### «The server cannot reach any Reality camouflage target»

На сервере не работает исходящий HTTPS к стандартным сайтам маскировки. Проверьте исходящий файрвол у хостинг-провайдера или укажите доступный сайт с помощью `--sni`.

### Прерванное или неудавшееся развёртывание

Развёртывание и применение плана сохраняют контрольные точки. Устраните указанную причину и запустите ту же команду снова — завершённые шаги будут пропущены.

### Конфликт порта 443

Другой сервис (Apache, nginx) использует порт 443. Остановите его или используйте чистый сервер. `meridian check IP` подскажет вам, что использует порт.

### Переход с Remnawave останавливается

`meridian migrate` сохраняет ход работы после каждого шага. Устраните названную причину и запустите команду снова: она продолжит с места остановки, а завершённый переход ничего не делает. База панели сохраняется до любых изменений — в `~/.config/meridian/backups/` и в `/var/backups/meridian-migration/` на сервере управления. Если после применения проверка ссылок не проходит, Remnawave остаётся на месте (остановленным), и команда сообщает об этом: это ошибка, поэтому [создайте issue](https://github.com/getmeridian/meridian/issues) с выводом `meridian doctor`.

### Ошибки подключения SSH

Протестируйте SSH вручную: `ssh root@SERVER_IP`. Убедитесь, что у вас есть доступ на основе ключей. Используйте флаг `--user` если не root. Если сервер принимает только пароль, запустите `meridian deploy` в терминале без `--yes` и позвольте ему установить ключ (см. [Серверы только с паролем](/ru/deploy/#серверы-только-с-паролем)) или один раз выполните `ssh-copy-id root@SERVER_IP`.

### Агент узла не в сети или не применяет конфигурацию

Проверьте логи: `meridian logs IP -c node -n 50` показывает агента (`netagent`) и Xray (`netcore`). Частые причины: порт на хосте уже занят (Xray сам открывает порты из вашей топологии, поэтому они должны быть свободны) или выход не может достучаться до сервера управления по TCP 443 (агент сам подключается к нему; проверьте исходящий файрвол провайдера).

**Решение:** запустите `meridian check IP`, выполните предложенные исправления, затем `meridian apply`: он заново зарегистрирует агента, потерявшего идентичность, и обновит агента со старой сборкой. `meridian fleet status` показывает, в сети ли каждый агент и применил ли он текущую конфигурацию; то же видно на экране **Servers** в консоли.

### Недостаточно места на диске

Менее 2ГБ свободного места. Освободите место: `journalctl --vacuum-time=1d`, `apt-get clean`, проверьте `/var/log/`.

### DNS не разрешается (режим домена)

Сертификат для вашего домена может быть выдан только когда A-запись домена указывает на сервер (серое облако во время развёртывания). Обновите запись, дождитесь распространения (обычно 5–15 минут), затем запустите команду развёртывания снова. `meridian check IP --domain DOMAIN` проверяет это перед развёртыванием.

## Было работающим, теперь остановилось

**Самая частая причина:** IP-адрес сервера был заблокирован. Запустите `meridian test IP`: результаты разделяют сетевую доступность, TLS, подписку и работу Xray. Ошибка TCP также может означать облачный файрвол или выключенный сервер.

Подробные инструкции по восстановлению см. в [Руководстве по восстановлению заблокированного IP](/ru/recovery/).

Другие причины:
- Сервер перезагрузился и сервисы не запустились автоматически → `meridian plan` показывает, что выключено, а `meridian apply` это чинит. Вручную: `systemctl restart ctld netagent nginx`
- Диск переполнен → `df -h /`, `journalctl --vacuum-time=1d`
- Сервер управления пропал насовсем → восстановите его из снимка командой `meridian restore` ([Сервер управления потерян](/ru/recovery/#сервер-управления-потерян))
- VPN подключён, но сайты по имени не открываются (по IP-адресу открываются) → выходной сервер не достаёт ни до одного из своих DNS-серверов с шифрованием. `meridian check` перечисляет их в пункте **Encrypted DNS**; разрешите исходящий TCP 443 к этим адресам в файрволе провайдера

## Низкая скорость

1. Выберите сервер географически ближе (Финляндия, Нидерланды, Швеция для Европы/Ближнего Востока)
2. Проверьте нагрузку на сервер: `htop` или `uptime`
3. Попробуйте WSS/CDN ссылку — может иметь лучшую маршрутизацию через Cloudflare
4. Проверьте, включен ли BBR: `sysctl net.ipv4.tcp_congestion_control`

**НЕ** запускайте другие протоколы (OpenVPN, WireGuard) на том же сервере — это помечает IP.

## AI-усиленная помощь

```
meridian doctor --ai
```

Копирует диагностическую подсказку в буфер обмена для использования с любым AI ассистентом.

Или соберите диагностику для [GitHub issue](https://github.com/getmeridian/meridian/issues):

```
meridian doctor
```

## Промежуточный сервер не работает

Проблемы с промежуточными серверами разобраны в разделе [Промежуточные серверы — устранение неполадок](/ru/relay/#устранение-неполадок) (конфликт портов, файрвол, недоступность выхода, не запущенный сервис).

## Интерпретация вывода предварительной проверки

| Проверка | Что проверяет | Если не прошла |
|----------|--------------|----------------|
| Camouflage target | Может ли сервер достучаться до сайта маскировки? | Исходящий трафик сервера ограничен. Попробуйте другой SNI с `--sni` |
| Camouflage target DNS | Разрешается ли сайт маскировки через DNS сервера? | Исправьте DNS-резолвер на сервере или выберите другой сайт маскировки |
| Port 443 | Свободен ли порт 443 или используется Meridian? | Другой сервис занимает порт 443. Остановите его или используйте чистый сервер |
| Port 443 from outside | Доступен ли порт 443 из интернета? | Облачный файрвол блокирует входящие соединения. Откройте входящий порт 443/TCP |
| Domain DNS | Разрешается ли домен в IP сервера? | Обновите A-запись DNS |
| Server OS | Это Ubuntu или Debian? | Без apt (CentOS, Fedora, Alpine) — ошибка; переустановите Ubuntu или Debian |
| Disk space | Минимум 2 ГБ свободно? | Освободите место на диске |
| Clock sync | Расхождение клиента и сервера меньше минуты? | Одна из сторон не синхронизирует время. Включите NTP и автоматическую установку времени на обоих устройствах |

## Интерпретация вывода doctor

| Раздел | На что обратить внимание |
|--------|------------------------|
| Local Machine | Совместимость ОС |
| Server | Версия ОС, uptime (недавняя перезагрузка?), использование диска и памяти |
| Services | Активны ли `ctld` (сервис управления), `netagent` (агент) и `netcore` (Xray)? |
| Exit node Logs | Ошибки запуска агента и Xray, записи "failed to start", проблемы с сертификатами |
| Listening Ports | Порт 443 должен показывать nginx. Если отсутствует, VPN не работает |
| Firewall (UFW) | Порт 443/tcp должен быть ALLOW. Если не указан, он заблокирован |
| Camouflage Target | Должно показывать CONNECTED с цепочкой сертификатов |
| Domain DNS | Должен разрешаться в IP сервера |

## Интерпретация вывода test

| Проверка | Пройдена | Не пройдена |
|----------|----------|-------------|
| Доступность TCP | Каждый настроенный публичный TCP-слушатель доступен | Файрвол, блокировка ISP, выключенный сервер или неверная топология |
| Маскировка TLS/SNI | Цель показывает ожидаемую маскировочную идентичность | Ошибка TLS-маршрутизации, сертификата, DNS или SNI |
| Корень домена | Доступен защищённый ответ `403`/`404` | Ошибка DNS/nginx или непредусмотренный публичный контент |
| Каноническая подписка | Сервис управления выдал корректный Xray JSON активного клиента | Нет активного клиента или сервис управления недоступен |
| Автоматический fallback | Выданная политика провела реальный трафик | Ошибка балансировщика, маршрута, учётных данных или endpoint |
| Проверки протоколов | Каждый outbound цели провёл реальный трафик | Ошибка слушателя, файрвола или выданной конфигурации протокола |

Итоговый код выхода различает результат: `0` — всё прошло, `4` — проверка завершена с отрицательными результатами, `3` — результат неопределён из-за отсутствующих обязательных данных. `--timeout` принимает 1–30 секунд и ограничивает каждую сетевую операцию или запуск протокола, а не длительность всей команды. При первом полном тесте Meridian может до 120 секунд загружать закреплённый Xray и проверять опубликованный checksum с GitHub; затем используется локальный cache.

Проверка реального трафика чередует несколько внешних IP-observer'ов. Если запросы через прокси не проходят, но observer работает напрямую, это отрицательный результат; если observer'ы недоступны и через прокси, и напрямую, Meridian не обвиняет прокси и возвращает неопределённость (`3`). Задавайте `MERIDIAN_CONNECT_TEST_URL`, только если вы сами поддерживаете известный адрес для проверки IP. `--basic` не подтверждает UDP-трафик Hysteria2.

Если все проверки пройдены, но VPN-клиент всё ещё не может подключиться: пересканируйте QR-код, проверьте, что устройство устанавливает дату и время автоматически, или попробуйте другое рекомендуемое приложение (Happ, FlClashX, Clash Mi или Throne на компьютере).
