Meridian начинает с **выключенным ограничением устройств** и **выключенной историей трафика**. Дополнительные записи включаете вы, когда они нужны. Ни один режим не хранит IP-адреса клиентов, журналы подключений или пути запросов.

Сервис управления уже хранит учётные записи людей и их данные подключения, суммарный трафик за всё время и последнюю активность. Захвативший сервер сможет прочитать эти данные. Настройки определяют, какие сведения об устройствах и записи по дням добавятся к ним.

## Ограничение устройств

| Режим | Что хранит Meridian | Что видно вам |
| --- | --- | --- |
| `off` (по умолчанию) | Нет записей об устройствах; они не отслеживаются и не ограничиваются | Нет счётчика устройств |
| `private` | Отпечатки HMAC-SHA256 от идентификаторов устройств с секретом только для ваших серверов; без систем, моделей и приложений | Число устройств и лимит |
| `full` | Идентификатор, платформа, версия ОС, модель, user agent, первый и последний запрос подписки | Список устройств каждого человека |

**Раскрытие данных в private:**

> Устройства каждого человека подсчитываются по нечитаемому отпечатку. Meridian не хранит названия устройств, систем или приложений. Тот, кто захватит управляющий сервер, сможет лишь проверить, использовалось ли устройство, которое у него уже есть.

**Раскрытие данных в full:**

> Meridian хранит идентификатор, систему, модель и приложение каждого устройства, а также время последнего запроса подписки. Тот, кто захватит управляющий сервер, узнает, какими устройствами пользуется каждый человек. Адреса никогда не сохраняются.

Лимит по умолчанию — **3 устройства**, допустимо **от 1 до 100**. Он действует, когда у человека нет собственного лимита. См. [Управление клиентами](/ru/client-management/).

## История трафика

| Режим | Что хранит Meridian |
| --- | --- |
| `off` (по умолчанию) | Суммарный трафик за всё время и последнюю активность, без ежедневной истории |
| `daily` | Отправленные и полученные байты каждого человека и общий трафик каждого сервера по дням UTC |

По умолчанию сохраняются **90 дней**. Можно выбрать **7–730 дней**, включая сегодня. Старые записи удаляются каждые 30 секунд; сокращение срока удаляет их сразу.

> Meridian хранит ежедневный объём трафика каждого человека и каждого сервера за N дней. Тот, кто захватит управляющий сервер, узнает, когда каждый человек был активен.

Трафик относится к дню UTC, когда новый прирост счётчиков дошёл до сервиса. Задержавшийся отчёт относится к дню получения. Повторный отчёт учитывается только один раз. Использование до включения истории не восстанавливается; пустой день означает отсутствие записанного трафика. Сброс лимита трафика человека сохраняет его историю.

В консоли есть график человека и график серверов с выбором сервера. CLI показывает компактные таблицы:

```bash
meridian client usage alice --days 30
meridian client show alice                 # последние 7 дней, если история включена
meridian fleet usage --days 7
```

Запрос ограничен сохранённым сроком хранения. При выключенной истории API трафика отвечает `409 history_off`.

## Изменить настройки

Эти настройки принадлежат сервису управления. Применение файла серверов никогда их не меняет.

```bash
meridian privacy                          # то же, что privacy show
meridian privacy show --json
meridian privacy set --devices private --device-limit 3
meridian privacy set --history daily --history-days 90
meridian privacy set --devices off --history off --yes --json
```

Меняются только переданные параметры. Повышение режима показывает раскрываемые данные перед подтверждением; `--yes` пропускает вопрос. Изменение в JSON требует `--yes`. Повтор тех же настроек ничего не меняет.

В веб-консоли откройте **Настройки → Конфиденциальность**. Каждая опция показывает раскрываемые данные. Перед сохранением прочитайте подтверждение; владельцу нужно недавнее подтверждение паролем и кодом входа, если он включён. Чтение API требует `read`, запись — `admin`.

Каждое изменение записывает автора (имя токена, `owner` или `root`), время, а также полные значения до и после. Консоль и CLI показывают 50 последних изменений.

## Понижение режима

- `full` → `private` преобразует сохранённые идентификаторы в отпечатки с ключом и удаляет системы, модели и приложения.
- Устройства → `off` удаляет все записи об устройствах.
- `daily` → `off` удаляет все ежедневные записи людей и серверов. Суммарный трафик за всё время и последняя активность остаются.
- Сокращение срока хранения удаляет записи за пределами нового срока.

Настройка, удаление и запись об изменении сохраняются вместе. Ответ показывает число удалённых или преобразованных записей. Удаление человека удаляет и его ежедневные записи; общий трафик серверов сохраняется до окончания срока хранения.

Отпечатки нельзя обратить в идентификаторы. Переход `private` → `full` удаляет приватные записи; устройства регистрируются заново при следующем запросе подписки.

## Снимки и восстановление

Настройки конфиденциальности и журнал изменений входят в зашифрованные снимки. Записи устройств и ежедневная история входят в них только при включённом соответствующем режиме.

Ключ отпечатков — секрет сервиса и **никогда не входит в снимок**. После восстановления **записи устройств private удаляются**, а устройства регистрируются заново при следующем запросе подписки. Записи full и включённая история переживают восстановление.

Понижение режима влияет на текущие данные и будущие снимки. Уже сохранённые снимки содержат записи, включённые при их создании; защищайте их ключами резервного копирования. См. [Восстановление](/ru/recovery/).
