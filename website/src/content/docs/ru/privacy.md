По умолчанию в Meridian **ограничение числа устройств выключено** и **посуточная история трафика выключена**. Дополнительный сбор данных включаете только вы, если он действительно нужен. Ни в одном из режимов не сохраняются IP-адреса клиентов, логи подключений или запрашиваемые адреса.

Сервис управления хранит только то, без чего невозможна выдача подписок: учётные записи пользователей и их ключи подключения, общий объём переданного трафика за всё время и время последней активности. Любой, кто получит доступ к серверу управления, увидит эти базовые данные. Настройки ниже определяют, какие сведения об устройствах и суточном расходе будут сохраняться дополнительно.

## Ограничение числа устройств

| Режим | Что сохраняет Meridian | Что видите вы |
| --- | --- | --- |
| `off` (по умолчанию) | Записи об устройствах не ведутся; устройства не отслеживаются и не ограничиваются | Счётчик устройств скрыт |
| `private` | HMAC-SHA256-отпечатки идентификаторов устройств с секретным ключом, известным только вашему сервису управления; без ОС, моделей и приложений | Количество устройств и установленный лимит |
| `full` | Идентификатор устройства, платформа, версия ОС, модель, User-Agent, а также время первого и последнего запроса подписки | Полный список устройств каждого пользователя |

**Предупреждение для режима `private`:**

> Устройства каждого человека считаются по необратимому отпечатку. Meridian не хранит названия устройств, операционные системы и приложения. Тот, кто получит доступ к серверу управления, сможет лишь проверить, подключалось ли конкретное известное ему устройство.

**Предупреждение для режима `full`:**

> Meridian сохраняет идентификатор, ОС, модель и приложение каждого устройства, а также время последнего обновления подписки. Тот, кто получит доступ к серверу управления, узнает, какими устройствами пользуется каждый человек. IP-адреса никогда не сохраняются.

Лимит по умолчанию — **3 устройства** (настраивается в диапазоне **от 1 до 100**). Он применяется ко всем пользователям, для которых не задан индивидуальный лимит. Подробнее см. в разделе [Управление клиентами](/ru/client-management/).

## История трафика

| Режим | Что сохраняет Meridian |
| --- | --- |
| `off` (по умолчанию) | Общий трафик за всё время и момент последней активности, без посуточной разбивки |
| `daily` | Объём отправленных и полученных данных по каждому пользователю и суммарный трафик каждого сервера за каждые сутки (по UTC) |

По умолчанию посуточная история хранится **90 дней** (можно задать **от 7 до 730 дней**, включая текущие сутки). Записи старше установленного срока автоматически очищаются каждые 30 секунд, а при уменьшении срока хранения — сразу же.

> Meridian хранит суточный расход трафика по каждому человеку и серверу за последние N дн. Тот, кто получит доступ к серверу управления, узнает, в какие дни каждый человек пользовался VPN.

Прирост счётчиков трафика относится к тем суткам по UTC, когда отчёт от узла поступил в сервис управления (если узел прислал отчёт с задержкой, трафик попадёт в день получения). Повторно отправленные отчёты учитываются только один раз. За время, когда запись истории была выключена, статистика не восстанавливается; пустые дни означают отсутствие записанного трафика. Сброс лимита трафика пользователя (`reset-traffic`) не удаляет его посуточную историю.

В веб-панели доступны графики по каждому пользователю и по серверам, а в CLI — компактные таблицы:

```bash
meridian client usage alice --days 30
meridian client show alice                 # последние 7 дней, если история включена
meridian fleet usage --days 7
```

Запрошенный период автоматически ограничивается настроенным сроком хранения. Пока история выключена, запросы к API статистики возвращают ошибку `409 history_off`.

## Как изменить настройки

Настройки конфиденциальности принадлежат сервису управления — применение файла конфигурации серверов (`meridian apply`) никогда их не сбрасывает.

```bash
meridian privacy                          # то же, что privacy show
meridian privacy show --json
meridian privacy set --devices private --device-limit 3
meridian privacy set --history daily --history-days 90
meridian privacy set --devices off --history off --yes --json
```

Изменяются только те параметры, которые вы явно указали в команде. При переходе на более подробный уровень сбора данных CLI выводит предупреждение о сохраняемых данных и просит подтверждения (флаг `--yes` пропускает интерактивный вопрос и обязателен при работе с `--json`). Повторная установка тех же самых значений ничего не меняет.

В веб-панели эти параметры находятся в разделе **Настройки → Конфиденциальность**. Для каждого режима отображается полное описание сохраняемых данных, а перед сохранением запрашивается подтверждение паролем владельца (и одноразовым кодом, если он включён). В API чтение настроек доступно с правом `read`, а изменение — с правом `admin`.

Каждое изменение фиксируется в журнале аудита: кто его внёс (имя API-токена, `owner` или `root`), точное время и полные значения параметров «было» и «стало». В веб-панели и CLI отображаются последние 50 записей.

## Понижение уровня сбора данных

- Переход `full` → `private` преобразует сохранённые идентификаторы устройств в защищённые ключом отпечатки и безвозвратно удаляет данные об ОС, моделях и приложениях.
- Отключение учёта устройств (`off`) удаляет все записи об устройствах.
- Переход `daily` → `off` удаляет всю посуточную историю по пользователям и серверам (общий трафик за всё время и время последней активности сохраняются).
- Уменьшение срока хранения сразу удаляет записи, выходящие за новые рамки.

Обновление настройки, удаление данных и запись в журнале аудита выполняются в одной транзакции, а в ответе возвращается точное число удалённых или преобразованных записей. При удалении пользователя его посуточная история удаляется сразу, а суммарная статистика серверов хранится до истечения срока хранения.

Восстановить исходные идентификаторы устройств из отпечатков невозможно. При переходе `private` → `full` приватные записи сбрасываются, и устройства регистрируются заново при следующем обновлении подписки.

## Резервные снимки и восстановление

Настройки конфиденциальности и журнал их изменений сохраняются в зашифрованных резервных снимках. Записи об устройствах и посуточная история включаются в снимок только тогда, когда соответствующий режим включён.

Секретный ключ для расчёта отпечатков устройств хранится только на сервере управления и **никогда не включается в резервные снимки**. Поэтому после восстановления сервера из снимка **приватные записи об устройствах очищаются**, а устройства заново занимают слоты при следующем обновлении подписки. Записи в режиме `full` и включённая посуточная история полностью сохраняются при восстановлении.

Понижение уровня сбора данных очищает текущую базу и будущие снимки, однако ранее сохранённые на вашем компьютере файлы снимков содержат те данные, которые были включены в момент их создания — храните ключи от резервных копий в надёжном месте. См. [Восстановление при блокировке IP](/ru/recovery/).
