## Зачем нужен промежуточный сервер

Если провайдер заблокирует IP-адрес вашего зарубежного выходного сервера, прямые подключения перестанут работать. Промежуточный сервер (relay) создаёт для пользователей точку входа на российском IP-адресе, который блокируют гораздо реже:

```
Клиент → Промежуточный сервер (внутренний IP) → Выходной сервер (за рубежом) → Интернет
```

Для систем фильтрации провайдера это выглядит как соединение с сервером внутри страны. Промежуточный сервер передаёт необработанный TCP-поток на ваш зарубежный сервер; шифрование остаётся сквозным от устройства пользователя до выходного сервера, поэтому на промежуточном сервере трафик никогда не расшифровывается.

## Как устроен промежуточный сервер

На промежуточном сервере работает [Realm](https://github.com/zhboner/realm) — легковесный TCP-форвардер с передачей данных без лишнего копирования в памяти (zero-copy). Он принимает входящие соединения на порту 443 (порт можно изменить) и перенаправляет их на порт приёма Reality выходного сервера. Никаких других компонентов Meridian — ни сервиса управления, ни агента узла — на промежуточном сервере нет; настройка выполняется с вашего компьютера по SSH.

Через промежуточные серверы передаётся трафик протокола **Reality**. Протоколы XHTTP, WSS и Hysteria2 продолжают работать напрямую через IP-адрес или домен выходного сервера и остаются в подписке как альтернативные маршруты.

## Добавление промежуточного сервера

Сначала разверните выходной сервер за рубежом, а затем привяжите к нему промежуточный сервер:

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.10
```

Meridian добавит промежуточный сервер в топологию и применит изменения:
1. Подготовит систему (обновит базовые пакеты, включит BBR, защитит SSH и настроит файрвол UFW так, чтобы открытыми остались только порт SSH и рабочий порт промежуточного сервера)
2. Установит проверенную по контрольной сумме SHA-256 сборку Realm как системную службу systemd
3. Настроит перенаправление TCP-потока на порт Reality выбранного выходного сервера
4. Добавит новые маршруты во все пользовательские подписки

### Параметры команды

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--exit/-e EXIT` | (обязателен) | IP-адрес или имя выходного сервера |
| `--name NAME` | (автоматически) | Понятное имя промежуточного сервера (например, `ru-moscow`) |
| `--port/-p PORT` | 443 | Порт приёма входящих соединений на промежуточном сервере |
| `--sni HOST` | SNI выходного сервера | Отдельный сайт маскировки Reality для этого промежуточного сервера (если не указан, наследует SNI выходного сервера) |
| `--user/-u USER` | root | Пользователь SSH на промежуточном сервере |
| `--ssh-port PORT` | 22 | Порт SSH на промежуточном сервере |
| `--yes/-y` | | Применить изменения без интерактивного запроса подтверждения |

### Пример со всеми параметрами

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.10 --name ru-moscow \
  --port 443 --sni dl.google.com --user ubuntu --ssh-port 2222 --yes
```

## Как подключаются пользователи

У существующих пользователей маршруты через промежуточный сервер появятся при очередном обновлении подписки (и сразу отобразятся на их страницах подключения), а новым пользователям они включаются автоматически:

```bash
meridian client add alice   # маршрут через промежуточный сервер уже в подписке
```

## Управление промежуточными серверами

```bash
meridian relay list                       # все промежуточные серверы
meridian relay list --exit 198.51.100.10  # промежуточные серверы для одного выхода
```

Проверить состояние всех звеньев цепочки (что службы Realm запущены, каждое звено видит следующее, а входной порт принимает подключения) и протестировать прохождение реального трафика можно командами:

```bash
meridian check 203.0.113.10
meridian test
```

Команда `check` также проверяет пропускную способность каждого плеча маршрута: с каждого звена она запрашивает главную страницу сайта маскировки через следующее звено с тем же SNI, который отправляют клиенты, и замеряет время соединения, задержку до первого байта и объём принятых данных. Если передача замирает на отметке 8–32 КБ, это характерный признак замедления трафика (ТСПУ) на данном участке — в этом случае поможет перенос промежуточного сервера к другому хостинг-провайдеру. Если главная страница выбранного сайта маскировки весит меньше 32 КБ, проверка объёма помечается как неопределённая.

Если `meridian test --probe` показал, что текущий домен маскировки (SNI) промежуточного сервера заблокирован, смените его одной командой. Meridian проверит, что выходной сервер открывает новый сайт по TLS 1.3 и HTTP/2, покажет план и применит изменения (чтобы вернуться к сайту маскировки выходного сервера, укажите SNI самого выхода):

```bash
meridian relay sni 203.0.113.10 dl.google.com
```

Чтобы вывести промежуточный сервер из работы, удалите его из топологии — Meridian покажет список удаляемых ресурсов, остановит службу Realm, очистит правила файрвола и обновит подписки:

```bash
meridian relay remove 203.0.113.10
```

## Несколько промежуточных серверов

К одному выходному серверу можно подключить сразу несколько промежуточных серверов — например, у разных провайдеров или в разных городах:

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.10 --name ru-moscow
meridian relay add 203.0.113.11 --exit 198.51.100.10 --name ru-spb
```

Все они попадут в подписку каждого пользователя. Цепочки из нескольких последовательных промежуточных серверов настраиваются через мастер `meridian setup`.

## Работа в условиях «белых списков» на мобильных сетях

Во время временных ограничений мобильного интернета в отдельных регионах операторы иногда переходят в режим «белых списков», пропуская трафик только к ограниченному перечню разрешённых доменов и российских подсетей. Правила фильтрации зависят от конкретного оператора и региона и нигде официально не публикуются. Meridian не отслеживает такие списки автоматически — ниже описано, какие настройки можно применить самостоятельно.

### Наблюдения администраторов

- **Операторы фильтруют по-разному.** В одних сетях проверяется только доменное имя в заголовке TLS (SNI), в других — одновременно и SNI, и IP-адрес назначения. Там, где проверяется только SNI, иногда достаточно подобрать разрешённый домен маскировки на прямом зарубежном сервере. Там, где фильтруются и IP-адреса, первой точкой входа должен быть сервер внутри разрешённой российской подсети.
- **Не каждая подсеть российского облака проходит.** Даже у одного и того же облачного провайдера одна подсеть может входить в белый список, а соседняя — блокироваться.
- **Зарубежные адреса CDN в режиме белых списков обычно не открываются.** [Режим домена](/ru/domain-mode/) через Cloudflare хорошо помогает при блокировке конкретного IP на домашнем интернете, но не заменяет точку входа внутри страны при жёстких мобильных ограничениях.
- **Связь между промежуточным и выходным сервером тоже может попадать под фильтрацию.** Даже если телефон пользователя видит промежуточный сервер, сам этот сервер должен успешно достучаться до вашего зарубежного выходного сервера.

### Настройка промежуточного сервера с отдельным SNI

Арендуйте VPS у российского провайдера, чья подсеть остаётся доступной в мобильной сети ваших пользователей, и добавьте его как промежуточный сервер с собственным доменом маскировки (`--sni`):

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.10 --name ru-mobile --sni allowed.example.com
```

При указании `--sni` этот домен используется только для маршрута через данный промежуточный сервер. На выходном сервере для него создаётся отдельный порт приёма Reality (принимающий пакеты только от промежуточного сервера), настроенный на имитацию `allowed.example.com`. Любые проверочные запросы без вашего ключа прозрачно перенаправляются на настоящий сайт `allowed.example.com` и получают его подлинный сертификат. Основной сайт маскировки выходного сервера и остальные маршруты в подписке при этом не затрагиваются. Сменить SNI промежуточного сервера позже можно командой `meridian relay sni RELAY NEW_SNI`.

После добавления проверьте цепочку:

```bash
meridian check 203.0.113.10
meridian test
```

Помните, что проверка с домашнего интернета не покажет, проходит ли трафик через мобильную сеть в режиме ограничений — обязательно проверьте подключение с телефона в самой мобильной сети.

### Подбор SNI для прямого подключения к выходу

Флаг `--sni` в командах `meridian deploy` и `meridian node add` задаёт сайт маскировки для прямого маршрута Reality. Выходной сервер должен открывать этот сайт по TLS 1.3; перед развёртыванием кандидата можно проверить командой `meridian check IP --sni HOST`.

### Ограничения

- Meridian не знает, какие подсети или домены входят в белые списки конкретного оператора и действуют ли ограничения в данный момент.
- Meridian не настраивает проксирование через российские CDN-сервисы (режим домена рассчитан на работу с Cloudflare).
- Через промежуточные серверы передаётся только протокол Reality; маршруты XHTTP, WSS и Hysteria2 всегда ведут напрямую к выходному серверу.
- Meridian не строит туннели поверх сторонних мессенджеров или сервисов видеозвонков.

## Устранение неполадок

### Порт уже занят

Если порт 443 на промежуточном сервере занят другой службой, проверьте список процессов командой `ss -tlnp sport = :443` и остановите конфликтующий сервис либо выберите другой порт с помощью флага `--port 8443`.

### Порт закрыт во внешнем файрволе

Убедитесь, что выбранный порт открыт для входящих TCP-соединений не только в UFW на самом сервере, но и в панели управления вашего облачного провайдера (Security Groups / Firewall).

### Нет связи с выходным сервером

Промежуточный сервер должен беспрепятственно подключаться к порту TCP 443 вашего выходного сервера. Запустите `meridian test` для сквозной проверки маршрута и `meridian check EXIT` для диагностики самого выходного сервера.

### Служба перенаправления не запущена

На промежуточных серверах службы и конфигурационные файлы именуются нейтрально (юниты `netfwd-*`, каталог `/etc/netfwd/`), чтобы в списке процессов и системном журнале не встречались названия Meridian или Realm. Проверить их статус и логи на самом промежуточном сервере можно командами:

```bash
systemctl list-units 'netfwd-*'
journalctl -u 'netfwd-*' --no-pager -n 20
```
