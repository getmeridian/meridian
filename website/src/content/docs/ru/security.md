## Сообщение об уязвимостях

Если вы обнаружили уязвимость безопасности в Meridian:

1. **НЕ создавайте публичный issue**
2. Сообщите о ней приватно через [GitHub Security Advisories](https://github.com/getmeridian/meridian/security/advisories/new)
3. Опишите шаги воспроизведения и возможное влияние

Мы стараемся отвечать в течение 48 часов и указываем авторов отчётов в описании исправления.

## Архитектура безопасности

- **Учётные данные**: хранятся с правами `0600` в `~/.config/meridian/cluster.yml`, секреты никогда не подставляются в shell-команды без `shlex.quote()` и автоматически скрываются в выводе `meridian doctor`. Права на каталог — `0700` (только для владельца). Любое приложение, запущенное от имени вашего пользователя, может прочитать эти файлы — так устроены все CLI-инструменты, хранящие ключи локально (SSH-ключи, токены облачных CLI и т. д.). Если ваша учётная запись на компьютере скомпрометирована, шифрование локального файла не спасёт: вредоносное ПО сможет перехватить парольную фразу или SSH-сессию. Следите за безопасностью своего компьютера.
- **Доступ к сервису управления**: сервис управления проксируется через nginx по секретному HTTPS-пути — SSH-туннель не нужен. Страницы подключения и ссылки на подписку используют отдельный путь и никогда его не раскрывают. CLI хранит токен администратора в `~/.config/meridian/cluster.yml`; скрипты получают собственные отзываемые токены с ограниченными правами
- **Веб-консоль**: один владелец, пароль и необязательный код из аутентификатора; сеанс истекает после 30 минут бездействия и максимум через 12 часов. Создание токена и изменение конфиденциальности требуют недавнего подтверждения паролем. Консоль управляет людьми и конфиденциальностью, не серверами, и не хранит SSH-ключей. Она ничего не загружает с других сайтов и работает под строгой Content Security Policy
- **Узлы**: агенты сами подключаются к сервису управления по HTTPS, поэтому узлы не открывают порт управления. Каждый узел регистрируется по одноразовому токену, а затем получает сертификат от собственного удостоверяющего центра ваших серверов. Каждый документ, который выполняет узел, подписан сервисом управления и проверяется агентом, который отвергает всё, что старше уже применённого
- **Приватность**: ограничение устройств и история трафика по умолчанию выключены; сервис хранит суммарный трафик за всё время и последнюю активность. Можно включить отпечатки устройств с ключом, полные данные устройств или ежедневный трафик с ограниченным сроком хранения. Ни один режим не хранит IP-адреса клиентов, журналы подключений или пути запросов. См. [Конфиденциальность](/ru/privacy/) о захвате сервера
- **Резервные копии**: снимки шифруются с помощью [age](https://age-encryption.org/) для ключа каждого управляющего компьютера и для ключа восстановления, закрытая часть которого есть только у вас. В них нет ключей подписи, сеансов и пароля консоли: восстановление создаёт новые, поэтому изъятый сервер управления не может подписать ничего, что примут восстановленные серверы
- **SSH**: вход по паролю отключён, а fail2ban включён по умолчанию (`--no-harden` пропускает и то и другое, а также настройку файрвола — для серверов, на которых работают другие сервисы)
- **Файрвол**: UFW блокирует все входящие соединения, кроме портов SSH сервера и портов, необходимых его роли — TCP/443 для трафика VPN, TCP/80 там, где выпускаются сертификаты, UDP/443 при включённом Hysteria2 и порт прослушивания на промежуточных серверах
- **DNS на выходных серверах**: выходные серверы определяют адрес каждого сайта через зашифрованный DNS (DNS over HTTPS одновременно к Cloudflare, Quad9 и Google, по IP-адресам), а не через DNS-сервер хостинг-провайдера, поэтому ни одно имя сайта не уходит с сервера открытым текстом. Если не отвечает ни один из трёх, сайты по имени через этот сервер не открываются: открытый DNS не подключается взамен. `meridian check` сообщает, какой из DNS-серверов недоступен с сервера
- **Закреплённые версии ПО**: сервис управления устанавливает точный выпуск Meridian через uv, проверенный по контрольной сумме; агент поставляется внутри пакета Meridian; скачиваемые Xray, Realm и RealiTLScanner закреплены по версиям и проверяются по контрольным суммам SHA-256
- **TLS**: [acme.sh](https://github.com/acmesh-official/acme.sh) выпускает и продлевает сертификаты Let's Encrypt, которые отдаёт nginx

## Границы ответственности

Meridian настраивает VPN-серверы и **не** реализует собственные криптографические протоколы. Безопасность соединений опирается на:

- [Xray-core](https://github.com/XTLS/Xray-core) — протоколы VLESS+Reality, XHTTP, WSS и Hysteria2
- [age](https://age-encryption.org/) (через pyrage) — шифрование снимков
- [nginx](https://nginx.org/) — маршрутизация по SNI и завершение TLS
- [acme.sh](https://github.com/acmesh-official/acme.sh) — выпуск и продление сертификатов Let's Encrypt
- [Realm](https://github.com/zhboner/realm) — перенаправление TCP на промежуточных серверах
