В Meridian **нет телеметрии, аналитики и рекламы**. Meridian не отправляет диагностические отчёты разработчикам. Страницы подключения и помощи, веб-панель и сайт используют собственные скрипты, стили, шрифты, значки и средства построения QR-кодов; **сторонние ресурсы не загружаются**. Переход в магазин приложений, по ссылке для связи с владельцем или на другой сайт происходит по вашему выбору.

Для установки, продления сертификатов, DNS и проверки связи нужен доступ к сети. Ниже перечислены эти обращения и передаваемые данные.

## Как сообщить об уязвимости

Если вы обнаружили уязвимость в системе безопасности Meridian:

1. **НЕ создавайте публичный issue**
2. Отправьте закрытый отчёт через [GitHub Security Advisories](https://github.com/getmeridian/meridian/security/advisories/new)
3. Опишите шаги для воспроизведения и потенциальные последствия

Мы стараемся отвечать в течение 48 часов и благодарим авторов отчётов в описании релиза с исправлением.

## Исходящие запросы

Получатель любого соединения видит IP-адрес подключившейся машины и обычные заголовки протокола. В таблицах указаны дополнительные данные. Конфигурация ваших серверов, учётные данные VPN-клиентов и записи о расходе трафика передаются только вашим серверам и сервису управления. Единого переключателя для полностью автономного развёртывания нет. Загрузки могут следовать перенаправлениям источника, в том числе на хосты файлов релизов GitHub. Имена для установщиков и проверок разрешаются через настроенный DNS подключающейся машины.

|--------|---------------------------------|---------------|
| **Установка CLI → `getmeridian.org`, GitHub и источники пакетов** | Вы загружаете `https://getmeridian.org/install.sh`. Если uv отсутствует, установщик получает скрипт фиксированной версии из astral-sh/uv и соответствующий архив, затем устанавливает Meridian с зависимостями из источников пакетов, обычно PyPI; при необходимости загружает и Python. Передаёт запросы скрипта, файлов, версий пакетов и платформы. | Только при запуске установщика; уже установленный uv исключает загрузки для его установки. |
| **Уведомление об обновлении → PyPI** (`pypi.org/pypi/meridian-vpn/json`) | CLI с обычным текстовым выводом проверяет список версий пакета не чаще раза в минуту. В запросе есть имя пакета, но нет данных о ваших серверах. При JSON-выводе и запуске `serve` проверка пропускается. | Задайте `MERIDIAN_DISABLE_UPDATE_CHECK=1`. Менеджер пакетов передаёт запросы с именами пакетов, версиями и платформой настроенному индексу, обычно PyPI и `files.pythonhosted.org`; uv при необходимости загружает Python с GitHub. | Запускайте команду, когда хотите обновиться. Индексы, кэш и автономный режим настраиваются в менеджере пакетов. |

| **Подсказка страны → IANA и RDAP соответствующего регионального интернет-регистратора (RIR)** | При добавлении выхода получает карту регистраторов IPv4/IPv6 у IANA, затем запрашивает регистрационную запись IP сервера. | **Определение публичного IP локальной машины → `ifconfig.me`, `api.ipify.org` или `api64.ipify.org`** | Для нового адресата `local` обращается к сервису, возвращающему внешний IP этой машины; при неудаче пробует следующий. | Используйте сохранённый сервер или явно указанный адрес, чтобы не определять IP заново. |
| **Картинка оформления → указанный вами URL** | Значок-картинка один раз загружается на ваш компьютер и сохраняется как встроенные данные изображения. Хост картинки получает URL и заголовок user-agent Meridian. | Используйте эмодзи или уже встроенные данные изображения. Браузер не обращается к исходному URL картинки. |
| **Управление серверами → ваши серверы и сервис управления** | Рабочие операции передают аутентификацию SSH, команды и файлы либо токены HTTPS API и нужные для операции настройки, учётные данные, команды и запросы резервных копий. Миграция читает только указанную вами старую панель. | Необходимо для управления работающими серверами; локальные операции просмотра и экспорта используют описанное для них локальное состояние. |
| **Помощник для тестирования Xray → релизы XTLS/Xray-core на GitHub** | При тесте соединения загружает архив фиксированной версии для вашей ОС и архитектуры, если локальный кэш помощника неполон. | Полный кэш исключает повторную загрузку. У теста, которому нужен помощник, нет флага отключения загрузки. |

### Проверки и установка на серверах

| Запрос | Когда выполняется и что передаёт | Как управлять |
|--------|---------------------------------|---------------|
| **Проверки связи, маскировки и блокировок → проверяемые адреса и сайты** | `check`, `test`, `--probe`, подбор SNI и проверка развёртывания отправляют TCP/TLS/HTTP-запросы с вашего компьютера или серверов. Передают выбранный SNI, HTTP-путь или тестовые байты. Прямое и обратное разрешение имён использует DNS-резолвер машины. | Дополнительные проверки запускаете вы. Развёртывание требует проверки связи; явный SNI исключает автоматический поиск соседей, но выбранный сайт всё равно проверяется. |
| **Тесты соединения → сервисы определения IP** | HTTPS-запрос через проверяемый VPN идёт к `api.ipify.org`, `ipv4.icanhazip.com` или `v4.ident.me`; для IPv6 — к `api6.ipify.org`, `ipv6.icanhazip.com` или `v6.ident.me`. Сервис видит IP выхода. При неудаче тест может повторить запрос напрямую, показав сервису IP управляющего компьютера. | Задайте `MERIDIAN_CONNECT_TEST_URL` с собственным адресом, возвращающим IP. Развёртывание тоже использует эти тесты трафика. |
| **Поиск сайта маскировки → GitHub и соседние TLS-сайты** | `scan` и автоматические подсказки SNI загружают фиксированную версию RealiTLScanner из XTLS/RealiTLScanner, проверяют соседние адреса и имена из сертификатов через DNS и TLS. Сайты видят проверки с сервера. | Явно задайте `--sni`, чтобы избежать автоматического поиска, и не запускайте `scan`, если сканирование не нужно. |
| **Системные пакеты и обновления безопасности → репозитории APT** | Установка получает пакеты из репозиториев ОС. Базовая подготовка включает ежедневное обновление списков пакетов и автоматические обновления безопасности. Если пакета дистрибутива недостаточно, она устанавливает nginx из `nginx.org`. Запросы раскрывают дистрибутив, архитектуру и пакеты. | Источники и расписание APT контролирует администратор сервера; применение базовой подготовки восстанавливает её настройки обновлений. `--no-harden` не отключает обновления пакетов. |
| **Установка сервиса управления → GitHub и PyPI** | Загружает архив фиксированной версии uv из astral-sh/uv, Python через uv и точную версию `meridian-vpn` с зависимостями из PyPI или настроенных индексов. При запуске из редактируемого checkout wheel собирается на управляющем компьютере, что может потребовать зависимостей сборки из индекса пакетов, затем передаётся по SSH. | Уже актуальная установка или заполненный кэш не требуют загрузок. Обычной установке нужны источники пакетов. |
| **Установка промежуточного сервера → релизы zhboner/realm на GitHub** | При установке или смене бинарного файла загружает архив фиксированной версии Realm. Передаёт только запрос публичного файла релиза. | Совпадающая установленная версия не требует загрузки. |
| **Утилита сертификатов → `raw.githubusercontent.com`** | Если acme.sh отсутствует, загружает скрипт фиксированной версии из acmesh-official/acme.sh, затем проверяет и устанавливает его. | Существующая установка используется повторно. |
| **Выпуск и продление сертификатов → Let's Encrypt** | acme.sh выполняет ACME-запросы для IP или домена сервера: передаёт идентификаторы сертификата, публичные ключи, доказательства владения учётной записью и контактный email, если он задан. Продление запускается через cron. Идентификаторы сертификата также попадают в публичные журналы Certificate Transparency. | Для обычного развёртывания нужны доверенные сертификаты. `MERIDIAN_ACME_SERVER` выбирает другой ACME-центр, но не отключает сертификаты. |

### Сервис управления и агенты узлов

| Запрос | Когда выполняется и что передаёт | Как управлять |
|--------|---------------------------------|---------------|
| **Зеркало файлов сервиса управления → HTTPS-источники, обычно релизы Xray на GitHub** | При запуске, смене спецификации узла или запросе отсутствующего файла агентом загружает недостающие архивы с фиксированной контрольной суммой. Неудачные запросы после обращения за отсутствующим файлом повторяются не чаще раза в минуту. Передаёт публичный URL файла без данных о пользователях и трафике. | Настройки отключения зеркала нет. Проверенные файлы в кэше не требуют обращения к источнику. |
| **Агент узла → ваш сервис управления** | Регистрируется, открывает и продлевает сеансы, запрашивает подписанные документы и команды, сообщает применённые ревизии и состояние служб, передаёт общие счётчики трафика по пользователям, подтверждает команды и загружает файлы сервиса. Передаёт токен регистрации или доказательства идентичности, токены сеансов, сведения об узле и сборке, а также отчёты. | Необходимо для работы агента. Его остановка прекращает управление конфигурацией и передачу счётчиков. |
| **Агент узла → HTTPS-источники фиксированных бинарных сборок, обычно GitHub** | Подписанный документ состояния может потребовать архив Xray. Сформированная спецификация сначала пробует GitHub, затем зеркало сервиса. Источник видит URL файла и сборку агента в user-agent; токен сервиса ему не передаётся. | Установленные бинарные файлы и кэш исключают загрузки. Зеркало служит запасным источником при недоступности GitHub; переключателя CLI для его приоритетного использования нет. |

**Сам агент не загружает свою сборку с GitHub.** Wheel Meridian содержит статические musl-сборки для x86_64 и aarch64 с файлами контрольной суммы и версии сборки. Управляющий компьютер проверяет вложенную сборку и передаёт её по SSH при установке или обновлении.

### VPN-трафик и приложения

| Запрос | Когда выполняется и что передаёт | Как управлять |
|--------|---------------------------------|---------------|
| **Выход → запрошенные пользователем ресурсы и сайт маскировки Reality** | Передаёт пользовательский трафик. Reality и перенаправление nginx также обращаются к выбранному сайту для TLS-маскировки и обработки подключений без аутентификации. Сайт видит соединение с выхода, SNI и перенаправленный проверочный трафик. nginx разрешает имя сайта маскировки через DNS-резолвер сервера. | Сайт маскировки выбираете вы; self-steal использует собственный локальный сайт. Передача пользовательского трафика — основная задача VPN. |
| **DNS выхода → Cloudflare, Quad9 и Google** | Имена пользовательских ресурсов разрешаются параллельными DoH-запросами к доступным IPv4/IPv6-адресам: Cloudflare `1.1.1.1` / `2606:4700:4700::1111`, Quad9 `9.9.9.10` / `2620:fe::10`, Google `8.8.8.8` / `2001:4860:4860::8888`, путь везде `/dns-query`. Каждый получивший запрос оператор видит имена и IP выхода. `check` отправляет этим адресам также фиксированный пример DNS-запроса. | Переключателя DNS в CLI нет. Если никто не отвечает, разрешение имён на выходе завершается ошибкой без перехода к обычному DNS. Эти запросы идут напрямую с сервера даже при включённом WARP. |
| **Необязательный WARP → Cloudflare** | При установке получает ключ и пакет из `pkg.cloudflareclient.com`; warp-cli регистрирует сервер и открывает туннель WARP. Выбранный для WARP трафик выходит через Cloudflare, который видит регистрацию сервера и адресатов исходящего трафика. | WARP необязателен: не включайте его, чтобы избежать установки, регистрации и туннеля. Если служба уже установлена, для прекращения её сетевых соединений её нужно остановить на сервере. |
| **Необязательный маршрутизирующий шлюз → DNS-сервисы и URL проверки пула** | Шлюзы используют Google DoH на `dns.google`, обычный DNS на `8.8.8.8` и системный резолвер для прямого трафика. Пул выходов выполняет проверки через свои выходы каждые 10 секунд, по умолчанию обращаясь к `https://www.apple.com/library/test/success.html`; тестовый сайт видит IP выхода и HTTP-запрос. | Шлюзы и пулы необязательны. В конфигурации пула, которую вы проверяете перед применением, можно задать собственный `probe_url`. На DNS шлюза не распространяется гарантия исключительно зашифрованного DNS выхода. |
| **Промежуточный сервер Realm → следующее звено или выход** | Передаёт зашифрованный TCP-поток клиента адресатам из проверенной конфигурации. Не запускает агент, VPN-ядро или отдельный клиент телеметрии. | Вы выбираете цепочку и выход. |
| **VPN-приложение → сервис подписок, DNS и тестовый сайт** | Выбранное приложение обновляет подписку и может выполнять собственные DNS-запросы и проверки связи. Профили Xray JSON от Meridian задают обычный DNS на `1.1.1.1` / `8.8.8.8` и проверку тестовой страницы Apple каждую минуту; активная группа резервирования Mihomo проверяет эту страницу каждые 5 минут; sing-box задаёт Cloudflare DNS по TLS и UDP и проверяет страницу каждые 3 минуты. Тестовый сайт видит исходящий IP маршрута, но не учётные данные подписки. | Поведение приложения отдельно от страницы в браузере. Настраивайте DNS и проверки в приложении или его конфигурации. |

### Страницы подключения, веб-панель и сайт

- **Страницы подключения и помощи:** только к своему сервису — страницы и конфигурация, состояние аккаунта, подписки, общие ресурсы и дополнительные проверки часов и передачи данных. Сервис получает секретный URL пользователя и обычные заголовки браузера. QR-коды и экспорт изображений выполняются локально. Сторонних запросов нет.
- **Веб-панель:** только к своему сервису — ресурсы интерфейса, вход, обновление сеанса, чтение и запись API, обновление видимых экранов. Пароли, коды аутентификатора, cookies сеанса и изменения поступают вашему сервису. Сторонних запросов нет.
- **Сайт:** только к собственному сайту, включая шрифты, поисковые файлы, Markdown-копии и ресурсы демонстраций. Демо веб-панели отвечает на API-запросы в браузере. Аналитики, внешних шрифтов, встроенных сторонних плееров и сторонних запросов нет.

Внешние ссылки на приложения, документацию и помощь открываются, только когда вы переходите по ним. Страница не загружает эти сайты в фоне.

## Проверка загрузок

Для Xray, Realm, RealiTLScanner, acme.sh и установки uv на сервере фиксируются версии и **проверяется SHA-256 до запуска**. Установщик CLI также проверяет скрипт фиксированной версии uv, содержащий контрольные суммы архивов. В релизах есть `SHA256SUMS` для проверки установщика Meridian перед запуском. Несовпадение останавливает установку.

Зеркало сервиса управления и агент проверяют **точный размер и SHA-256** файла до публикации или извлечения. До применения контрольных сумм агент проверяет подпись сервиса на документе состояния. Статические musl-сборки агента сверяются с файлами контрольных сумм в wheel и проверяются после передачи по SSH. Обновление серверов принимает новый релиз Realm только при наличии опубликованных GitHub SHA-256 для каждого нужного файла.

Сервис управления фиксирует версию пакета Meridian. Зависимости Python используют индекс и проверки целостности менеджера пакетов; пакеты ОС — подписанные репозитории APT. Для добавляемых репозиториев nginx и WARP проверяются ожидаемые отпечатки ключей подписи. Целостность загрузки всё равно опирается на доверие к источнику пакета или релиза, задающему контрольную сумму.

## Архитектура безопасности

- **Учётные данные**: хранятся в файле `~/.config/meridian/cluster.yml` с правами доступа `0600` в каталоге с правами `0700` (доступ только у владельца). Секреты никогда не передаются в shell-команды без экранирования через `shlex.quote()` и автоматически скрываются в выводе `meridian doctor`. Любая программа, запущенная от имени вашего пользователя, может прочитать эти файлы — это общее свойство всех локальных CLI-утилит (SSH-ключей, токенов облачных провайдеров и т. п.). При компрометации вашей учётной записи локальное шифрование файла не защитит от перехвата парольной фразы или активной SSH-сессии, поэтому следите за безопасностью своего компьютера.
- **Доступ к сервису управления**: сервис управления работает за обратным прокси nginx по секретному HTTPS-пути — поднимать SSH-туннель не требуется. Страницы подключения и ссылки на подписку обслуживаются по отдельному префиксу и никогда не раскрывают секретный путь управления. Токен администратора для CLI хранится в `~/.config/meridian/cluster.yml`, а для скриптов выпускаются отдельные токены с ограниченными правами, которые можно отозвать в любой момент.
- **Веб-панель**: рассчитана на одного владельца с паролем и необязательным одноразовым кодом (TOTP); сеанс завершается через 30 минут бездействия и максимум через 12 часов с момента входа. Для выпуска API-токенов и изменения настроек конфиденциальности требуется повторно подтвердить пароль. Через веб-панель управляются пользователи, общие сообщения, язык и настройки конфиденциальности — в ней нет управления топологией серверов и никогда не хранятся SSH-ключи. Веб-панель не делает внешних запросов и защищена строгой политикой Content Security Policy (CSP).
- **Узлы**: агенты на серверах сами устанавливают исходящее HTTPS-соединение с сервисом управления, поэтому открывать входящие порты управления на узлах не нужно. Каждый узел регистрируется по одноразовому токену и получает клиентский сертификат от внутреннего удостоверяющего центра ваших серверов. Конфигурационные документы подписываются сервисом управления; агент проверяет криптографическую подпись и отвергает любые документы со старым номером ревизии.
- **Конфиденциальность**: ограничение числа устройств и посуточная история трафика по умолчанию выключены — сервис управления хранит только общий объём трафика за всё время и время последней активности. При необходимости можно включить учёт устройств по защищённым ключом отпечаткам, полное сохранение метаданных устройств или посуточную статистику с ограниченным сроком хранения. IP-адреса клиентов, логи подключений и пути запросов не сохраняются ни в одном из режимов. Подробный разбор того, какие данные окажутся на сервере в случае его изъятия, приведён в разделе [Конфиденциальность](/ru/privacy/).
- **Резервные копии**: снимки состояния шифруются с помощью [age](https://age-encryption.org/) для ключей каждого управляющего компьютера и для ключа восстановления, закрытая часть которого хранится только у вас. В снимки не включаются ключи подписи узлов, активные сеансы и пароль от веб-панели: при восстановлении создаются новые ключи, поэтому компрометация старого сервера управления не позволит подделать команды для восстановленных серверов.
- **SSH**: вход по паролю отключается, а защита fail2ban включается по умолчанию (флаг `--no-harden` пропускает эти шаги и настройку файрвола на серверах, где работают сторонние службы).
- **Файрвол**: UFW блокирует все входящие соединения, кроме порта SSH и портов, необходимых для роли сервера: TCP/443 для VPN-трафика, TCP/80 на серверах, выпускающих сертификаты, UDP/443 при включённом Hysteria2 и рабочего порта на промежуточных серверах.
- **DNS выходных серверов**: имена пользовательских ресурсов разрешаются параллельными запросами DNS over HTTPS к Cloudflare, Quad9 и Google по IP. Эти операторы видят имена; провайдер хостинга не получает их в обычных DNS-запросах. Если никто не отвечает, разрешение имён завершается ошибкой без перехода к обычному DNS. Проверки при установке, разрешение имени сайта маскировки, DNS шлюзов и приложений работают отдельно, как описано выше.
- **Версии и целостность**: проверяемые бинарные загрузки, подписанные документы состояния и вложенные статические musl-сборки агента защищают установку, как описано выше; сервис управления запускает точную версию пакета Meridian.
- **TLS**: выпуск и автоматическое продление сертификатов Let's Encrypt выполняются через [acme.sh](https://github.com/acmesh-official/acme.sh), а терминация TLS — силами nginx.

## Границы ответственности

Meridian отвечает за безопасную настройку и оркестрацию серверов, но **не** разрабатывает собственные криптографические протоколы. Криптографическая защита и сетевой стек опираются на проверенные проекты:

- [Xray-core](https://github.com/XTLS/Xray-core) — реализация протоколов VLESS+Reality, XHTTP, WSS и Hysteria2
- [age](https://age-encryption.org/) (через библиотеку pyrage) — шифрование резервных снимков
- [nginx](https://nginx.org/) — маршрутизация по TLS SNI и терминация HTTPS
- [acme.sh](https://github.com/acmesh-official/acme.sh) — выпуск и продление сертификатов Let's Encrypt
- [Realm](https://github.com/zhboner/realm) — перенаправление TCP-соединений на промежуточных серверах
