## Диагностика

Запустите проверку со своего компьютера (подключение по SSH не требуется):

```
meridian test 198.51.100.10
```

Если проверка TCP на порту 443 не проходит из вашей сети, но успешно проходит из другой сети (например, от другого провайдера или через работающий VPN), скорее всего, заблокирован сам IP-адрес сервера. Если же порт 443 не отвечает ниоткуда, проверьте внешний файрвол в панели облачного провайдера и убедитесь, что сам сервер включён.

Когда ни один маршрут выходного сервера не отвечает из вашей сети, `meridian test` в конце выводит готовую команду `node replace` для переноса этого узла на новый IP (в JSON-выводе она возвращается в поле `data.recovery`).

Чтобы точнее определить характер блокировки, выполните [`meridian test 198.51.100.10 --probe`](/ru/cli-reference/#взгляд-цензора-meridian-test---probe) изнутри сети, где наблюдается проблема: команда проверит, блокируется ли сам IP-адрес сервера или домен маскировки (SNI). Пользователи без установленного CLI могут просто открыть свою страницу подключения и нажать «Проверить соединение».

## Как быстро восстановить связь

Если сервер был развёрнут в **режиме домена** (`--domain`) с включённым проксированием через Cloudflare, маршруты XHTTP и WSS продолжат работать — трафик для них идёт на адреса Cloudflare, а не на заблокированный IP вашего сервера. Приложения с поддержкой Xray JSON, Mihomo и sing-box переключатся на них автоматически; в остальных приложениях достаточно выбрать подключение XHTTP или WSS вручную.

Если перед выходным сервером настроен **промежуточный сервер** внутри страны, пользователи, подключающиеся через него (`via relay`), не заметят блокировки, пока сам промежуточный сервер сохраняет связность с зарубежным выходным сервером.

## Способы восстановления

### Вариант 1: добавить новый выходной сервер

Самый быстрый способ, если сервер управления (на котором работает сервис управления) по-прежнему доступен с вашего компьютера:

```bash
# 1. Арендуйте новый VPS с чистым IP-адресом
# 2. Добавьте его к вашим серверам
meridian node add 198.51.100.20 --name replacement
```

Все учётные записи пользователей и их ссылки сохранятся. Новый выходной сервер появится в приложениях после очередного обновления подписки (или сразу после нажатия кнопки «Обновить» в приложении).

### Вариант 2: перенести заблокированный выходной сервер на новый IP

Команда `node replace` переносит существующий выходной сервер на новую машину, сохраняя его внутренний идентификатор, ключи Reality, настроенные протоколы и привязанные к нему промежуточные серверы, а затем очищает старый сервер:

```bash
meridian node replace exit-1 198.51.100.20
```

Приложения подхватят новый адрес при обновлении подписки, а промежуточные серверы сразу начнут перенаправлять трафик на новый IP. Перенести таким способом сервер управления нельзя, поскольку его адрес зашит в ссылки подписок (для переноса сервера управления используется `meridian restore`).

Если старый сервер уже недоступен по SSH из вашей сети, `node replace` всё равно сначала полностью настроит новый сервер и переключит на него пользователей, а ошибкой завершится только финальный шаг очистки старой машины. Вы можете завершить очистку позже командой `meridian apply` (когда блокировка спадёт или через сеть, откуда старый сервер виден). Если же старый сервер уже удалён в панели хостинга или доступ к нему потерян окончательно, поручите Meridian забыть его:

```bash
meridian apply --forget-unreachable
```

При этом Meridian пропустит очистку по SSH и удалит запись об узле из сервиса управления (флаг `--forget-unreachable` можно передать и сразу в команду `node replace`). Учитывайте, что если старая виртуальная машина всё ещё запущена у провайдера, оставшийся на ней Xray продолжит пускать старых клиентов, пока вы не удалите саму виртуальную машину в панели хостинга.

### Вариант 3: подключить домен для работы через CDN

Если раньше вы не использовали домен, добавьте его к новому выходному серверу:

```bash
meridian node add 198.51.100.20 --domain vpn.example.com
```

Пошаговая настройка Cloudflare описана в разделе [Режим домена](/ru/domain-mode/).

### Вариант 4: добавить промежуточный сервер внутри страны

Промежуточный сервер у местного хостинг-провайдера даёт пользователям внутреннюю точку входа, которая остаётся доступной при блокировке зарубежных подсетей:

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.20
```

Чтобы перенаправить существующий промежуточный сервер на другой выходной сервер, удалите маршрут командой `meridian relay remove` и добавьте его заново с нужным `--exit`.

### Сервер управления потерян

Если сервер управления безвозвратно утерян (удалён, изъят или наглухо заблокирован), восстановите его на новом VPS из резервного снимка:

```bash
meridian restore --to 198.51.100.30
```

После каждого изменения конфигурации ваш компьютер автоматически сохраняет зашифрованный снимок состояния сервиса управления в папку `snapshots/`, поэтому актуальная копия всегда под рукой. Команда `restore` покажет план восстановления, установит сервис управления на новый сервер, развернёт из снимка базу пользователей (со всеми ключами, лимитами и накопленной статистикой трафика) и переподключит агенты всех ваших выходных серверов к новому центру управления.

- **Ссылки пользователей**: если сервис управления работал по IP-адресу без домена, этот IP-адрес входил во все ссылки подписок, поэтому при переезде на новый IP ссылки изменятся — в конце работы `restore` выведет новые ссылки для каждого пользователя. Если же для панели управления использовался домен, ссылки останутся прежними, как только вы перенаправите A-запись домена на новый IP-адрес.
- **Проверка старого сервера**: пока старый сервер управления продолжает отвечать по сети, `restore` не запустится, чтобы не возникло два конфликтующих центра управления. Если старый сервер отвечает, но вы ему больше не доверяете (например, к нему получили доступ посторонние), укажите флаг `--force`.
- **Новые ключи безопасности**: восстановленный сервис управления создаёт новый удостоверяющий центр и новые ключи подписи документов, поэтому старый скомпрометированный сервер не сможет отдавать команды вашим узлам. Для входа в веб-консоль запросите новую ссылку установки пароля командой `meridian panel`.
- **Восстановление с нового компьютера**: если у вас нет доступа к прежнему компьютеру, скопируйте файл снимка на новый компьютер и запустите `meridian restore --to NEW_IP --snapshot FILE --recovery-key`, после чего введите свой ключ восстановления. Сам файл снимка уже содержит копию `cluster.yml` и `servers.json`; на новом компьютере потребуется только SSH-доступ к новому серверу и существующим выходным серверам.

Ключ восстановления выводится один раз при первом развёртывании; сгенерировать новый ключ можно командой `meridian backup recovery-key`. Храните его офлайн отдельно от рабочего компьютера. Подробнее см. [`meridian restore`](/ru/cli-reference/#meridian-restore).

## Управление серверами с нескольких компьютеров

Все локальные данные о ваших серверах хранятся в каталоге `~/.config/meridian/` на компьютере, с которого выполнялось развёртывание. Чтобы управлять ими со второго компьютера, скопируйте этот каталог туда, исключив файл `device.key` и папку `snapshots/` (при первом изменении второй компьютер автоматически создаст собственный ключ для резервных снимков). После внесения изменений в топологию не забывайте синхронизировать каталог `~/.config/meridian/` между своими компьютерами. Команда `meridian backup devices` показывает список компьютеров, для которых шифруются снимки, а `meridian backup revoke` отзывает доступ у потерянного или неиспользуемого устройства.

Meridian защищает конфигурацию от случайной перезаписи устаревшими данными. Сервис управления помнит последнюю применённую ревизию, и перед любым изменением CLI сверяет вашу локальную копию с сервером (команда `meridian plan` заранее предупредит о расхождении):

- **"Another machine changed this fleet"**: локальная копия на этом компьютере отстаёт от сервера. Скопируйте свежий каталог `~/.config/meridian/` с того компьютера, с которого изменения применялись последними, и повторите команду.
- **"Another apply is running"**: прямо сейчас изменения применяются с другого устройства. Дождитесь завершения операции (если тот процесс аварийно прервался, блокировка автоматически снимется через 30 минут; прерванный запуск с того же самого компьютера повторному запуску не мешает).
- **"This control server belongs to a different copy of the fleet"**: локальный каталог `~/.config/meridian/` был создан с нуля, а не скопирован с компьютера, управляющего этим сервером.

## Как подготовиться к блокировкам заранее

1. **Добавьте промежуточный сервер** внутри страны: `meridian relay add RELAY_IP --exit EXIT_IP`
2. **Подключите домен** для резервного маршрута через CDN Cloudflare: `--domain vpn.example.com`
3. **Комбинируйте оба способа** — тогда в подписке каждого пользователя будут сразу три независимых маршрута: через промежуточный сервер внутри страны, через CDN Cloudflare и напрямую к зарубежному серверу
4. **Сохраните ключ восстановления офлайн** — он вместе с файлом снимка позволит поднять потерянный сервер управления одной командой `meridian restore`
5. **Делайте резервную копию `~/.config/meridian/`** — чтобы не потерять SSH-ключи и настройки при поломке ноутбука

## Не удаляйте заблокированный сервер сразу

Провайдеры нередко снимают временные блокировки подсетей через несколько дней или недель. Оставьте сервер включённым на некоторое время и периодически проверяйте его:

```bash
meridian test 198.51.100.10
```

Если адрес так и не разблокировали, выведите сервер из конфигурации командой `meridian node remove`.
