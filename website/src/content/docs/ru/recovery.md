## Диагностика

Запустите со своей машины (SSH не требуется):

```
meridian test 198.51.100.10
```

Если проверка TCP на порту 443 не удаётся из вашей сети, но работает из другого места (другая сеть, VPN, [инструмент ping](https://getmeridian.org/ping)), IP, вероятно, заблокирован. Отказ TCP везде обычно означает облачный брандмауэр или выведенный из строя сервер.

## Немедленное облегчение

Если вы развернулись с **доменом** (`--domain`) и запись проксируется через Cloudflare, пути XHTTP и WSS по-прежнему работают — они достигают Cloudflare, не вашего заблокированного IP. Приложения, использующие JSON Xray или подписку Mihomo, переключаются автоматически; другие могут вручную выбрать запись XHTTP или WSS.

Если у вас есть **ретранслятор**, клиенты, подключающиеся через него, не затрагиваются, пока сам ретранслятор может достичь выхода.

## Варианты восстановления

### Добавить замещающий выход

Самый быстрый путь, пока ваш сервер control plane (на котором работает панель) по-прежнему доступен со своей машины:

```bash
# 1. Получите новый VPS у вашего провайдера (новый IP)
# 2. Подготовьте узел и зарегистрируйте его в текущей панели
meridian node add NEW_IP

# 3. Проверьте узел
meridian node check NEW_IP
```

Клиенты хранятся в панели на уровне всего кластера, поэтому повторно добавлять их для нового узла не нужно. Новый выход появится в их приложениях после обновления подписки.

`meridian node add` требует доступной текущей панели Remnawave. Если потерянный сервер также размещал панель, сначала восстановите этот хост; автоматическая миграция панели пока не поддерживается.

### Вариант B: Новый выходной сервер + существующий relay

Следующая императивная последовательность относится только к legacy Realm-relay:

```bash
# 1. Добавьте новый выходной узел
meridian node add NEW_EXIT_IP

# 2. Переключите relay на новый выход
meridian relay remove RELAY_IP --exit OLD_EXIT_IP
meridian relay deploy RELAY_IP --exit NEW_EXIT_IP

# Клиенты переподключаются автоматически — IP relay не изменяется
```

В V4 команды `relay remove` и `node remove` для управляемых ресурсов отклоняются. Откройте `meridian setup`, измените exit/relay chain в intent, проверьте план и примените его. После этого подтвердите канонический маршрут через `meridian test`, а не только доступность listener.

### Вариант C: Добавить режим домена для fallback CDN

Если вы раньше не использовали режим домена, добавьте его теперь, чтобы предотвратить будущие перебои:

```bash
meridian node add NEW_IP --domain proxy.example.com
```

С режимом домена WSS/CDN соединение работает даже когда IP сервера заблокирован — трафик маршрутизируется через Cloudflare. Смотрите [руководство режима домена](/docs/ru/domain-mode/) для настройки Cloudflare.

## Упреждающая защита

Установите устойчивость **до** того как ваш IP заблокирован:

1. **Разверните relay** — дает клиентам домашнюю точку входа. Когда выходной IP заблокирован, замените выход позади relay без изменения клиентов:
   ```bash
   meridian relay deploy RELAY_IP --exit EXIT_IP
   ```

2. **Включите режим домена** — добавляет WSS/CDN fallback, который работает даже если IP заблокирован:
   ```bash
   meridian deploy EXIT_IP --domain proxy.example.com
   ```

3. **Оба** — максимальная устойчивость. Клиенты имеют три пути: relay (домашний), CDN (Cloudflare) и прямой (если не заблокирован).

## Клиенты и подписки

Клиенты принадлежат панели Remnawave, а не отдельному выходному узлу. Команды `meridian node add` и `meridian relay deploy` добавляют новые хосты в существующие подписки, поэтому повторно выполнять `meridian client add` не нужно.

Попросите пользователей обновить подписку в приложении. `meridian client show NAME` всегда повторно выдаёт URL подписки и QR-код; PWA-ссылка выводится только при наличии подтверждённой legacy-страницы. Пропавшую legacy-страницу можно явно восстановить через `--repair-page`.

## Восстановление локального состояния

`meridian fleet recover` не является общим восстановлением V4. Оно работает только явно для legacy shared-profile deployment:

```bash
meridian fleet recover --legacy --panel-url https://PANEL_HOST/SECRET_PATH
```

URL обязан содержать полный секретный путь. Recovery отказывается угадывать profile, squad, panel node или неоднозначное WSS-соответствие node-to-domain, восстанавливает `sub_path`/Reality key через SSH и регистрирует узлы в `servers.json`. V4 intent восстанавливайте из резервной копии либо пересоздавайте через `meridian setup`.

## Оставьте старый сервер

Не удаляйте старый сервер сразу — он может стать разблокированным через дни или недели. Вы можете проверять периодически:

```bash
meridian test OLD_IP
```

Если он вернется, у вас есть запасной выходной сервер готов к использованию.
