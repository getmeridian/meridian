---

## Диагностика

Запустите со своей собственной машины (SSH не требуется):

```
meridian test 198.51.100.10
```

Если проверка TCP на порту 443 не проходит из вашей сети, но работает откуда-то ещё (из другой сети или через VPN), IP, скорее всего, заблокирован. Отказ TCP везде обычно означает облачный файрвол или сервер, который не работает.

Когда с выхода ничего не отвечает из вашей сети, `meridian test` в конце выводит для него команду `node replace` (см. ниже); с `--json` она приходит в `data.recovery`.

Чтобы понять, что именно заблокировано, запустите [`meridian test 198.51.100.10 --probe`](/ru/cli-reference/#взгляд-цензора-meridian-test---probe) изнутри цензурируемой сети: команда сообщит, выглядит ли заблокированным IP сервера или маскировочный SNI. Тем, у кого нет CLI, достаточно открыть свою страницу подключения: если она загружается в их сети, сервер управления оттуда достижим.

## Немедленное облегчение

Если вы развёрнули с **доменом** (`--domain`) и запись проксируется через Cloudflare, пути XHTTP и WSS всё ещё работают — они достигают Cloudflare, не вашего заблокированного IP. Приложения, использующие JSON Xray или подписку Mihomo, переключаются самостоятельно; другие могут выбрать запись XHTTP или WSS вручную.

Если у вас есть **промежуточный сервер**, клиенты, подключающиеся через него, не затрагиваются, пока он сам может достичь выходного сервера.

## Варианты восстановления

### Добавить замену выхода

Самый быстрый путь, пока ваш сервер управления (тот, на котором работает сервис управления) всё ещё достижим с вашей машины:

```bash
# 1. Получите новый VPS у вашего провайдера (новый IP)
# 2. Добавьте его к своим серверам
meridian node add 198.51.100.20 --name replacement
```

Клиенты сохраняют свои учётные записи. Они получают новый выход при следующем обновлении подписки — попросите их обновить в приложении, если это не происходит автоматически.

### Или переместить заблокированный выход на новый сервер

`node replace` перемещает выход на новый сервер, сохраняя его ID, ключи, пути протокола и промежуточные серверы, затем очищает старый сервер:

```bash
meridian node replace exit-1 198.51.100.20
```

Клиенты подберут новый адрес при следующем обновлении подписки. Сервер управления не может быть перемещён таким образом: его адрес входит в каждый URL подписки.

Если старый сервер заблокирован и из вашей сети, перенос всё равно сначала разворачивает новый сервер, и клиенты переходят на него; не удаётся только очистка старого сервера. Завершите её командой `meridian apply`, когда блокировку снимут, или из сети, откуда старый сервер доступен. Если этого не случится (вы удалили его у провайдера или он остаётся заблокированным), пусть Meridian его забудет:

```bash
meridian apply --forget-unreachable
```

Тогда Meridian пропускает эту очистку; сервис управления по-прежнему забывает то, что хранил у себя. Всё, что работало на старом сервере, продолжает обслуживать прежних пользователей, включая клиентов, которых вы удалите позже, пока вы не удалите или не очистите сервер у провайдера. Чтобы сделать это за один шаг, передайте `--forget-unreachable` прямо в `node replace`.

### Добавить домен для резервного CDN

Если вы не использовали домен, добавьте его к новому выходу:

```bash
meridian node add 198.51.100.20 --domain vpn.example.com
```

См. [Domain mode](/ru/domain-mode/) для шагов Cloudflare.

### Добавить промежуточный сервер

Промежуточный сервер внутри страны даёт пользователям точку входа, которая остаётся достижимой, когда иностранные IP заблокированы:

```bash
meridian relay add 203.0.113.10 --exit 198.51.100.20
```

Чтобы направить промежуточный сервер на другой выход, удалите его командой `meridian relay remove` и добавьте снова, указав в `--exit` новый выход.

### Сервер управления потерян

Если сервер управления пропал (удалён, изъят или заблокирован навсегда), восстановите его на новом сервере из снимка:

```bash
meridian restore --to 198.51.100.30
```

Каждый компьютер, который управляет вашими серверами, после каждого изменения сохраняет зашифрованный снимок сервиса управления, поэтому свежий снимок уже лежит у вас. Restore показывает, что собирается сделать, устанавливает сервис управления на новый сервер из этого снимка и применяет вашу конфигурацию: агент каждого выхода регистрируется на новом сервере, а клиенты сохраняют свои учётные записи, лимиты и трафик.

- **Ссылки**: если сервер работает по голому IP, его адрес входит в каждый URL подписки, поэтому все ссылки меняются; restore выводит новую ссылку для каждого клиента. С доменом ссылки остаются прежними, как только DNS-запись указывает на новый сервер; при проверке restore называет эти записи.
- **Старый сервер**: restore отказывается работать, пока старый сервер управления отвечает, потому что два сервиса управления разделили бы ваши серверы. Если он отвечает, но вы ему больше не доверяете (например, его изъяли), передайте `--force`.
- **Ключи**: новый сервер получает новый удостоверяющий центр и новые ключи подписи, поэтому изъятый сервер не может подписать ничего, что примут ваши узлы. Владелец консоли задаёт новый пароль по ссылке, которую выводит `meridian panel`.
- **Другой компьютер**: на компьютере без ваших серверов скопируйте туда файл снимка и выполните `meridian restore --to NEW_IP --snapshot FILE --recovery-key`, затем вставьте ключ восстановления, когда его спросят. Снимок содержит файлы вашей конфигурации; этому компьютеру всё равно нужен SSH-доступ к новому серверу и к вашим выходам.

Ключ восстановления показывается один раз, в конце первого развёртывания; `meridian backup recovery-key` создаёт новый. Храните его офлайн, отдельно от компьютеров, которые управляют серверами. См. [`meridian restore`](/ru/cli-reference/#meridian-restore).
## Управление с нескольких компьютеров

Всё, что Meridian знает о ваших серверах, хранится в `~/.config/meridian/` на компьютере, с которого вы их разворачивали. Чтобы управлять серверами со второго компьютера, скопируйте туда этот каталог без `device.key` и `snapshots/`, чтобы второй компьютер при первом изменении получил собственный ключ резервных копий. Обновляйте копию после изменений, сделанных на другом устройстве. `meridian backup devices` показывает компьютеры, которые получают снимки, а `meridian backup revoke` убирает тот, которым вы больше не пользуетесь.

Случайно затереть изменения, сделанные с другого компьютера, не получится. Сервис управления хранит отметку о последнем применённом изменении. Перед любым изменением Meridian сверяет локальную копию с этой отметкой, а `meridian plan` заранее предупредит, если `apply` будет отклонён:

- **"Another machine changed this fleet"**: ваша локальная копия устарела. Скопируйте `~/.config/meridian/` с компьютера, где изменения применялись последними, и повторите команду.
- **"Another apply is running"**: кто-то прямо сейчас применяет изменения. Подождите завершения. Если тот процесс аварийно оборвался, блокировка сама снимется через 30 минут (а прерванный запуск на том же самом компьютере вас не блокирует).
- **"This control server belongs to a different copy of the fleet"**: локальный каталог `~/.config/meridian/` был создан отдельно, а не скопирован с компьютера, который управляет этим сервером.

## Подготовка на случай блокировки

1. **Добавьте промежуточный сервер** внутри страны: `meridian relay add RELAY_IP --exit EXIT_IP`
2. **Подключите домен** для резервного канала через CDN: разверните с `--domain vpn.example.com`
3. **Используйте оба варианта** — тогда у клиентов будет три способа входа: через промежуточный сервер (внутри страны), через CDN (Cloudflare) и напрямую
4. **Храните ключ восстановления офлайн** — с ним и снимком `meridian restore` восстановит потерянный сервер управления
5. **Сделайте резервную копию `~/.config/meridian/`** — она позволит управлять серверами с другого компьютера

## Не спешите удалять старый сервер

Не удаляйте заблокированный сервер сразу — иногда блокировки снимают через несколько дней или недель. Время от времени проверяйте его:

```bash
meridian test 198.51.100.10
```

Когда он больше не нужен, удалите его командой `meridian node remove`.
