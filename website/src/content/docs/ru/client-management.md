## Добавить клиента

```
meridian client add alice
```

Команда создаёт уникальный доступ для `alice` и выводит URL подписки и QR-код. В legacy-развёртывании Meridian также пытается развернуть отдельную PWA-страницу на хосте панели. В V4 пользователь добавляется в `topology_intent.access.users`, обновлённый intent применяется, а выдаётся каноническая подписка Remnawave без отдельной PWA-страницы.

Передайте несколько имён чтобы добавить несколько клиентов сразу:

```
meridian client add alice bob charlie
```

В legacy-режиме ошибки сообщаются отдельно: успешно созданные клиенты сохраняются, а частичный batch или неудачная загрузка страницы завершаются кодом `3`. В V4 все имена сначала добавляются в access intent, затем применяется получившийся план.

### Что видит получатель

В legacy-режиме успешно развёрнутая страница подключения содержит:
- Пошаговыми инструкциями по установке VPN приложения (v2RayTun, v2rayNG, Hiddify или v2rayN)
- QR-кодами для каждого протокола подключения
- Ссылками "Открыть в приложении" одним нажатием
- Статусом подключения и статистикой использования

Если страница недоступна или используется V4, отправляйте URL подписки или его QR-код: это всегда канонический источник настроек подключения.

## Отобразить данные подключения

Чтобы в любой момент повторно отобразить информацию о подключении существующего клиента:

```
meridian client show alice
```

Команда выводит QR-код и URL подписки, не создавая новый ключ. PWA-ссылка выводится только при наличии положительного подтверждения, что страница развёрнута. Для явного ремонта отсутствующей legacy-страницы выполните:

```
meridian client show alice --repair-page
```

Используйте `show`, когда:
- Вам нужно повторно отправить страницу подключения кому-то
- Вы потеряли исходный QR-код или URL
- Вы хотите повторно получить каноническую подписку

В V4 `show` и `list` отображают только пользователей, объявленных в access intent; пользователи, созданные напрямую в панели, не приобретают владение Meridian автоматически. `--repair-page` относится только к legacy-страницам.

## Список клиентов

```
meridian client list
```

Показывает статус и статистику клиентов. В V4 список ограничен пользователями из access intent.

## Удалить клиента

```
meridian client remove alice
```

В legacy-режиме команда удаляет пользователя панели и его подтверждённую локальную страницу. В V4 она намеренно отклоняется: безопасное удаление управляемого access-пользователя ещё не реализовано. Для немедленного временного отзыва используйте `client disable`; не удаляйте пользователя напрямую в панели.

## Приостановить клиента

```
meridian client disable alice
```

Временно блокирует клиента от подключения. Его конфигурация остаётся целой — ключи не удаляются и URL подписки остаётся действительным. В V4 команда принимает только объявленного access-пользователя, а отключение действует лишь до следующего `meridian apply`, который снова приводит объявленный доступ к активному состоянию.

Для повторного включения: `meridian client enable alice`

## Повторно включить клиента

```
meridian client enable alice
```

Возобновляет ранее приостановленного клиента. Он может снова подключаться сразу же используя существующие ключи и URL подписки.

## Где хранятся данные

Meridian хранит топологию флота локально в `~/.meridian/cluster.yml` — URL панели, токен API, учётные данные админа, узлы и ретрансляторы. Состояние клиента (пользователи, UUID, трафик) живёт в базе данных PostgreSQL панели Remnawave, которая является источником истины.

```
~/.meridian/cluster.yml                 # топология флота + доступ к панели
```

Команды клиента работают с REST API панели по сохранённому токену. Обычные операции не требуют SSH; исключения — развёртывание, проверка, ремонт и удаление legacy PWA-страницы на хосте панели.

После потери локального состояния `meridian fleet recover --legacy --panel-url https://HOST/SECRET_PATH` может импортировать один однозначный общий legacy-профиль. V4 topology intent восстановить из панели нельзя; для V4 используйте резервную копию или снова запустите `meridian setup`.

## Веб-панель

Meridian развёртывает панель управления [Remnawave](https://remna.st/) для мониторинга трафика, управления пользователями и продвинутой конфигурации. Она обратно проксируется nginx'ом по случайному пути HTTPS — SSH туннель не требуется. Найдите URL и учётные данные админа в `~/.meridian/cluster.yml`:

```
grep -A6 "^panel:" ~/.meridian/cluster.yml
```

Соответствующие поля:

```yaml
panel:
  url: https://<your-server-ip>/<secret_path>/
  admin_user: admin
  admin_pass: <generated>
  api_token: <JWT used by Meridian CLI>
  secret_path: <random>
  sub_path: <random>   # subscription page path
```

Откройте `url` в браузере и выполните вход используя `admin_user` / `admin_pass`.

Изменения управляемых ресурсов на стороне панели появляются как drift. В legacy желаемый список задаётся `desired_clients`; в V4 авторитетен `topology_intent.access.users`. Перед `apply` всегда проверяйте план, особенно удаление посторонних ресурсов.

## Как это работает

Каждый клиент Meridian — пользователь Remnawave с UUID. В legacy он привязывается к общему Internal Squad. В V4 доступ компилируется из access intent и управляется драйверами ресурсов. URL подписки Remnawave содержит только разрешённые этому пользователю endpoints и остаётся каноническим источником для приложений.

Приложения клиента (v2rayNG, Streisand, Hiddify, sing-box) обрабатывают URL подписки как один источник истины: обновление его подтягивает новые входящие когда вы развёртываете новый выход, добавляете ретранслятор или ротируете ключи Reality.

## Декларативный доступ

Для legacy-развёртываний можно добавить `desired_clients` в `~/.meridian/cluster.yml`:

```yaml
desired_clients:
  - alice
  - bob
  - charlie
```

Затем `meridian plan` сравнивает список с панелью, а `meridian apply` приводит состояние в соответствие. В V4 эквивалентом является `topology_intent.access.users`: добавляйте пользователей через `meridian client add` или пересматривайте intent в `meridian setup`; `desired_clients` не является источником истины V4.
