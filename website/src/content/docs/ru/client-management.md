## Добавить клиента

```
meridian client add alice
```

Это создает уникальный ключ подключения для "alice" и отображает:
- **QR-код** в терминале — отсканируйте его с помощью VPN-приложения для быстрого подключения
- **Ссылку на PWA-страницу** — она размещена на вашем сервере и готова к отправке через любой мессенджер
- **URL подписки** — единая ссылка для импорта доступных подключений в совместимые клиенты

Передайте несколько имён чтобы добавить несколько клиентов сразу:

```
meridian client add alice bob charlie
```

Каждый клиент получает свой собственный ключ и страницу подключения. Ошибки сообщаются для каждого клиента — успешно созданные клиенты сохраняются даже если некоторые не удались.

### Что видит получатель

Страница для обмена открывает страницу подключения с:
- Пошаговыми инструкциями по установке VPN приложения (v2RayTun, v2rayNG, Hiddify или v2rayN)
- QR-кодами для каждого протокола подключения
- Ссылками "Открыть в приложении" одним нажатием
- Статусом подключения и статистикой использования

Отправьте URL через электронную почту, iMessage, Telegram или любой другой мессенджер. Получатель открывает его, устанавливает приложение, сканирует QR-код и подключается. Не требуется никаких технических знаний.

## Отобразить данные подключения

Чтобы в любой момент повторно отобразить информацию о подключении существующего клиента:

```
meridian client show alice
```

Команда выводит тот же QR-код, ссылку на PWA-страницу и URL подписки, не создавая новый ключ. Используйте её, когда:
- Вам нужно повторно отправить страницу подключения кому-то
- Вы потеряли исходный QR-код или URL
- Вы хотите проверить, как выглядит подключение клиента

## Список клиентов

```
meridian client list
```

Показывает всех клиентов с их подключениями по протоколам (Reality, XHTTP, WSS).

## Удалить клиента

```
meridian client remove alice
```

Отзывает доступ сразу. UUID клиента удаляется из всех входящих каналов на сервере.

## Приостановить клиента

```
meridian client disable alice
```

Временно блокирует клиента от подключения. Его конфигурация остаётся целой — ключи не удаляются и URL подписки остаётся действительным. Используйте это чтобы приостановить доступ без потери настроек клиента.

Для повторного включения: `meridian client enable alice`

## Повторно включить клиента

```
meridian client enable alice
```

Возобновляет ранее приостановленного клиента. Он может снова подключаться сразу же используя существующие ключи и URL подписки.

## Где хранятся данные

Meridian хранит топологию флота локально в `~/.meridian/cluster.yml` — URL панели, токен API, учётные данные админа, узлы и ретрансляторы. Состояние клиента (пользователи, UUID, трафик) живёт в базе данных PostgreSQL панели Remnawave, которая является источником истины.

```
~/.meridian/cluster.yml                 # топология флота + доступ к панели
```

Команды клиента говорят непосредственно с REST API панели используя сохранённый токен API. SSH не требуется для операций с клиентом.

Если вы потеряли локальный файл, `meridian fleet recover` перестраивает `cluster.yml` из активного REST API панели.

## Веб-панель

Meridian развёртывает панель управления [Remnawave](https://remna.st/) для мониторинга трафика, управления пользователями и продвинутой конфигурации. Она обратно проксируется nginx'ом по случайному пути HTTPS — SSH туннель не требуется. Найдите URL и учётные данные админа в `~/.meridian/cluster.yml`:

```
grep -A6 "^panel:" ~/.meridian/cluster.yml
```

Соответствующие поля:

```yaml
panel:
  url: https://<your-server-ip>/<secret_path>/
  admin_user: admin
  admin_pass: <generated>
  api_token: <JWT used by Meridian CLI>
  secret_path: <random>
  sub_path: <random>   # subscription page path
```

Откройте `url` в браузере и выполните вход используя `admin_user` / `admin_pass`.

Изменения на стороне панели (например переименование пользователя, отключение хоста) появляются в Meridian как дрейф — следующий `meridian plan` показывает различие между фактическим состоянием панели и желаемым состоянием вашего `cluster.yml`. Используйте `meridian apply` чтобы привести в соответствие в любом направлении.

## Как это работает

Каждый клиент Meridian это один пользователь Remnawave (один UUID в таблице `users`). Пользователь назначается на внутренний по умолчанию Squad Meridian'а, который предоставляет видимость над каждым входящим которой панель знает (`vless-reality`, `vless-xhttp` и `vless-xhttp-ws` в режиме домена). URL подписки — `https://<ip>/<sub_path>/<short_uuid>` — обслуживается контейнером страницы подписки Remnawave и содержит все входящие конечные точки которые клиент может использовать.

Приложения клиента (v2rayNG, Streisand, Hiddify, sing-box) обрабатывают URL подписки как один источник истины: обновление его подтягивает новые входящие когда вы развёртываете новый выход, добавляете ретранслятор или ротируете ключи Reality.

## Декларативный список клиентов

Для установок флота в масштабах вы можете управлять клиентами декларативно вместо императивно. Добавьте список `desired_clients` в `~/.meridian/cluster.yml`:

```yaml
desired_clients:
  - alice
  - bob
  - charlie
```

Затем `meridian plan` показывает различие против фактического списка пользователей панели, и `meridian apply` приводит в соответствие — добавляет любых отсутствующих клиентов, удаляет любых лишних. `meridian client add/remove` всё ещё работает наряду с этим; два подхода сосуществуют. Смотрите [декларативный рабочий процесс](/docs/ru/getting-started/#declarative-workflow) для полной истории.
