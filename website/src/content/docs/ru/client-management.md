## Добавить клиента

```
meridian client add alice
```

Команда создаёт для «alice» личный ключ и выводит две ссылки, которыми можно поделиться:

- **Ссылка на страницу подключения** с QR кодом — самый простой способ отправить
- **URL подписки** для прямого импорта в приложение Xray/V2Ray

Добавьте нескольких человек сразу:

```
meridian client add alice bob charlie
```

Клиенты принадлежат всем вашим серверам, а не одному серверу. Каждый выход и промежуточный сервер, который у вас есть, показывается в их подписке.

### Что видит получатель

Страница подключения построена из подлинной подписки человека, поэтому она перечисляет ровно то, что получают его приложения: прямые выходы, промежуточные серверы и все включённые способы. На ней есть:

- Три шага: установить приложение, рекомендованное для платформы человека (сначала Happ, затем FlClashX и Clash Mi, а на компьютере ещё Throne), и добавить подключение одним касанием, затем включить подключение по подсказкам приложения
- QR-код подписки; на компьютере он показан рядом с шагами, чтобы человек мог настроить телефон
- Каждое отдельное подключение с кнопками «Открыть», «Копировать» и QR, свёрнутое, пока не понадобится
- Раздел «Не подключается?» с советами и проверкой «Проверить подключение», которая копирует отчёт без ссылок, чтобы его можно было отправить вам

В приложении записи названы по стране выхода и способу: «🇩🇪 DE · Reality · Chrome», «🇩🇪 DE · XHTTP · Chrome», «🇩🇪 DE · WebSocket · CDN», «🇩🇪 DE · Hysteria2 · UDP»; у записей через промежуточный сервер добавляется «via relay». Если два выхода находятся в одной стране, после флага показываются их имена («🇩🇪 main»); у выхода с неизвестной страной показывается его имя, когда выходов несколько. Reality и XHTTP приходят также копиями «· Firefox» с другим отпечатком TLS — на случай, если один отпечаток заблокируют. Приложения с автопереключением (приложения на Xray JSON, такие как Happ, а также Mihomo и sing-box) сами выбирают рабочую запись, но не переключаются между отпечатками; для этого Happ показывает отдельную запись «Automatic · Firefox».

Отправьте ссылку через любой мессенджер. Получатель открывает её, устанавливает приложение, нажимает «Добавить в …» (или сканирует QR-код с другого устройства) и подключается. [Подключение](/ru/connecting/) проводит человека через эти шаги и подсказывает, что делать, когда подключение перестаёт работать; отправьте ему и эту страницу.

## Показать детали подключения

Чтобы снова поделиться ссылками клиента:

```
meridian client show alice
```

Команда выводит личный URL, а также статус, объём трафика, срок доступа и время последней активности клиента. Тот же URL открывает страницу подключения в браузере и отдаёт конфигурацию приложению. Сервис управления автоматически обслуживает страницы всех людей, в том числе добавленных в консоли.

## Список клиентов

```
meridian client list
```

Показывает каждого клиента со статусом, трафиком, сроком доступа и последней активностью.

## Личные заметки и метки

Для каждого человека, в том числе добавленного в консоли, можно сохранить личную заметку и одну метку:

```bash
meridian client set sample --note "Временное приглашение" --tag TRIAL_7
meridian client show sample
meridian client list --tag TRIAL_7
meridian client set sample --note "" --tag none
```

Заметка — обычный текст длиной до 500 символов с переносами строк. Метка содержит 1–16 заглавных букв A–Z, цифр или подчёркиваний. Пустая заметка и `--tag none` очищают поля; неуказанные параметры сохраняют значения. В `client list` есть столбец меток, а `--tag none` находит людей без метки.

Те же поля можно редактировать на странице человека в консоли. API принимает `PATCH /api/users` с полями `username`, `note` и `tag` либо `PATCH /api/users/NAME` без `username`. Чтение и изменение доступны с правами `people` или `admin`; более низкие права возвращают пустые строки. Поля хранятся в сервисе управления и зашифрованных снимках вместе с данными человека. Они не попадают в подписки, страницы подключения, события и журналы. Применение конфигурации сохраняет правки оператора. Миграция переносит описания Remnawave и допустимые метки, сообщая об обрезке описаний до 500 символов и пропуске недопустимых меток.

## Лимит трафика и срок доступа

Выделите клиенту трафик на месяц и задайте дату окончания доступа:

```
meridian client set alice --limit 50GB --reset month --expires 2026-12-31
```

Те же флаги работают и при добавлении (`meridian client add alice --limit 50GB --reset month`). Потом меняется только то, что вы передаёте:

```
meridian client set alice --expires 2027-06-30
meridian client set alice --limit none --expires never
```

- `--limit` принимает размер вроде `500MB`, `50GB` или `1.5TB` (1 GB — это 1024³ байт, как считает сервис управления); `none` снимает лимит.
- `--reset` обнуляет использованный трафик каждый день (`day`), неделю (`week`) или месяц (`month`); с `never` счёт идёт без сброса.
- `--expires` принимает дату (доступ заканчивается в конце этого дня по UTC), время ISO вроде `2026-12-31T18:00:00+03:00` или `never`.

Клиент, исчерпавший лимит, получает статус `limited`, а клиент с истёкшим сроком — `expired`. Они не могут подключиться до следующего сброса или пока вы не поднимете лимит или не перенесёте дату. Чтобы вернуть трафик сразу:

```
meridian client reset-traffic alice
```

`client show` показывает, как обстоят дела:

```
  Статус       ● active
  Трафик       12.4 GB / 50 GB (сброс каждый месяц)
  Срок доступа 2026-12-31
```

`apply`, повторные развёртывания и изменения серверов лимиты и срок доступа не меняют.

## Лимит устройств

Лимиты устройств **по умолчанию выключены**: Meridian не читает и не сохраняет сведения об устройствах. Если нужен лимит, выберите `private` или `full` в **Settings → Privacy**. Уровень приватности и лимит каждого человека хранятся в сервисе управления; `apply` их не меняет.

- **Private:** Устройства каждого человека считаются по нечитаемому отпечатку. Meridian не хранит названия устройств, системы и приложения. Тот, кто захватит сервер управления, сможет лишь проверить, использовалось ли устройство, которое уже есть у него.
- **Full:** Meridian хранит ID, систему, модель и приложение каждого устройства, а также время последнего обновления подписки. Тот, кто захватит сервер управления, узнает, какими устройствами пользуется каждый человек. Адреса никогда не сохраняются.

В режиме private также не сохраняется время первого и последнего обновления. Отпечатки входят в зашифрованные снимки, но их общий ключ остаётся на сервере управления. После восстановления регистрации private удаляются: устройства зарегистрируются при следующем обновлении подписки. При переходе с full на private ID заменяются отпечатками, а сведения удаляются; при выключении удаляются все регистрации.

Задайте лимит от 1 до 100 при добавлении или позже. `default` использует общий лимит (изначально 3):

```
meridian client add alice --devices 2
meridian client set alice --devices 4
meridian client set alice --devices default
```

Посмотрите или удалите регистрации:

```
meridian client devices alice
meridian client devices alice --json
meridian client devices alice --remove ID
meridian client devices alice --clear
```

В private показывается только «N из M устройств»; JSON также возвращает ID отпечатков для удаления одного устройства. В full перечисляются ID, системы и версии, модели, приложения и время первого и последнего обновления. В карточке человека в консоли — то же количество или список, кнопка очистки и, в full, кнопки удаления отдельных устройств.

Известное устройство сохраняет доступ после снижения лимита. Новому устройству сверх лимита отдаётся заглушка подписки с просьбой удалить устройство или попросить повысить лимит. Для подсчёта нужен корректный заголовок `x-hwid` от приложения; браузеры, запросы страницы подключения и приложения без поддерживаемого HWID всегда обслуживаются и не считаются. Удаление регистрации освобождает место; устройство может зарегистрироваться при следующем обновлении. Лимит действует на обновления подписки и не отзывает уже импортированную конфигурацию. `client reissue` заменяет ключи и очищает все регистрации, сохраняя лимит. Регистрации устройств Remnawave никогда не импортируются через `migrate`.

## Приостановка и возобновление клиента

```
meridian client disable alice
meridian client enable alice
```

`disable` отключает клиента немедленно; `enable` возвращает доступ по тем же ссылкам.

Отключение действует до вызова `client enable`: `apply`, повторные развёртывания и изменения серверов его не сбрасывают.

## Замена утёкшей ссылки

Если ссылка или страница подключения клиента попала не к тому человеку, замените её:

```
meridian client reissue alice
```

Сервис управления выдаёт клиенту новый идентификатор подписки и новые ключи. Старый URL подписки и старая страница подключения отвечают 404, а серверы отклоняют старые ключи. Meridian выводит новый URL подписки, который одновременно открывает новую страницу подключения. Новую ссылку импортируют один раз: приложения не могут обновить подписку, URL которой больше не существует. Статус, лимит и расход трафика, срок действия и лимит устройств сохраняются. Регистрации устройств очищаются.

С `--json` передайте `--yes`. Новые ссылки появляются только в выводе этой команды.

## Удаление клиента

`meridian client remove NAME` удаляет клиента окончательно: его ссылки перестанут работать и его страница подключения перестанет открываться. Всегда остаётся минимум один клиент.

Открытые сеансы VLESS могут продолжаться после отзыва ключей. **`--cut-off`** в `client remove` или `client reissue` ждёт, пока каждый затронутый сервер применит ревизию без старых ключей, затем сбрасывает нужные входы. Все их сеансы завершаются, включая сеансы других пользователей; они ненадолго переподключатся. Если API входа не сработает, перезапустится Xray и завершатся все его сеансы на этом сервере. Флаг включается явно и рекомендуется при утечке ссылки. JSON содержит результат каждого сервера в `data.cut_off`: `done`, `core_restart`, `failed` или `timed_out`. Ожидание длится до пяти минут; сбой завершает команду с кодом `4`, тайм-аут — `3`. Консоль предлагает тот же выбор при удалении человека, добавленного через неё.

## Ссылки подписки

URL подписки выглядят как `https://198.51.100.10/<page-path>/sub/<id>`. Они находятся под путём страницы подключения; консоль сервиса управления остаётся на отдельном секретном пути, который общие ссылки никогда не раскрывают.

Каждая подписка просит приложения обновлять её каждые 6 часов (заголовок `profile-update-interval`, которому следуют такие приложения, как Happ и Clash Verge), поэтому когда вы добавляете выход или промежуточный сервер, клиенты подхватывают его в течение нескольких часов без новой ссылки. Приложения, игнорирующие заголовок, обновляют подписку по собственному расписанию; ручное обновление в приложении подхватывает изменения сразу.

Кнопка поддержки в приложении открывает страницу подключения этого человека с подсказками «Не подключается?».

### Проверенные приложения и движки

Один URL подписки отдаёт каждому приложению тот формат, который оно читает; Stash получает профиль на своём диалекте. Каждое изменение Meridian проверяет каждый формат, который отдаёт сервис управления, движком, на котором построены эти приложения:

| Формат | Приложения | Проверенный движок | Что проверяет лаборатория |
|--------|------|---------------|---------------------|
| Xray JSON | Happ, v2rayNG, v2rayN, Streisand, V2Box | Xray 26.7.28 | Трафик проходит через каждую точку входа и через автоматическое переключение при сбое; неверный ключ отклоняется |
| Mihomo | FlClashX, Clash Mi | Mihomo 1.19.32 | `mihomo -t` загружает профиль, его правила и резервную группу |
| sing-box | sing-box (SFA, SFI), Karing | sing-box 1.14.3 | `sing-box check` загружает профиль, а его автоматическая группа является маршрутом по умолчанию |
| Base64 ссылки | другие приложения Xray/V2Ray (v2RayTun, Shadowrocket) | — | Каждая ссылка разбирается и указывает те же серверы и ключ, что и другие форматы |

Приложения сами выпускают обновления движков, поэтому приложение может использовать чуть более старый или более новый движок, чем проверенный.

### BitTorrent в приложениях на Xray

Подписки Xray JSON (Happ и другие приложения на Xray) отправляют распознанные BitTorrent-соединения с пирами напрямую с устройства: торренты идут через собственное подключение человека, а не через адрес выхода. Это работает не всегда: зашифрованные соединения с пирами и UDP (DHT/uTP) могут по-прежнему идти через VPN. Подписки Mihomo, sing-box и Base64 этого правила не получают.

## Где хранятся данные клиентов

Учётные записи клиентов (ключи, статус, лимиты, трафик) хранятся в базе данных сервиса управления на сервере управления. Список клиентов, которыми управляет Meridian, входит в вашу топологию в `~/.config/meridian/cluster.yml`. Команды `client` обращаются к API сервиса управления, а сам сервис отдаёт страницы подключения прямо из своей базы данных. После каждого изменения ваш компьютер сохраняет зашифрованный снимок этой базы (см. [Резервные копии](/ru/deploy/#резервные-копии)).

## Веб-консоль

У сервиса управления есть веб-консоль, где можно управлять людьми из браузера, в том числе с телефона. `meridian panel` выводит её адрес, а в первый раз — ещё и одноразовую ссылку настройки, где вы выбираете пароль владельца. Позже в **Settings** можно добавить код входа из приложения-аутентификатора.

| Меняется в консоли | Только для чтения (меняется через `meridian`) |
|---|---|
| **People**: добавить, поделиться ссылкой и QR-кодом, включить или отключить, задать срок действия, лимит трафика и период сброса, сбросить трафик, выпустить новую ссылку, удалить | **Servers**: каждый выход и шлюз, в сети ли его агент и применена ли текущая конфигурация, его версия и трафик |
| **Tokens**: создать и отозвать API-токены | **Revisions**: каждое изменение, применённое с вашего компьютера, с его планом |
| Ваш пароль и код входа | Название подписки, которое видят приложения |

Изменения в консоли и в CLI — одни и те же изменения: `meridian client list` показывает и людей, добавленных в консоли, а применения никогда не отменяют статус, лимит или срок действия, заданные там или там. Люди, добавленные через `meridian client add`, остаются за CLI: консоль может менять их лимиты и статус, но вместо удаления или выпуска новой ссылки показывает команду `meridian client`, потому что эти люди принадлежат проверенной топологии. У каждого человека, в том числе добавленного в консоли, есть страница подключения по URL его подписки.

Консоль не хранит SSH-ключей, поэтому украденный сеанс не может изменить ваши серверы. Каждый вход истекает после 30 минут бездействия и не позже чем через 12 часов, а создание токена снова спрашивает пароль.

### API-токены

Скрипты и сторонние боты, например Telegram-бот, который сообщает людям, сколько трафика у них осталось, обращаются к API сервиса управления. Дайте каждому собственный токен:

1. Откройте консоль (`meridian panel` выводит адрес), перейдите в **Tokens** и выберите **Create token**.
2. Назовите токен по имени бота и выберите **Read**. Консоль показывает токен один раз; сохраните его вместе с секретами бота.
3. Укажите боту адрес консоли и отправляйте токен как `Authorization: Bearer <token>`. Пути API идут после этого адреса, например `https://198.51.100.10/<secret-path>/api/users/alice`. Адрес содержит секретный путь, поэтому храните его так же бережно, как токен.

#### Контракт OpenAPI

Получите **`GET /api/openapi.json`** по адресу консоли, передав тот же заголовок `Authorization: Bearer <token>`. Документ доступен любому действующему API-токену, включая `people`; истёкший или отозванный токен получает `401`. Это англоязычный контракт **OpenAPI 3.1** с версией установленного сервиса, схемами запросов и ответов, ошибками и нужными правами. Копия в репозитории находится в `contracts/meridian/v1/admin/openapi.json`; для неё задайте клиенту базовый URL консоли вместе с секретным путём.

`x-meridian-scopes` перечисляет альтернативные права доступа. `x-meridian-credentials: true` у операции и её успешного ответа означает, что ответ может содержать секретные данные: храните его приватно и не записывайте в журнал. Данные подключения людей доступны только с правом `people` или `admin`; токены чтения получают пустые UUID и токены подписки. Ответ с точкой подключения может содержать пароль обфускации транспорта, а зашифрованная резервная копия тоже содержит секреты. Регистрация и протокол агентов, подписки, страницы подключения и сеансы консоли имеют отдельные интерфейсы и в документ не входят.

Таблицы операций ниже проверяются по контракту. Токен с правом чтения видит:

| Endpoint | Возвращает |
|---|---|
| `GET /api/users/{username}` | Статус одного человека, расход и лимит трафика, период сброса и срок действия |
| `GET /api/users` | Всех людей |
| `GET /api/traffic` | Итоги трафика по каждому человеку |
| `GET /api/health` | Версию сервиса |
| `GET /api/openapi.json` | Контракт административного API |
| `GET /api/events` | Ограниченную страницу локальных событий |
| `GET /api/attention` | Вычисляемые предупреждения об учётных записях, узлах и серверах |

Токены с правом чтения не видят ключей и идентификаторов подписки. Для бота, который управляет учётными записями и выдаёт данные подключения, выберите **Люди**. Создание такого токена требует того же подтверждения пароля, что и создание любого другого токена в консоли.

| Право | Доступ |
|---|---|
| `read` | Просмотр серверов и людей без данных подключения |
| `propose` | Право чтения и предложение ревизий |
| `approve` | Право предложения и одобрение ревизий других участников |
| `people` | Чтение и управление людьми, включая UUID и токены подписки |
| `admin` | Оба набора прав, включая изменение топологии, регистрацию агентов, токены и резервные копии; выдаётся через API-доступ владельца CLI |

`people` не входит в цепочку read → propose → approve. Такой токен обращается к `/api/users` и читает `/api/openapi.json`: у него нет доступа к узлам, точкам входа, блокировке применения, ревизиям, резервным копиям, регистрации агентов, API-токенам, приватности и настройкам. Admin включает право people.

| Endpoint для людей | Действие |
|---|---|
| `POST /api/users` | Создать человека с `username`, `status`, `expire_at`, `traffic_limit_bytes`, `traffic_limit_strategy` и `device_limit` в одной транзакции |
| `PATCH /api/users/{username}` | Изменить статус, срок действия, лимит и период сброса трафика или число устройств; пропущенные поля сохраняются |
| `POST /api/users/{username}/reset-traffic` | Сбросить использованный трафик |
| `POST /api/users/{username}/extend` | Отправить `{"days": N}` (1–3650), чтобы добавить дни к текущему сроку или к настоящему времени, если срок прошёл или не задан |
| `POST /api/users/{username}/reissue` | Заменить данные подключения и очистить регистрации устройств |
| `DELETE /api/users/{username}` | Удалить человека |
| `GET /api/users/{username}/devices` | Прочитать регистрации в пределах выбранного владельцем уровня приватности |
| `DELETE /api/users/{username}/devices` | Очистить все регистрации |
| `DELETE /api/users/{username}/devices/{device_key}` | Удалить одну регистрацию |

Токен people не может удалить человека, указанного в файле серверов, или перевыпустить его данные подключения: API возвращает `409 declared_user` и нужную команду CLI. Это правило действует и во время одобренного или неудачного применения, где человек ещё указан. Неодобренное предложение никого не закрепляет. Статус, лимиты, срок действия и число устройств менять можно.

Перевыпуск и удаление принимают необязательное тело `{"cut_off": true}`, чтобы завершить открытые сеансы после применения смены данных подключения. Для этого также нужно право `admin`, указанное в `x-meridian-conditional-scopes`; другие люди на затронутых входящих подключениях могут ненадолго потерять связь. Без этого выбора ответ содержит обычную учётную запись или подтверждение удаления, а с ним — поставленные в очередь команды.

Выберите **7, 30 или 90 дней** либо **Без срока действия**; новый токен в консоли по умолчанию действует 90 дней. Список показывает срок действия и отмечает истёкшие токены. И истечение срока, и отзыв отклоняют следующий запрос одинаковым ответом `401 unauthenticated`. У существующих токенов срок действия остаётся неограниченным. Храните токен people как пароль: он даёт доступ к данным подключения людей.

`POST /api/tokens` принимает `expires_in_days` от 1 до 3650 или `null` для неограниченного срока; пропущенное поле тоже означает отсутствие срока. Вместо этого можно передать будущий момент UTC в `expires_at`; выберите одно поле срока действия. `TokenRecord.expires_at` возвращается всегда, в том числе со значением `null`. Управление токенами требует API-права admin или сеанса владельца консоли; создание в консоли также требует подтверждения пароля. Токен people не может создавать токены. Схемы `token-create`, `token-record`, `token-issued` и `token-list` доступны через `meridian api schema NAME`.

## Контакт владельца на страницах подключения

`meridian fleet contact` показывает контакт из проверенного описания ваших серверов. Сначала просмотрите публичные указания и ссылку для связи:

```bash
meridian fleet contact --text "Напишите, если нужна помощь" --link mailto:help@example.com --dry-run --json
meridian fleet contact --text "Напишите, если нужна помощь" --link mailto:help@example.com --yes
meridian fleet contact --text "" --link none --yes
```

Указания — одна строка обычного текста длиной до 120 символов. Ссылки используют только `https:`, `tg:` или `mailto:`; Meridian проверяет их и приводит к каноническому виду. Поля независимы: неуказанные параметры сохраняют значения, `--text ""` удаляет указания, а `--link none` удаляет ссылку. Изменение с JSON требует `--yes`; пробный запуск и отказ от подтверждения сохраняют настройки. Экспорт и импорт переносят `delivery.owner_contact.text` и `delivery.owner_contact.link`. Настройки в консоли показывают контакт и команду для его изменения.

Раздел помощи на странице подключения и страница поддержки показывают публичные указания и ссылку **Связаться с владельцем** на всех четырёх языках интерфейса. Ссылка открывается только после нажатия; все ресурсы страниц локальные. Если контакт задан, страница поддержки оставляет его на экране и предлагает **Открыть страницу подключения**. Приложения получают ссылку в `support-url`; без неё заголовок сохраняет адрес локальной страницы поддержки. Личная ссылка подключения не меняется.

Подписки с приостановленным доступом могут добавить указания к сообщениям о состоянии, если каждое сообщение остаётся в пределах 100 символов. Более длинные указания не меняют эти сообщения и остаются видны на страницах.
