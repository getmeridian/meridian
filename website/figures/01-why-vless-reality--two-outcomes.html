VLESS + Reality

One Client Hello, two outcomes

On the wire, a real client and a censor's probe send the same thing. Only the server can tell them apart, and it answers the probe with a real website.

What the censor sees, either way
TCP 443 TLS 1.3 Client Hello SNI = camouflage target Chrome fingerprint (uTLS) random-looking session ID
Client with the exit's public key

Token in the session ID checks out

  1. Server finishes the TLS handshake itself
  2. Temporary certificate, verified with the shared x25519 secret
  3. VLESS runs inside the TLS session
→ Encrypted tunnel to the open internet
Prober, scanner, or wrong key

No valid token

  1. Server relays the whole connection to the real target site
  2. Prober completes a handshake with that site
  3. It receives the site's genuine CA-signed certificate
→ An ordinary website. Nothing to block on.
