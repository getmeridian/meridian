# reconciler — Declarative plan / apply engine

## Design decisions

- **Checkpointed apply** — `resource_executor.py` re-observes every immutable compiler action, persists each transition, and cuts over a generation only after all dependencies and postconditions succeed.
- **Service bootstrap is a driver** — `control_service_driver.py` installs `ctld` through `setup/control_service.py`; its attestation hashes the payload, target, package identity, and render contract, so a CLI upgrade or contract bump reinstalls and nothing else does.
- **Rollback-safe server artifacts** — Realm services and nginx files use hashed logical IDs; a failed reload restores the previous files before the action fails.
- **Neutral host names** — `server_render.py` names Realm units `netfwd-<token>`, UFW comments `fw-<token>`, and baseline attestations under `/var/lib/host-baseline/`.
- **One progress stream** — `execute_resource_plan(reporter=, operation=)` emits `plan.action.started` then exactly one completed/failed/skipped per action, and `SetupRuntime` shares it with provisioner steps.
- **Cooperative cancellation** — the executor polls between actions, before an unknown-outcome retry, and before retirement; the generation stays pending so re-running the plan resumes from checkpoints.
- **Fenced applies** — `fence.py` decides and `state_fence.py` stores the control server's `fence.json` (fleet ID, committed generation and plan hash, 30-minute lease) by compare-and-swap and holds it for the whole apply. A copy behind refuses, one ahead heals a lost commit, and only a fresh copy replaces a foreign fleet's fence; a swap that lost its connection re-reads before swapping again. A control-service fleet keeps it in the service (`service_fence.py`, `/api/fence`) once the service answers, and each apply there proposes, approves, and records a revision; see that module for bootstrap and migration.
- **Stalled connections retry read-only work** — `stall_retry.py` re-runs observations and fence reads/swaps on retryable system errors after 2/5/10/20s pauses, reported as `warning` events with `code: connection_stalled`; one outage that outlasts it ends retries for the run.
- **Graph-owned preparation** — one attested baseline prepares packages, hardening, SSH-safe UFW, and optional Docker; only compiled rules open public ports.
- **Meridian drivers (#95)** — `meridian_drivers.py` installs `netagent` over SSH with the contract's `AgentBootstrap` (0600: a single-use enrollment token and `ca_sha256` from the admin API, `tls_pin_sha256` null because 443 serves a Let's Encrypt IP certificate) and PUTs `agent_spec.py` node specs, endpoints, users, and settings; the agent observes in place only when the unit's running image has this build's hash, the bootstrap identity matches, and a hello is recent; a healthy agent of another build is upgraded in place (`agent_upgrade.py`: stage, `netagent check`, rename, restart, roll back unless the new build reports), and only a missing, foreign, or dead one is enrolled again. A workload converges only once its agent reports the current revision applied. Reality keys come from `LocalRealityKeyFactory`, not a panel. A gateway's edges dial each exit bridge with `bridge_client_uuid()` of that exit's keys, which the exit's spec renders as the bridge's only client; bridges are never managed inbounds, so no user reaches one. WARP (an apt package, daemon, and registration, outside the agent's resource kinds) installs over SSH with the agent through `server_support.ensure_warp()`.

## What's done well

- **Unknown outcomes are fail-closed** — a timed-out mutation stays `unknown` until observed; only a successful non-converged observation allows a retry, with the same idempotency key.
- **Retirement after convergence** — `retirement.py` removes vanished bindings, committed ones and what an uncommitted apply installed (newer than the active generation), dependents-first (`RETIREMENT_ORDER`) only after the whole plan succeeds; a failed rank stops later ranks and leaves the generation uncommitted. `validate_resource_plan_transition` refuses only teardown-owned kinds.
- **Forget-only kinds are explicit** — `FORGET_ONLY` names kinds whose state lives in their Profile, is read-only, or must never be reverted; every other retirable kind needs a driver `retire()` or retirement fails closed.
- **Reviewed render contract** — bump the `render_contract.py` manifest whenever deployed bytes or commands change.

## Pitfalls

- **An unseen but installed agent gets its backoff first** — after a control-service outage a healthy agent reads not-live until it retries (≤ 60 s); `AgentRuntimeDriver.apply` waits for it before re-enrolling, which once re-keyed every agent on the first apply after a ctld restart.
- **A new agent build is an upgrade, never an enrollment** — a binary hash change used to mint a token and re-key the node; hash the running image (`/proc/<MainPID>/exe`), not the file, so a swap whose restart was lost still reads as the old build, and keep that image as the rollback copy (the file is already the new build). Any failure after the swap rolls back, not only a silent timeout.
- **Raise `UnknownResourceOutcome` for an uncertain mutation** (a timeout or SSH exit 255) — never catch it as an ordinary failure or retry it through `StallRetry`; the executor observes before any retry. Only transport loss marks evidence retryable.
- **Unavailable evidence is not drift** — SSH/tool/panel failures stop reconciliation; only completed inspections prove absence, and read-only observation never allocates workload secrets. Pass each SSH read through `require_available_evidence()`: a lost `systemctl is-active` once read as a dead agent and re-keyed a healthy node.
- **Access users are partly operator-owned** — manage only username and squads (the control service's user driver only creates); status, description, limits, expiry, and quotas are the operator's (rewriting them undid `client disable`).
- **Server inbounds sniff route-only** — domain routing sees names only through sniffing; keep `routeOnly` so destinations are never rewritten.
- **Always render Reality `minClientVer`** — Xray 26.7.11+ otherwise rejects Mihomo/sing-box (they announce 1.8.x), and Meridian's own Xray-based `test` never notices.
- **One TLS output path per Host, one stream owner per listener** — hostname-derived certificate directories; the V4 port-443 artifact carries the panel/no-SNI route and retires `stream.d/meridian.conf` with rollback.
- **Normalize asynchronous observations** — compare UFW rules as `shlex` tokens and read Realm's version before feature suffixes.
- **A failed postcondition names its predicate** — drivers (nginx, Realm, baseline, certificates) put plain `mismatches` on the observation (never file contents: artifacts carry secret paths) and the executor appends `observation_shortfall()`; a bare "did not satisfy the reviewed hash" left a Debian 12 tester nothing to act on. After an nginx reload, wait for the listener before observing: nginx opens new ports ~90 ms after `systemctl reload` returns, and `deploy local` (no SSH round trips) observed inside that window.
- **The node's architecture picks both builds** — `MeridianDriverContext.architecture()` reads `uname -m` once per apply, and the agent build (`control_artifacts.AGENT_TARGETS`) and the Xray `binary_pin` (`agent_spec.XRAY_LINUX_ASSETS`) follow it; a hard-coded `Xray-linux-64.zip` would hand an ARM exit a core that never starts.
- **Only a step-boundary `OperationCancelledError` is `cancelled`** — timeouts and killed processes stay `unknown`.
- **Attest server artifacts against their own inputs** (target, pins, renderer contract) — hashing the whole deployment re-runs every server on any fleet edit.
- **Delete, never mark inactive** — give a kind an idempotent driver `retire()` (404 = done) before adding it to `RETIREMENT_ORDER`; server-side retirement needs the binding's recorded `server_ref`. The one exception is `forget_server()`, on the operator's word (`--forget-unreachable`), for a removed server whose SSH port doesn't answer; service-side kinds still retire.
- **Unbound dependencies are pending, not lost evidence** — a new generation binds identities as it applies, so raise `UnboundDependencyError` for a missing dependency identity; `plan` shows those dependents as `recheck` (exit 2), and every other observation failure stays unavailable (exit 3).
- **Commit forgets superseded bindings** — keep the newest binding per (logical ID, remote ID) pair (what `was_managed` matches) plus active and current-generation ones; keeping every generation's copy grew `cluster.yml` by tens of KB per apply.
- **Bindings are per generation** — new generations find resources by name.
- **Certificates retire through acme.sh's record** — match `Le_RealFullChainPath`, not the hostname; skip while the control service or an nginx route still uses the file (missing the service once deleted a control server's own IP certificate when its exit left); drop the ACME listener with the last one.
- **An agent retires with its core** — stop and delete `netagent` and `netcore` with their config, keys, and state, and verify both stopped; removing only the agent left a retired exit's Xray running. A plan that still runs an agent on that server only forgets the old binding; `agent_runtime` is `SERVER_PLACED`, since re-enrolling a moved exit revokes the old agent but leaves its core serving.
- **Renames migrate, never orphan** — a surviving pre-rename unit or `meridian-v4-*` UFW comment is drift; stop the old unit before the new one binds, and re-add rules after deleting the old comment.
