# control/ui — The owner's web console (M5, #95)

## Design decisions
- **Served by the service, under the secret path** — `ui_routes.py` serves `index.html` at `/` and these files at `/ui/<name>`; the API lives in the same process, so there is no CORS, no build step, and no outside request (system fonts, a local icon, QR codes are SVG data URIs from `segno`).
- **Vanilla JS on one namespace** — `boot.js` sets theme and direction before paint; `core.js` owns `M.h` (the only DOM builder), `M.api`, dialogs, and formatting; each screen file adds `M.screens.*`; `app.js` runs the state machine (setup link → no owner → sign in → shell).
- **Owner sign-in** — one owner signs in at the secret path's root: a scrypt password (`passwords.py`) and an optional RFC 6238 code, offered after setup and switched on or off after re-entering both. `owner.py` keeps sessions as SHA-256 only (30 min idle, 12 h absolute, ten at most) and mints single-use 15-minute setup links, which only the root token asks for (`meridian panel`). Read polls carrying `X-Meridian-Passive` authenticate without touching owner idle activity, including `auth/state`; every write ignores the passive header and still re-checks session liveness in its transaction.
- **An owner session is the admin caller `WEB_OWNER` on `server.OWNER_ROUTES` only** — the routes the screens call (people, tokens, settings and revision reads, the fleet and share views); every other route (node, endpoint, and fence writes, revisions, enrollment, user import, backups) refuses it outright. A token it mints stays below `admin` (which would reach every other route) and needs a sign-in from the last 5 minutes, held in the insert's transaction. Its only direct command is `restart_unit` for a held managed resource; cut-off resets are queued through the guarded person mutation, and all other command kinds remain API-token operations.
- **The console changes only what the service owns** — People (add, link and QR, enable/disable, expiry, limits and reset strategy, reset traffic, reissue, remove), API tokens (secret shown once, revoke), operator-owned privacy settings, and signed managed-unit restarts. Server topology, Revisions, and the fleet title stay read-only; topology screens print the `meridian` command. Server restart results sit alongside reachability, fresh runtime health, and pending convergence.
- **Topology-owned settings stay reviewed** — Settings shows the public owner instructions and canonical link with `meridian fleet contact`, and the service's `client_routing` (an omitted value is `ru-split`) with an explanation of the policy and `meridian fleet routing`; Servers composes read-only allowance and payment evidence and attention from service settings, adds cards for non-agent servers, and prints `meridian server set`. Owner sessions never write topology settings.
- **Settings edits delivery the service owns** — `delivery-settings.js` edits the fleet's subscription language (browser language or four explicit defaults) and the service notice: preview and save use the same admin API, confirmation shows the rendered literal text, and the optional expiry is entered locally and saved in UTC. `format-preview.js` adds only a Settings form; bounded User-Agent/Accept inputs and typed explanations remain in the current view, with text-node rendering and no storage or credential disclosure.
- **People the deployer declared stay the deployer's** — users in the last applied revision's intent (`ui_views.is_declared`, `declared` on each share view, `declared_users` on the fleet view). Removing one or issuing a new link shows `meridian client remove|reissue NAME`, and the service refuses both to an owner session or people token (`declared_user`); admin tokens stay allowed.
- **Every invitee gets a page** — share views use the subscription URL as the page URL for both declared and console-created people; the service renders it from its own state.
- **Person drafts live only in memory** — person and password drafts; changed forms guard routes, history traversal, sign-out, and their own dialog dismissal with Leave/Stay, while visible person reads refresh status and usage passively every 30 seconds. The access form tracks its language select in the same draft and PATCHes `UserRecord.language` (en/ru/fa/zh, or null for the fleet default) only when edited, so editing other fields preserves it.
- **Expiry uses the browser's clock** — person and add forms use native local date/time with the browser zone and exact UTC instant; core-computed +1/+3 calendar-month previews only fill a draft, and No expiry PATCHes null when saved.
- **Individual connections** — the closed disclosure uses canonical subscription order and local QR codes; explicit format URLs and entries share the subscription link's credential permissions.
- **Tokens** — new console tokens last 90 days by default: Tokens offers 7, 30, 90 days or never, always sends the choice through the existing owner step-up, and shows expiry or an expired state alongside revocation metadata. After the same step-up it can mint the separate people capability, which manages accounts and credentials with the same declared-person remove/reissue guard as an owner session.
- **Same locale approach as the PWA** — `locales/{en,ru,fa,zh}.json`, English fallback, `fa` sets `dir="rtl"`; numbers and sizes are bidi-isolated.
- **Privacy and history** — Settings discloses every level before confirmation and PUT; `M.api` handles owner step-up. Usage charts and icons use SVG through `M.h`, with UTC day labels and an accessible totals table.
- **Device controls** — `devices.js` owns the person card: counts/clear in private, metadata/remove in full, no device data in off. Cap edits PATCH only `device_limit`; blank uses the fleet default. Confirmation explains that removed registrations can return; global privacy choices stay in Settings.
- **Passkeys are a seam** — `PasskeyState` reports `no_domain` on a bare IP and `not_built` otherwise; py_webauthn would add pyOpenSSL, pyasn1, and cbor2 to every CLI install, and attestation is never parsed by hand.

## What's done well
- **CSP with no exceptions for script** — `default-src 'none'`, `script-src 'self'`, `frame-ancestors 'none'`, `Referrer-Policy: no-referrer` on every console response; `test_control_ui_assets.py` refuses inline script, style, handlers, HTML sinks, outside URLs, and locale drift.
- **Every mutating request is same-origin twice** — `SameSite=Strict` plus the `X-Meridian-Request: 1` header `M.api` adds (and a matching `Origin`/`Sec-Fetch-Site` when sent).
- **Assets revalidate by ETag** (content hash, `no-cache`); anything holding a secret is `no-store`.
- QR export adds person/fleet captions with text nodes, rasterizes only the local SVG data URI, and confines generated blob download URLs to an image-only helper; the CSP and general URL guards stay unchanged.
- Server cards offer a signed Xray restart with a reconnect disclosure and per-node results, and repeated clicks before confirmation cannot queue duplicate restarts.
- Person removal offers an opt-in open-session cut-off with the affected nodes and the reconnect/core-restart disclosure; command results poll only same-origin reads, and declared people keep the CLI ownership guard.

## Pitfalls
- **The session cookie is scoped to `ServiceConfig.public_path`** (the bootstrap writes it); without one sign-in is refused (`ui_unconfigured`), since a `/` cookie would ride every subscription request.
- **An unconfigured service shows its notice before a setup link's form**, and `check_setup_link` refuses too; the form once took a password only for setup to answer `ui_unconfigured`.
- **Guess limits are per bucket, never per source** — every browser arrives as nginx's 127.0.0.1, so `login_limits.py` keeps in-memory buckets for sign-in, setup links, and each session's own re-checks, and no client address is kept; one shared source bucket let setup-link guesses lock sign-in and failed sign-ins lock a signed-in owner's re-check. Never trust a forwarded-address header.
- **Judge every guess inside `LoginLimiter.turn()`** (check, hash, count) — checking the lock before the slow hash let every concurrent request pass it before the first failure counted.
- **Write what a password check grants** (a session, `confirmed_at`, a new password) in the same transaction that re-reads the hash it was compared with and the session it acts for — the scrypt runs unlocked, so a reset or sign-out in between once still let the old password or an ended session through.
- **Re-check the password (and code) before anything that hands out a credential** (`OWNER_STEP_UP`) — `server.OWNER_ROUTES` is an allowlist a test derives from every `M.api` call; under the old denylist a borrowed browser once could seal a snapshot to its own key, and could still PUT node specs and approve revisions.
- **A setup link travels in the URL fragment** (never sent to nginx), and `auth.js` strips it with `history.replaceState` before anything else renders.
- **`M.busy` ignores a `cancelled` step-up** — closing the password check once showed a generic error.
- **The fleet title is the intent's** (`delivery.profile_title`, decided 2026-10-29) — Settings shows it with the CLI commands that change it, and owner sessions cannot `PUT /api/settings`; an editable title was put back by the next apply.
- **Treat page input as hostile** — decode the hash through `M.route()`'s guard (a bare `%` threw at boot, and retry reloaded the same hash) and read name maps with `M.has()` (a person named `toString` broke People).
- **Adding a person is one `POST /api/users` carrying expiry and limits** (`ControlService.create_user`, one transaction, 409 `user_exists`) — create-then-PATCH left an active, unlimited person whenever the PATCH never landed, and a retry only met `user_exists`.
- **Saving a person PATCHes only the fields edited** — the limit field shows bytes unrounded (`M.gbText`): a CLI quota of 4 MB rounded to "0" GB, so saving the expiry sent 0: unlimited. Metadata fills textareas with text nodes (a textarea `value` attribute does not populate its value) and validates 500 Unicode characters and the uppercase tag.
- **Person refresh never clobbers an edit** — preserve edited input nodes, focus, and selection; accept live reads only before a newer mutation result, and refresh device counts on their originating card. Capture the person and screen generation before a mutation, apply its returned record only there, name the person in feedback, and report effective expired/limited access after enabling.
- **Drafts save from their submitted baseline** — ignore disabled draft fields and keep the submitted baseline before locking a save; clear only successful saves or actually discarded forms, and a confirmed person deletion discards its obsolete drafts once.
- **Validate edited expiry instants as whole-second future UTC values before 2099** — a local date before 2099 can cross into the legacy no-expiry range; preserve untouched fractional timestamps and reject nonexistent local times in a DST gap.
- **Judge "declared" from the person's own share view**, never only the fleet list fetched at boot; a stale list must not offer removal or reissue of a person owned by the reviewed topology.
- **People keeps rendering and polling users when fleet metadata fails**, using cached names and declared markers; user-list failures still keep stale data with retry.
- **People and Servers poll only while visible** (30 s / 10 s), stop on navigation, keep stale data with retry and bounded backoff, and accept replies through `M.latestOnly`; passive GETs carry `X-Meridian-Passive` and every request has a body-inclusive deadline.
- **A screen that re-requests on every pick wraps its request in `M.latestOnly()`** and labels from the value it asked for — the revision diff once showed #2's reply under "1 to 3".
- **Command polling keeps successful sibling replies**, times out only a node's pending records, and stops terminal read errors with an unavailable result while preserving finished outcomes.
- **Server cards keep reachability, runtime health, and convergence separate**; resource metrics and health checks come only from fresh report evidence.
- **Render billing dates as isolated UTC calendar dates**, preserving the anchor and computed next date; a relay's null usage is not zero and must say not measured.
- **Notices** — clearing one sends no preview person, and unfinished text, expiry, or a missing preview account must never block the global clear action. Confirmations pass literal strings to `M.confirm`, which creates its own text node; passing a DOM node displays an object label instead of the reviewed message.
- **Token issuance is locked and may be uncertain** — lock dialog dismissal throughout issuance and reject duplicate submits; the secret lives only in its result step. A successful response without a secret is still uncertain: refresh the metadata list and explain that the secret cannot be recovered instead of closing an empty result.
- **Quotas use GiB/TiB with an explicit Unlimited choice** — validate at the field before any form submits, round decimal bytes like the CLI, and refuse new values above JavaScript's exact integer range.
- **Reject invalid numeric cap input before treating blank as default** — a browser's `badInput` must never clear an override.
- **Turning a privacy level off preserves its disabled numeric defaults**; invalid unfinished edits must never block lowering a level.
- **Dialogs fit phones** — constrain the scrolling body to dvh and safe areas, keep form actions sticky, and scroll focused fields clear of the sticky footer after layout (native focus scrolling treated a covered input as visible on a phone). Use unique title IDs for nested identity checks; icon-only actions need an aria-label and coarse-pointer controls need 44 px targets.
- **Locale catalogs load independently** — a selected-locale failure retains English, and a failed language switch keeps the previous catalog, language, and direction, switching to English only after its catalog loads. If both fail, startup waits on a local retry notice whose bootstrap labels match the catalogs.
- **Keep each script under 800 lines and every `M.t("…")` key in `en.json`**; the asset tests read literal keys only.
