# control — Meridian's own control service (`meridian serve`)

Owner sign-in and the console's screens: `ui/CLAUDE.md`. Subscription documents: `formats/CLAUDE.md`.

## Design decisions
- **Replaces Remnawave** — every fleet shape but client-IP forwarding (exits anywhere, relays, routing gateways as agent nodes, WARP, a control server without an exit), users, signed node documents, and every subscription format; the only backend since the flip (#95). Client-IP forwarding waits for its own review, so `--client-ips` is hidden and `migrate` drops it.
- **Service owns users, deployer owns topology (for now)** — the reconciler's Meridian drivers PUT node specs, endpoints, and users over the admin API; the service composes each node's whole document (`node_documents.py`: spec + one users resource per managed inbound, right after the `xray_config`), signs it, and serves it to the agent; `NodeStatus.in_sync` compares the applied (epoch, revision, hash) with the epoch as the agent reported it (relabelled with the service's, a cached pre-restore report read as in sync).
- **Stdlib HTTP on loopback** — `ThreadingHTTPServer` behind nginx's secret path; a thread per waiting long-poll is cheap at Meridian's fleet sizes; one request per connection, a 60 s socket read deadline, and only a digit Content-Length (`read(-1)` reads to EOF, past the body limit). nginx strips the secret path, so routes are `/api`, `/agent/v1`, `/sub`.
- **Admin HTTP contract** — `route_catalog.py` declares every `/api` method, named path, scopes, body/query and response models, errors, credential marker, and publication decision; `route_types.py` compiles the same parameter schemas for dispatch, and `openapi.py` uses Pydantic validation/serialization schemas for OpenAPI 3.1.
- **HTTP front** — `route_table.py` owns ordered route matching and scope bindings, so the front binds its handler without importing the server back into routing; it delegates generic nginx error pages and bounded field validation messages to `http_errors.py`, and `subscription_routes.py` writes subscription responses through the shared public request interface while the server keeps routing and authentication.
- **One SQLite file, migrated forward** — `store.Store` shares one connection, lock, and change condition between `ControlService`, `NodeAuthority`, `TrafficLedger`, `TokenRegistry`, `RevisionLedger`, `BackupLedger`, `OwnerAuth`, `PrivacyLedger`, and `DeviceLedger`, each owning its tables (`users.py` turns rows into `UserRecord`s, `user_policy.py` holds expiry, reset periods, and enforcement); WAL mode, and the condition wakes polls on a new revision. `SCHEMA_VERSION` plus `_MIGRATIONS` (statements per version step) move it forward; a database from a newer Meridian is refused, never downgraded.
- **Scoped API tokens** — one revocable `/api` token per device or agent (`tokens.py`), scoped `read` < `propose` < `approve` < `admin`; each `/api` route in `server.ROUTES` names its scope. Whatever applying does (node/user/endpoint writes, a revision's result, the fence) is `WRITE` = `admin`. The config's admin token is the root `admin`: unlisted, rotated only by rewriting the config.
- **People capability** — `people` is separate from `read < propose < approve`, and `admin` covers both; `server.ROUTES` allows either read or people for user reads, only people/admin for user mutations, and no people access to fleet, settings, privacy, enrollment, tokens, or backups. Cut-off scope needs read and ending sessions needs admin, including a cut-off requested with a user mutation. People and admin reads include credentials; lower scopes see `uuid`/`sub_token` blank, since they connect as the user. `user_access.py` checks declared remove/reissue refusals in the write's transaction for people tokens and the owner session.
- **Token expiry is registry time** — schema step 12 adds nullable `api_tokens.expires_at`; old tokens remain indefinite. Issuance accepts a future UTC expiry or 1–3650 days, computed inside the insert transaction, and authentication refuses at the deadline with the same 401 as revocation, without touching last use. Historical step 4 keeps its original table definition so an older database adds expiry only once.
- **Revisions record every reviewed apply** — `revisions.py`: number, author (token ID and name; `root` for the config token), secret-free intent snapshot, plan and review hashes, `proposed` → `approved` → `applied`|`failed`. `propose` proposes, `approve` approves another's proposal; only an `admin` token approves its own (the deployer's one-person path).
- **The apply fence is one CAS row** — `GET/PUT /api/fence` stores what `reconciler/fence.py` decides (fleet, generation, plan hash, committed revision, lease) and replaces it only from the version read (409 otherwise), answering with what that swap wrote (a re-read after commit could hand back the next writer's version); the service never judges leases itself.
- **Fleet CA from the first start** — `NodeAuthority` (`enrollment.py`) creates an Ed25519 CA (`pki.py`; keys in the `secrets` table) and certifies the signing key with URI SAN `meridian-service://<fleet>`; `key_id` is that certificate's DER SHA-256. Documents signed under another certificate are signed again at start.
- **Enrollment and sessions follow the contract** — the admin API mints one single-use, 30-minute enrollment token per node; `enroll` trades it and a CSR for a 90-day certificate (SAN `meridian-agent://<fleet>/<node>`) and revokes the node's earlier certificates and sessions; `hello` checks chain, revocation, SAN, ±300 s, and nonce, then opens a one-hour session; `renew` re-checks revocation in its own transaction (a renewal racing an enrollment once revived a revoked node). Every token is stored only as SHA-256; the 443 handshake never asks for a client certificate. Version skew follows `core/version_skew.py`: a hello offering no protocol the service speaks gets `unsupported_protocol` (retry after 300 s, in the body and `Retry-After`) before the rest is parsed.
- **Signed commands** — `commands.py` and schema step 14 deliver oldest first, only session-negotiated kinds, with durable first-result acknowledgements, 64 unanswered per node, expiry, and seven-day finished retention; revision gates release only on applied reports. Session capabilities and queues are transient snapshot state, so a restore never replays a signed command under the old epoch or signing certificate.
- **Cut-offs ride the credential change** — `cutoff.py` captures affected inbounds before a credential change and queues revision-gated resets in that change's transaction; a full queue rolls back the credentials and documents together, and a closed console tab cannot strand the cut-off. A deployer user deletion requests its cut-off in the DELETE body, so no separate revision read or reset POST follows it.
- **Traffic counted exactly once** — `traffic.py` keeps each node's last seq and totals per counter epoch and adds only growth; a resent seq is acked uncounted. Epoch IDs are random, so a late report from an old or unseen epoch counts against its own baselines (it once retired the live epoch, which then never counted again); only the `KEPT_EPOCHS` newest arrivals keep baselines, older ones are retired (the newest `REMEMBERED_RETIRED_EPOCHS` stay remembered), and counters of a user ID the service never had are dropped, so a node cannot grow the database at will. `GET /api/traffic` joins totals to usernames; no client address is ever stored.
- **Durable node evidence** — step 13 adds accepted upload/download growth to `node_traffic_totals` in the user's accounting transaction; replay baselines can retire independently. Migration backfills only retained per-epoch counters and marks when complete accounting starts; first-use and last-node evidence are scalar receipt-time aggregates, and latest collection time selects each node's active count (never sessions or addresses). Node status exposes that total as `traffic_bytes`, with its activity window from the same row, and the CLI's `Node` carries it, so deployer adapters consume the public API rather than replay baselines.
- **Daily history is opt-in** — with `usage_history: daily`, `traffic.py` adds the same growth it counts to `traffic_daily`/`node_traffic_daily` on its UTC receipt day (nothing while off); the 30 s timer prunes days beyond `history_days`, today included. `operations_api.py` parses HTTP history day counts, with thin server delegations.
- **Operator-owned users** — the operator sets `active`/`disabled`, expiry, and limits over `PATCH /api/users`; enforcement (a 30 s timer, every change, and each stats report, whose periods advance before its growth counts, or the timer's reset folded post-midnight use into the offset) turns an active user `expired` or `limited` and back once a change, `reset-traffic`, or a new day/week/month (UTC, weeks from Monday) lifts it. Node documents carry only active users. Use is lifetime (the ledger's total plus `traffic_carried_bytes`) minus the offset the last reset recorded.
- **User import** — admin-only `POST /api/import/users` (`meridian migrate`) creates users with given credentials, status, limits, and usage, all or nothing: same credentials again change nothing, others refuse the batch (409), and `replace` overwrites existing users; a UUID is stored as given (Hysteria2 authenticates with the exact string), compared case-insensitively, and lowercased for VLESS documents (the contract refuses uppercase, which wedged every node); carried use is lifetime with an offset leaving the period's use, and a source reset before the current period becomes the import time, so enforcement never wipes it.
- **Person edits stay atomic** — `user_updates.py` owns the person-edit transaction (the service delegates with its clock, enforcement, composition, and event hooks, so later operator fields stay atomic without growing the service module); `user_lifecycle.py` owns fresh account inserts and duration extensions, computing max(now, expiry) plus whole days inside the write transaction, then recording the expiry change, enforcing, and composing before returning; disabled status and traffic cutoffs remain the operator's.
- **Read-only person helpers** — `person_expiry.py` serves owner, people, and admin callers a month preview (choosing a preset stores nothing; the person form saves the resulting UTC instant through its changed-field PATCH), and `person_connections.py` composes credentials from the canonical `/info` renderer under one state lock for `/api/users/{name}/connections`, admitting people/admin tokens and owner sessions, with no new stored data.
- **Private notes and tags** — schema step 15 adds `users.note` and `users.tag`; PATCH accepts the existing name path or a `username` body at `/api/users`, only people/admin reads retain them, applies preserve them, and snapshots carry them with user rows.
- **Languages** — schema step 17 adds nullable `users.language`; `languages.py` stores the explicit fleet default in snapshot-covered meta, where an unset default reads `auto` and stored explicit values are preserved, and `/api/language` reads with `read` and writes with `admin`. Personal connection and support HTML resolve overrides under the state lock, and old fragment support links navigate to personal HTML without a background bearer fetch.
- **Privacy is the operator's** — `privacy.py` keeps one settings row (device limits `off|private|full`, usage history `off|daily`, both off by default) and a full before/after audit (`privacy_changes`, newest 50 read, author from `TokenRegistry.actor`); applies never write it, and `PUT /api/privacy` is `WRITE` plus an owner step-up. A lowering, a shorter retention, and the audit row commit in one transaction: the writer asks `DeviceLedger.lower_level` to re-key full IDs into fingerprints or delete every device; identical settings add no row.
- **Device caps** — `devices.py`: off reads no header; private stores HMAC-SHA256 (secret `device_hmac_key`) of `x-hwid` with every metadata column and timestamp NULL; full stores the HWID, platform, OS version, model, user agent, and first/last fetch, never an address. A new device over the cap (`users.device_limit`, else the fleet default) gets the status placeholder and v2RayTun's `x-hwid-*` headers, decided in the fetch's transaction; known devices stay allowed above a lowered cap, inactive users take no new slot, and a raise from private to full learns each raw ID at its next fetch without taking a second slot.
- **Encrypted snapshots** — `snapshot.py`, `meridian.snapshot/v1`: a `meridian-snapshot/v1` line, the header as canonical one-line JSON (fleet ID, epoch, newest revision, recipients), then a standard age v1 file (pyrage: per-recipient X25519 + HKDF-SHA256 wrap of a random file key, ChaCha20-Poly1305 STREAM payload). age has no associated data, so the sealed ZIP repeats the header bytes in `header.json` and decryption refuses any mismatch; the plaintext header is for listing only. Recovery keys are plain age identities (`age -d -i` works). `backups.py` seals `GET /api/backup/snapshot` (admin, like every backup route) to each registered device key and the recovery key (only its public half is stored), from an online-backup copy that also carries the deployer's deposited `cluster.yml`/`servers.json` (an older generation never replaces a newer one). `restore.py` stages a snapshot's database for a new server: the next epoch (above `minimum_epoch` too), node certificates revoked, a new CA and signing key, every document signed again.
- **Blob mirror** — `blobs.py` keeps every `binary_pin` that lists `service` (the agent spec puts it after GitHub) in `<state>/blobs/<sha256>`: one background worker downloads it after a spec PUT, at start, and when an agent's miss finds it still absent (at most once a minute), verifying size and hash before an atomic rename; `blobs/{sha256}` streams it to a session whose own node's spec pins that hash (404 otherwise, like an unknown one). Nodes that cannot reach GitHub install from the service.
- **Connection pages at subscriptions** — a browser at `/sub/<token>` gets the PWA shell; apps keep their negotiated configs and `/info` stays JSON. `subscription_serving.py` reads accounts, endpoints, settings, and privacy under the store lock, registers app devices transactionally (`ControlService.subscription` delegates to it), and hands browser HTML to `connection_pages.py`, which reads live subscription data and settings for every person; `page_routes.py` serves content-versioned package assets at token-free `/sub/~pwa/` plus legacy UUID redirects (`~` is outside the token alphabet).
- **Service settings** — `service_settings.py` reads and persists delivery settings, and every setting is saved in one store transaction (the public service methods delegate). Saved branding and reviewed exit countries travel through `ServiceSettingsDriver`; the topology owns `client_routing` (old databases read `ru-split`) and the subscription refresh hours (1–168, default `SUBSCRIPTION_UPDATE_INTERVAL_HOURS` = 6, sent as the `profile-update-interval` header; old databases read six), which persist with the rest. Defaults are omitted from serialization and read back on old databases without a migration.
- **Owner contact** — persists in the page-settings meta row inside the delivery transaction; native `support-url` prefers its link, page URLs remain personal, and short text joins status remarks only when every format's 100-character names remain bounded.
- **Operator notice** — `notices.py` stores it in snapshot-covered meta; `delivery_routes.py` handles GET with `read` and PUT with `admin` (declared in `route_catalog.py`), PUT previews until `confirm=true`, applies preserve it, and `notice.changed` events carry the actor with no text.
- **Format preview** — `subscription_preview.py` backs read-scoped `POST /api/subscription/preview` with the live selector and capability filters; it reads one consistent view, accepts no HWID or device inputs, stores no request data, and bypasses device registration and backup mutation hooks.
- **API-disabled endpoints** — `ClientEndpoint.enabled` defaults true and omits that default from serialization; false keeps the API-managed endpoint for explanation while all live formats omit it, and a reviewed endpoint apply restores topology delivery.
- **Server allowances and payments** — schema step 16 keeps per-server period offsets over durable accepted upload/download totals; reviewed settings persist metadata and anchors together, UTC payment repeats are computed on read, and non-agent servers are not measured.
- **Derived attention** — `attention.py` reads users, liveness, and fresh runtime health under the store lock and delegates to `core/attention.py`; nothing is written. Read-scoped `/api/attention` (owner allowed) uses expiry 7 days, quota 80%, and unused age over 3 days by default, with bounded query thresholds; unseen nodes and degraded health also need attention.
- **Local events** — `events.py`, step 13: typed `core/fleet_events.py` facts for user, token, privacy, and node transitions, capped at 2,000 entries and 180 days. Mutation hooks append inside their write transaction; request actors are thread-local and enforcement is `system`. The 30 s timer debounces node liveness and apply failures, including a full live window before an unseen new node goes offline; facts and debounce state ride snapshots, and privacy facts point to the audit's exposed row ID. Command issue and terminal result facts share their mutation's transaction; retries add no duplicate result, and details carry only command ID, kind, status, and reset effect.

## What's done well
- The discovery route accepts read or people, covering every valid API token; optional user cut-offs read their extra admin requirement from the catalog, and handler body models must match the declared request model.
- A revision is signed only when the resources' hash (or the signing certificate) changes, so repeated applies never wake agents.
- Agent errors use the protocol's `AgentErrorResponse` with the status `AGENT_HTTP_SURFACE` maps (`errors.agent_error`); admin errors a plain `{"error": {...}}`.
- An API token's public ID (`mrd_<id>_<secret>`) finds its row, so the hash is compared once with `hmac.compare_digest`, against a dummy when no row matches.
- A refused CSR rolls back with its transaction, so a bad request never burns the enrollment token.
- A proposal whose intent has a secret-shaped key or value (`secret_paths()`, keys per `core.redaction`) is refused, never stored; so is one whose `access` block is malformed (the console reads `access.users` on every person screen, and a `null` there broke them all).

## Pitfalls
- **Classify every route** — keep enrollment/CA bootstrap and console-owner APIs internal with a reason; every agent, subscription, page, and console route also needs an explicit internal classification, while credential markers include conditionally visible people records, endpoint passwords, and encrypted snapshots.
- **Decode the path before routing** — `ControlClient` percent-encodes IDs, so `:` in endpoint IDs arrives as `%3A` and every endpoint PUT 404'd; node routes match only topology IDs (`_NODE`), or a grant stored `main:exit` before its response refused it and broke the fleet view.
- **Answer like nginx everywhere** — `HEAD` dispatches as `GET`, `send_error()` writes nginx's page (http.server's own named the backend), and any miss under `/sub/` gets the unknown-subscription answer; routes read before authentication (`/auth/*`, enroll, hello) take 64 KiB bodies, not the 4 MiB the APIs allow.
- **Never log requests or store where they came from** — paths carry the secret path and subscription tokens (`log_message` is silenced); a token keeps only a once-a-minute `last_used_at`.
- **nginx answers 502/503/504 for a stopped or hung service** — `ControlClient` raises those as retryable unreachable errors; as plain refusals, a stopped ctld failed the fence at once with "refused: HTTP 502". A write the backup hook counts as maybe-committed (a lost reply, any 5xx) raises `ControlServiceUncertain`, which Meridian drivers turn into `UnknownResourceOutcome`.
- **`serve` is a daemon** — the root callback skips the beta banner and the update check for it (it once printed the banner into journald and phoned out on every start).
- **`control/` never imports the deployer** (CLI, SSH, panel, provision, reconciler); architecture-tested.
- **`executescript()` commits on its own** — create tables with `Store.create()`, never inside `transaction()`.
- **A console check holds only inside the write's own transaction** — `Store.conditions()` re-runs it after `BEGIN IMMEDIATE` (session liveness via `OwnerAuth.while_live` on every owner request and `hold_live` in the `/ui/api/auth` writes, which authenticate themselves; declared people); judged before the body was read, a revoked tab still wrote, and a person mid-apply could be relinked. Declared counts every revision after the newest applied one, approved or failed (a merely proposed one declares no one, or a `propose` token locked the owner out): an apply creates its people before it records applied, and a failed one leaves them to the CLI's retry.
- **A revision's number is kept from the moment it is proposed** — an approval that landed with its reply lost was otherwise left `approved` forever (in flight in `fleet history`) once acquisition gave up.
- **Compare timestamps parsed, never as strings** — the contract allows fractional seconds, and `…:00.5Z` sorts before `…:00Z`.
- **Hash and sign the document as JSON values**, never re-serialized typed models (the agent verifies the bytes it received); verify a `NodeProof` over the hello dict as received, too.
- **Record a hello nonce only after the proof verifies**, and keep it until `issued_at` + 300 s + margin, or a captured hello replays.
- **A poll answers before its session expires**, so the agent's next request is a fresh `hello` rather than a 401.
- **Agent polls refresh reachability only** — judge runtime health and convergence from a report younger than the live window, and keep stale reports as unavailable evidence; attention shares `NodeStatus` runtime freshness and degradation with fleet views, so stale reports cannot supply current health or apply failures, and failing checks count even under a healthy summary.
- **A cut-off must wait for the credential-removal revision to be reported applied** — resetting an inbound against the previous composition can restore the revoked credentials.
- **Command results can outlive service expiry** — expiry stops redelivery, but the first agent result can replace an expired row with no result; record that late outcome and its event atomically and never overwrite an acknowledged result. Deleting a node expires its waiting and pending commands in the same transaction, so a replacement with the same logical ID never inherits a queued restart.
- **Traffic baselines and revisions outlive node deletion** (`retired_revision:` in `meta`) — a re-added node whose agent kept its state would otherwise count its totals twice and refuse every document as older.
- **Removing a person erases lifetime totals, per-user baselines, and daily history in the user's transaction** — node report sequences and epochs stay, and the ledger drops unknown IDs before comparing counters, so a late report cannot recreate them.
- **Node totals come from the ledger** — `NodeStatus` traffic is the node total, never reconstructed from user totals, the adapter's default zero, or the last-arriving epoch, and never cleared by user, history, or node deletion; duplicates and retired epochs leave activity alone, and a late older collection window adds bytes without replacing fresher activity.
- **Unknown first use stays unknown** — existing or imported usage with an unknown first time stays unknown after more growth; never assign a recent report as the historical first use. The last node and receipt time still advance, and known first times stay set once.
- **Never identify an unused invitation from current-period traffic or a null first time alone** — a reset or undated imported use still has lifetime evidence. Quota predicates multiply integers, expiry includes both window endpoints, and unused age is strictly more than the threshold.
- **Shared UTC periods** — enforcement and subscription refill dates share `control.periods` boundaries: weeks start Monday, and months advance by calendar month rather than a fixed number of days.
- **Validate each new user expiry inside its write transaction**, including imports and extensions; years 2099 onward project as legacy "never", so refuse them with removal guidance.
- **Bound every API quota at SQLite's signed int64 maximum before it reaches a write**; create, update, and returned user records share the CLI's bound.
- **An app that sends no valid `x-hwid` is served and counted nowhere** — Remnawave refused it, which locks out apps without HWID support; browsers and the connection page's `/sub/<token>/info` account check never register a device (the page read 404 there once, which disabled every import).
- **In full mode a raw `x-hwid` matching a pending fingerprint (no first-seen time) is no device** — it once promoted an app into another device's slot after a raise from private.
- **Secrets never ride a snapshot** — the copy drops the `secrets` table, sessions, enrollment tokens, nonces, and the `ui_*` owner tables, then VACUUMs (autocommit, or SQLite refuses) so their pages go too; a restore regenerates them, so a seized server's CA signs nothing agents accept. Privacy settings and their audit always ride; device and history rows only while their level is on, and a restore drops private fingerprints (their key never rides), including any still awaiting promotion to full. Strip through `strip_unsnapshotted()`, which skips tables an older schema lacks: a restore strips before migrating, and a bare `DELETE FROM ui_owner` refused every schema-7 snapshot.
- **Blob attempts publish under the blob lock** — refresh wanted blobs from the whole current fleet under that lock, prune retired or seeded failures, and publish attempt results there so a late failure cannot restore obsolete degradation; clearing an obsolete error never invents a mirror success.
- **Background tasks log no exception text** — enforcement and blob mirroring keep attempt/success times and fixed error codes only in memory and warn at most once per task per five minutes.
- **Event details are typed** — accept only typed field names, statuses, counts, audit IDs, and token names/scopes; never copy user records, credential values, raw report errors, addresses, device metadata, command targets, or user identifiers. A missing report cannot announce an apply recovery, and a repeated state or write adds no transition event.
- **Startup prunes events only after fleet identity and schema checks succeed** — pruning in a ledger constructor once let a refused foreign-fleet open erase older local facts.
- **Notes and tags stay private** — keep them out of event field catalogs and subscription projections; metadata-only edits must produce no lifecycle fact or new node document.
- **Resolve person language before rendering**, under the account/settings lock; an omitted edit preserves the override, explicit null uses the fleet, and User-Agent/Accept never choose a language.
- **Encode `announce` as `base64:` plus UTF-8 Base64 after per-person substitution**; suppress expired notices on every read and keep previews out of SQLite, devices, and backup mutation hooks.
- **Support HTML is no-store and fetches nothing** — it embeds escaped public contact data from current settings and stays outside service-worker caches; it never fetches person data or puts a bearer token into a background request.
- **Person pages are no-store and noindex** — person HTML, config, and manifests are not cacheable; shared assets alone are. Page responses carry the strict CSP and frame/nosniff headers; nginx supplies Referrer-Policy and gzip.
- **Preview distinguishes the browser shell** — Accept `text/html` gets the shell while suffix `/info` gets JSON; keep exact format content types and privacy's no-HWID header flags, and redact page/support URLs plus encoded title/notice values.
- **`ClientEndpoint` strips one matching pair of IPv6 brackets at the API boundary**; structured server addresses stay bare, and only URI authorities add brackets.
- **Server allowance offsets advance inside the accounting transaction before accepted growth** — label changes and allowance amounts preserve use, while enabling or changing the reset day starts tracking at apply with earlier period use unknown. Allowance reads and attention never write; receipt-period usage excludes overhead, host downloads, and relay forwarding, and one-off past payment dates remain overdue.
