# control — Meridian's own control service (`meridian serve`)

## Design decisions
- **Replaces Remnawave** — every fleet shape but client-IP forwarding (exits anywhere, relays, routing gateways as agent nodes, WARP, a control server without an exit), users, signed node documents, and every subscription format; hidden behind `--control=meridian` until it reaches parity (#95).
- **Service owns users, deployer owns topology (for now)** — the reconciler's Meridian drivers PUT node specs, endpoints, and users over the admin API; the service composes each node's whole document (spec + one users resource per managed inbound, right after the `xray_config`), signs it, and serves it to the agent.
- **Fleet CA from the first start** — `NodeAuthority` (`enrollment.py`) creates an Ed25519 CA (`pki.py`; keys in the `secrets` table) and certifies the signing key with URI SAN `meridian-service://<fleet>`; `key_id` is that certificate's DER SHA-256. Documents signed under another certificate are signed again at start.
- **Enrollment and sessions follow the contract** — the admin API mints one single-use, 30-minute enrollment token per node; `enroll` trades it and a CSR for a 90-day certificate (SAN `meridian-agent://<fleet>/<node>`) and revokes the node's earlier certificates and sessions; `hello` checks chain, revocation, SAN, ±300 s, and nonce, then opens a one-hour session. Every token is stored only as SHA-256; the 443 handshake never asks for a client certificate. Version skew follows `core/version_skew.py`: a hello offering no protocol the service speaks gets `unsupported_protocol` (retry after 300 s, in the body and `Retry-After`) before the rest is parsed.
- **Traffic counted exactly once** — `traffic.py` keeps each node's last (counter_epoch, seq, totals) and adds only growth; a resent seq is acked uncounted, an epoch the node left never counts again. `GET /api/traffic` joins totals to usernames; no client address is ever stored.
- **Scoped API tokens** — one revocable `/api` token per device or agent (`tokens.py`), scoped `read` < `propose` < `approve` < `admin`; each `/api` route in `server.ROUTES` names its scope. Whatever applying does (node/user/endpoint writes, a revision's result, the fence) is `WRITE` = `admin`. The config's admin token is the root `admin`: unlisted, rotated only by rewriting the config. User reads blank `uuid`/`sub_token` below `admin` (they connect as the user).
- **Revisions record every reviewed apply** — `revisions.py`: number, author (token ID and name; `root` for the config token), secret-free intent snapshot, plan and review hashes, `proposed` → `approved` → `applied`|`failed`. `propose` proposes, `approve` approves another's proposal; only an `admin` token approves its own (the deployer's one-person path).
- **The apply fence is one CAS row** — `GET/PUT /api/fence` stores what `reconciler/fence.py` decides (fleet, generation, plan hash, committed revision, lease) and replaces it only from the version read (409 otherwise); the service never judges leases itself.
- **Blob mirror** — `blobs.py` keeps every `binary_pin` that lists `service` (the agent spec puts it after GitHub) in `<state>/blobs/<sha256>`: one background worker downloads it after a spec PUT, at start, and when an agent's miss finds it still absent (at most once a minute), verifying size and hash before an atomic rename; `blobs/{sha256}` streams it to session holders. Nodes that cannot reach GitHub install from the service.
- **Stdlib HTTP on loopback** — `ThreadingHTTPServer` behind nginx's secret path; a thread per waiting long-poll is cheap at Meridian's fleet sizes. nginx strips the secret path, so routes are `/api`, `/agent/v1`, `/sub`.
- **Operator-owned users** — the operator sets `active`/`disabled`, expiry, and limits over `PATCH /api/users`; enforcement (a 30 s timer plus every change) turns an active user `expired` or `limited` and back once a change, `reset-traffic`, or a new day/week/month (UTC, weeks from Monday) lifts it. Node documents carry only active users. Use is lifetime (the ledger's total plus `traffic_carried_bytes`) minus the offset the last reset recorded. Admin-only `POST /api/import/users` (`meridian migrate`) creates users with given credentials, status, limits, and usage, all or nothing: same credentials again change nothing, others refuse the batch (409); carried use is lifetime with an offset leaving the period's use, and a source reset before the current period becomes the import time, so enforcement never wipes it.
- **Encrypted snapshots** — `snapshot.py`, `meridian.snapshot/v1`: a `meridian-snapshot/v1` line, the header as canonical one-line JSON (fleet ID, epoch, newest revision, recipients), then a standard age v1 file (pyrage: per-recipient X25519 + HKDF-SHA256 wrap of a random file key, ChaCha20-Poly1305 STREAM payload). age has no associated data, so the sealed ZIP repeats the header bytes in `header.json` and decryption refuses any mismatch; the plaintext header is for listing only. Recovery keys are plain age identities (`age -d -i` works). `backups.py` seals `GET /api/backup/snapshot` (admin, like every backup route) to each registered device key and the recovery key (only its public half is stored), from an online-backup copy that also carries the deployer's deposited `cluster.yml`/`servers.json` (an older generation never replaces a newer one). `restore.py` stages a snapshot's database for a new server: epoch + 1, node certificates revoked, a new CA and signing key, every document signed again.
- **One SQLite file, migrated forward** — `store.Store` shares one connection, lock, and change condition between `ControlService`, `NodeAuthority`, `TrafficLedger`, `TokenRegistry`, `RevisionLedger`, `BackupLedger`, and `OwnerAuth`, each owning its tables; WAL mode, and the condition wakes polls on a new revision. `SCHEMA_VERSION` plus `_MIGRATIONS` (statements per version step) move it forward; a database from a newer Meridian is refused, never downgraded.
- **Web console (hidden with the backend)** — one owner signs in at the secret path's root: a scrypt password (`passwords.py`) and an optional RFC 6238 code, offered after setup and switched on or off after re-entering both. `owner.py` keeps sessions as SHA-256 only (30 min idle, 12 h absolute, ten at most) and mints single-use 15-minute setup links, which only the root token asks for (`meridian panel`). An owner session is the admin caller `WEB_OWNER`, so `ROUTES` keep their scope checks and revisions record author `owner`; minting a token also needs a sign-in from the last 5 minutes, and routes only the CLI calls (`server.MACHINE_ONLY`: enrollment, user import, backups) refuse a session outright. The request's source is always nginx's loopback, so guess limits (`login_limits.py`, in memory) are per bucket: sign-in, setup links, and each session's own re-checks; no client address is kept. Screens: `ui/CLAUDE.md`.
- **Subscriptions follow the golden corpus** — `formats/` renders Base64, Xray JSON (a list: "Automatic", then fingerprint copies' own config), Mihomo, Stash, sing-box, and a browser's status JSON by filling `compiler/delivery.py`'s templates; `formats/selector.py` picks by suffix, Accept, then User-Agent. `tests/test_control_subscription_corpus.py` diffs every corpus request, each deliberate fix a named row (plain Clash/Stash get Meridian's Mihomo, Hiddify sing-box, an empty User-Agent Base64; no panel security headers). Hysteria2 auth is the VLESS UUID, as Remnawave delivered it. WSS, which no capture holds, follows Remnawave 3.4.5's generators field for field (`test_wss_entries_match_remnawave_generators`).
- **Renderer takes plain values** — `SubscriptionUser` (UUID, short ID, status `active|disabled|limited|expired`, expiry, traffic) and `ClientEndpoint`s; a suspended user gets Remnawave's status placeholder entries in every format. `ServiceSettings.public_url` feeds `support-url`/`profile-web-page-url`; `ClientEndpoint.fingerprint_copy` marks copies.

## What's done well
- A revision is signed only when the resources' hash (or the signing certificate) changes, so repeated applies never wake agents.
- Agent errors use the protocol's `AgentErrorResponse` with the status `AGENT_HTTP_SURFACE` maps (`errors.agent_error`); admin errors a plain `{"error": {...}}`.
- An API token's public ID (`mrd_<id>_<secret>`) finds its row, so the hash is compared once with `hmac.compare_digest`, against a dummy when no row matches.
- A refused CSR rolls back with its transaction, so a bad request never burns the enrollment token.
- A proposal whose intent has a secret-shaped key or value (`secret_paths()`, keys per `core.redaction`) is refused, never stored.

## Pitfalls
- nginx answers 502/503/504 for a stopped or hung service — `ControlClient` raises those as retryable unreachable errors; as plain refusals, a stopped ctld failed the fence at once with "refused: HTTP 502".
- `serve` is a daemon: the root callback skips the beta banner and the update check for it (it once printed the banner into journald and phoned out on every start).
- Decode the path before routing — `ControlClient` percent-encodes IDs, so `:` in endpoint IDs arrives as `%3A` and every endpoint PUT 404'd.
- Compare timestamps parsed, never as strings — the contract allows fractional seconds, and `…:00.5Z` sorts before `…:00Z`.
- Never log requests or store where they came from: paths carry the secret path and subscription tokens (`log_message` is silenced); a token keeps only a once-a-minute `last_used_at`.
- Secrets never ride a snapshot — the copy drops the `secrets` table, sessions, enrollment tokens, nonces, and the `ui_*` owner tables, then VACUUMs (autocommit, or SQLite refuses) so their pages go too; a restore regenerates them, so a seized server's CA signs nothing agents accept. Strip through `strip_unsnapshotted()`, which skips tables an older schema lacks: a restore strips before migrating, and a bare `DELETE FROM ui_owner` refused every schema-7 snapshot.
- `executescript()` commits on its own — create tables with `Store.create()`, never inside `transaction()`.
- Hash and sign the document as JSON values, never re-serialized typed models (the agent verifies the bytes it received); verify a `NodeProof` over the hello dict as received, too.
- Record a hello nonce only after the proof verifies, and keep it until `issued_at` + 300 s + margin, or a captured hello replays.
- Traffic baselines outlive node deletion — a re-added node whose agent kept its counter store would otherwise count its totals twice.
- A poll answers before its session expires, so the agent's next request is a fresh `hello` rather than a 401.
- `control/` never imports the deployer (CLI, SSH, panel, provision, reconciler); architecture-tested.
- Never compress or send Referrer-Policy on `/sub/` — nginx gzips JSON/Base64 (YAML stays plain, as `gzip_types` has none) and adds its own Referrer-Policy; the panel's duplicate was a corpus defect.
- A fingerprint copy without `fingerprint_copy` lands in the primary balancer and failover groups, mixing fingerprints toward one server (TSPU escalates); sing-box omits copies entirely.
- Stash spells fields its own way (`sni`, Hysteria2 `auth`) and has no `exclude-filter` or `GEOIP,private`; Remnawave's Stash and Clash answers had no failover at all.
