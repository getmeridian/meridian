# control — Meridian's own control service (`meridian serve`)

## Design decisions
- **Subscription HTTP** — `subscription_routes.py` writes the response through the shared public request interface; the server keeps routing and authentication.
- **Service settings** — `service_settings.py` reads and persists delivery settings; the public service methods delegate, and every setting is saved in one store transaction.
- **Token expiry is registry time** — schema step 12 adds nullable `api_tokens.expires_at`; old tokens remain indefinite. Issuance accepts a future UTC expiry or 1–3650 days, computed inside the insert transaction, and authentication refuses at the deadline with the same 401 as revocation, without touching last use. Historical step 4 keeps its original table definition so an older database adds expiry only once.
- **Duration extensions** — `user_lifecycle.py` owns fresh account inserts and computes max(now, expiry) plus whole days inside the service's write transaction, then records the expiry change, enforces, and composes before returning; disabled status and traffic cutoffs remain the operator's.
- **People capability** — `people` is separate from `read < propose < approve`, and `admin` covers both; `server.ROUTES` allows either read or people for user reads, only people/admin for user mutations, and no people access to fleet, settings, privacy, enrollment, tokens, or backups. Cut-off scope needs read and ending sessions needs admin, including a cut-off requested with a user mutation. People reads include credentials, while `user_access.py` checks declared remove/reissue refusals in the write's transaction for people tokens and the owner session.
- **Derived attention** — `attention.py` reads users, liveness, and fresh runtime health under the store lock and delegates to `core/attention.py`; nothing is written. Read-scoped `/api/attention` (owner allowed) uses expiry 7 days, quota 80%, and unused age over 3 days by default, with bounded query thresholds; unseen nodes and degraded health also need attention.
- **Local events** — `events.py`, step 13: typed `core/fleet_events.py` facts for user, token, privacy, and node transitions, capped at 2,000 entries and 180 days. Mutation hooks append inside their write transaction; request actors are thread-local and enforcement is `system`. The 30 s timer debounces node liveness and apply failures, including a full live window before an unseen new node goes offline; facts and debounce state ride snapshots, and privacy facts point to the audit's exposed row ID.
- **Durable node evidence** — step 13 adds accepted upload/download growth to `node_traffic_totals` in the user's accounting transaction; replay baselines can retire independently. Migration backfills only retained per-epoch counters and marks when complete accounting starts; first-use and last-node evidence are scalar receipt-time aggregates, and latest collection time selects each node's active count (never sessions or addresses).
- **Replaces Remnawave** — every fleet shape but client-IP forwarding (exits anywhere, relays, routing gateways as agent nodes, WARP, a control server without an exit), users, signed node documents, and every subscription format; the only backend since the flip (#95). Client-IP forwarding waits for its own review, so `--client-ips` is hidden and `migrate` drops it.
- **Service owns users, deployer owns topology (for now)** — the reconciler's Meridian drivers PUT node specs, endpoints, and users over the admin API; the service composes each node's whole document (spec + one users resource per managed inbound, right after the `xray_config`), signs it, and serves it to the agent; `NodeStatus.in_sync` compares the applied (epoch, revision, hash) with the epoch as the agent reported it (relabelled with the service's, a cached pre-restore report read as in sync).
- **Fleet CA from the first start** — `NodeAuthority` (`enrollment.py`) creates an Ed25519 CA (`pki.py`; keys in the `secrets` table) and certifies the signing key with URI SAN `meridian-service://<fleet>`; `key_id` is that certificate's DER SHA-256. Documents signed under another certificate are signed again at start.
- **Enrollment and sessions follow the contract** — the admin API mints one single-use, 30-minute enrollment token per node; `enroll` trades it and a CSR for a 90-day certificate (SAN `meridian-agent://<fleet>/<node>`) and revokes the node's earlier certificates and sessions; `hello` checks chain, revocation, SAN, ±300 s, and nonce, then opens a one-hour session; `renew` re-checks revocation in its own transaction (a renewal racing an enrollment once revived a revoked node). Every token is stored only as SHA-256; the 443 handshake never asks for a client certificate. Version skew follows `core/version_skew.py`: a hello offering no protocol the service speaks gets `unsupported_protocol` (retry after 300 s, in the body and `Retry-After`) before the rest is parsed.
- **Traffic counted exactly once** — `traffic.py` keeps each node's last seq and totals per counter epoch and adds only growth; a resent seq is acked uncounted. Epoch IDs are random, so a late report from an old or unseen epoch counts against its own baselines (it once retired the live epoch, which then never counted again); only the `KEPT_EPOCHS` newest arrivals keep baselines, older ones are retired (the newest `REMEMBERED_RETIRED_EPOCHS` stay remembered), and counters of a user ID the service never had are dropped, so a node cannot grow the database at will. `GET /api/traffic` joins totals to usernames; no client address is ever stored.
- **Daily history is opt-in** — with `usage_history: daily`, `traffic.py` adds the same growth it counts to `traffic_daily`/`node_traffic_daily` on its UTC receipt day (nothing while off); the 30 s timer prunes days beyond `history_days`, today included. `operations_api.py` parses HTTP history day counts, with thin server delegations.
- **Scoped API tokens** — one revocable `/api` token per device or agent (`tokens.py`), scoped `read` < `propose` < `approve` < `admin`; each `/api` route in `server.ROUTES` names its scope. Whatever applying does (node/user/endpoint writes, a revision's result, the fence) is `WRITE` = `admin`. The config's admin token is the root `admin`: unlisted, rotated only by rewriting the config. User reads blank `uuid`/`sub_token` below `admin` (they connect as the user).
- **Revisions record every reviewed apply** — `revisions.py`: number, author (token ID and name; `root` for the config token), secret-free intent snapshot, plan and review hashes, `proposed` → `approved` → `applied`|`failed`. `propose` proposes, `approve` approves another's proposal; only an `admin` token approves its own (the deployer's one-person path).
- **The apply fence is one CAS row** — `GET/PUT /api/fence` stores what `reconciler/fence.py` decides (fleet, generation, plan hash, committed revision, lease) and replaces it only from the version read (409 otherwise), answering with what that swap wrote (a re-read after commit could hand back the next writer's version); the service never judges leases itself.
- **Blob mirror** — `blobs.py` keeps every `binary_pin` that lists `service` (the agent spec puts it after GitHub) in `<state>/blobs/<sha256>`: one background worker downloads it after a spec PUT, at start, and when an agent's miss finds it still absent (at most once a minute), verifying size and hash before an atomic rename; `blobs/{sha256}` streams it to a session whose own node's spec pins that hash (404 otherwise, like an unknown one). Nodes that cannot reach GitHub install from the service.
- **Stdlib HTTP on loopback** — `ThreadingHTTPServer` behind nginx's secret path; a thread per waiting long-poll is cheap at Meridian's fleet sizes; one request per connection, a 60 s socket read deadline, and only a digit Content-Length (`read(-1)` reads to EOF, past the body limit). nginx strips the secret path, so routes are `/api`, `/agent/v1`, `/sub`.
- **Operator-owned users** — the operator sets `active`/`disabled`, expiry, and limits over `PATCH /api/users`; enforcement (a 30 s timer, every change, and each stats report, whose periods advance before its growth counts, or the timer's reset folded post-midnight use into the offset) turns an active user `expired` or `limited` and back once a change, `reset-traffic`, or a new day/week/month (UTC, weeks from Monday) lifts it. Node documents carry only active users. Use is lifetime (the ledger's total plus `traffic_carried_bytes`) minus the offset the last reset recorded. Admin-only `POST /api/import/users` (`meridian migrate`) creates users with given credentials, status, limits, and usage, all or nothing: same credentials again change nothing, others refuse the batch (409), and `replace` overwrites existing users; a UUID is stored as given (Hysteria2 authenticates with the exact string), compared case-insensitively, and lowercased for VLESS documents (the contract refuses uppercase, which wedged every node); carried use is lifetime with an offset leaving the period's use, and a source reset before the current period becomes the import time, so enforcement never wipes it.
- **Privacy is the operator's** — `privacy.py` keeps one settings row (device limits `off|private|full`, usage history `off|daily`, both off by default) and a full before/after audit (`privacy_changes`, newest 50 read, author from `TokenRegistry.actor`); applies never write it, and `PUT /api/privacy` is `WRITE` plus an owner step-up. A lowering, a shorter retention, and the audit row commit in one transaction: the writer asks `DeviceLedger.lower_level` to re-key full IDs into fingerprints or delete every device; identical settings add no row.
- **Device caps** — `devices.py`: off reads no header; private stores HMAC-SHA256 (secret `device_hmac_key`) of `x-hwid` with every metadata column and timestamp NULL; full stores the HWID, platform, OS version, model, user agent, and first/last fetch, never an address. A new device over the cap (`users.device_limit`, else the fleet default) gets the status placeholder and v2RayTun's `x-hwid-*` headers, decided in the fetch's transaction; known devices stay allowed above a lowered cap, inactive users take no new slot, and a raise from private to full learns each raw ID at its next fetch without taking a second slot.
- **Encrypted snapshots** — `snapshot.py`, `meridian.snapshot/v1`: a `meridian-snapshot/v1` line, the header as canonical one-line JSON (fleet ID, epoch, newest revision, recipients), then a standard age v1 file (pyrage: per-recipient X25519 + HKDF-SHA256 wrap of a random file key, ChaCha20-Poly1305 STREAM payload). age has no associated data, so the sealed ZIP repeats the header bytes in `header.json` and decryption refuses any mismatch; the plaintext header is for listing only. Recovery keys are plain age identities (`age -d -i` works). `backups.py` seals `GET /api/backup/snapshot` (admin, like every backup route) to each registered device key and the recovery key (only its public half is stored), from an online-backup copy that also carries the deployer's deposited `cluster.yml`/`servers.json` (an older generation never replaces a newer one). `restore.py` stages a snapshot's database for a new server: the next epoch (above `minimum_epoch` too), node certificates revoked, a new CA and signing key, every document signed again.
- **One SQLite file, migrated forward** — `store.Store` shares one connection, lock, and change condition between `ControlService`, `NodeAuthority`, `TrafficLedger`, `TokenRegistry`, `RevisionLedger`, `BackupLedger`, `OwnerAuth`, `PrivacyLedger`, and `DeviceLedger`, each owning its tables (`users.py` turns rows into `UserRecord`s, `user_policy.py` holds expiry, reset periods, and enforcement); WAL mode, and the condition wakes polls on a new revision. `SCHEMA_VERSION` plus `_MIGRATIONS` (statements per version step) move it forward; a database from a newer Meridian is refused, never downgraded.
- **Web console** — one owner signs in at the secret path's root: a scrypt password (`passwords.py`) and an optional RFC 6238 code, offered after setup and switched on or off after re-entering both. `owner.py` keeps sessions as SHA-256 only (30 min idle, 12 h absolute, ten at most) and mints single-use 15-minute setup links, which only the root token asks for (`meridian panel`). An owner session is the admin caller `WEB_OWNER` on `server.OWNER_ROUTES` only, the routes the screens call (people, tokens, settings and revision reads, the fleet and share views); every other route (node, endpoint, and fence writes, revisions, enrollment, user import, backups) refuses it outright, and a token it mints stays below `admin` (which would reach every other route) and needs a sign-in from the last 5 minutes, held in the insert's transaction. The request's source is always nginx's loopback, so guess limits (`login_limits.py`, in memory) are per bucket: sign-in, setup links, and each session's own re-checks; no client address is kept. Screens: `ui/CLAUDE.md`.
- **Subscriptions follow the golden corpus** — `subscription_serving.py` reads accounts, endpoints, settings, and privacy under the store lock and registers app devices transactionally; `ControlService.subscription` delegates to it. `formats/` renders Base64, Xray JSON (a list: "Automatic", then one config per copy fingerprint), Mihomo, Stash, sing-box, and a browser's status JSON by filling `compiler/delivery.py`'s templates; `formats/selector.py` picks by suffix, Accept, then User-Agent. `tests/test_control_subscription_corpus.py` diffs every corpus request, each deliberate fix a named row (plain Clash/Stash get Meridian's Mihomo, Hiddify sing-box, an empty User-Agent Base64; no panel security headers). Hysteria2 auth is the VLESS UUID, as Remnawave delivered it. WSS, which no capture holds, follows Remnawave 3.4.5's generators field for field (`test_wss_entries_match_remnawave_generators`).
- **Renderer takes plain values** — `SubscriptionUser` (UUID, short ID, status `active|disabled|limited|expired`, expiry, traffic and its reset strategy) and `ClientEndpoint`s; a suspended user gets Remnawave's status placeholder entries in every format. `ServiceSettings.public_url` feeds `support-url`/`profile-web-page-url`; `ClientEndpoint.fingerprint_copy` marks copies.

## What's done well
- Node status exposes durable `traffic_bytes` and its activity window from the same accounting row, so deployer adapters consume the public API rather than replay baselines.
- The console's direct command permission is only `restart_unit` for a held managed resource; cut-off resets are queued through the guarded person mutation, and all other command kinds remain API-token operations.
- `cutoff.py` captures affected inbounds before a credential change and queues revision-gated resets in that change's transaction; a full queue rolls back the credentials and documents together, and a closed console tab cannot strand the cut-off.
- Signed commands live in `commands.py` and schema step 14: oldest first, only session-negotiated kinds, durable first-result acknowledgements, 64 unanswered per node, expiry and seven-day finished retention; revision gates release only on applied reports.
- Command session capabilities and command queues are transient snapshot state; restore never replays a signed command under the old epoch or signing certificate.
- Command issue and terminal result facts share their mutation's transaction in the local event ledger; retries add no duplicate result, and details carry only command ID, kind, status, and reset effect, never targets, user identifiers, or raw errors.
- A revision is signed only when the resources' hash (or the signing certificate) changes, so repeated applies never wake agents.
- Agent errors use the protocol's `AgentErrorResponse` with the status `AGENT_HTTP_SURFACE` maps (`errors.agent_error`); admin errors a plain `{"error": {...}}`.
- An API token's public ID (`mrd_<id>_<secret>`) finds its row, so the hash is compared once with `hmac.compare_digest`, against a dummy when no row matches.
- A refused CSR rolls back with its transaction, so a bad request never burns the enrollment token.
- A proposal whose intent has a secret-shaped key or value (`secret_paths()`, keys per `core.redaction`) is refused, never stored; so is one whose `access` block is malformed (the console reads `access.users` on every person screen, and a `null` there broke them all).

## Pitfalls
- Deployer user deletion requests its cut-off in the DELETE body; a full reset queue rolls back the deletion, so no separate revision read or reset POST follows it.
- Service expiry stops redelivery, but the first agent result can replace an expired row with no result; record that late outcome and its event atomically and never overwrite an acknowledged result.
- Refresh wanted blobs from the whole current fleet under the blob lock, prune retired or seeded failures, and publish attempt results under that lock so a late failure cannot restore obsolete degradation; clearing an obsolete error never invents a mirror success.
- Validate each new user expiry inside its write transaction, including imports and extensions; years 2099 onward project as legacy "never", so refuse them with removal guidance.
- Sort endpoints once before allocating presentation names; primary filters and fingerprint groups preserve that order because generated numeric suffixes sort differently.
- Xray availability checks primary endpoints; fingerprint copies alone must show the same inert availability notices as Mihomo and sing-box.
- Attention shares NodeStatus runtime freshness and degradation with fleet views; stale reports cannot supply current health or apply failures, and failing checks count even under a healthy summary.
- The topology owns `client_routing`: persist it in the delivery settings transaction, read old databases as `ru-split`, and pass it to every structured subscription renderer, including Xray fingerprint groups and Stash.
- The topology owns subscription refresh hours (1–168, default 6); persist them with the other service settings in one transaction, and read old databases as six hours.
- ClientEndpoint strips one matching pair of IPv6 brackets at the API boundary; structured server addresses stay bare, and only URI authorities add brackets.
- Enforcement and subscription refill dates share control.periods UTC boundaries: weeks start Monday, and months advance by calendar month rather than a fixed number of days.
- Empty supported endpoint sets use inert availability placeholders in all four locales, with existing status notices taking priority; filter Stash XHTTP and sing-box XHTTP/copies before checking availability.
- Allocate unique presentation names before filtering endpoints, reserving generated groups and direct/reject labels; preserve original suffix-shaped remarks and use the same names in proxies, tags, and copy exclusions.
- Derive subscription suffix routing from formats.selector.SUFFIX_FORMATS; aliases override Accept and User-Agent, and Stash retains its own dialect.
- Read polls carrying X-Meridian-Passive authenticate without touching owner idle activity, including auth/state; every write ignores the passive header and still re-checks session liveness in its transaction.
- Bound every API quota at SQLite's signed int64 maximum before it reaches a write; create, update, and returned user records share the CLI's bound.
- Background enforcement and blob mirroring keep attempt/success times and fixed error codes only in memory; warn at most once per task per five minutes and never log exception text.
- NodeStatus traffic is the ledger's node total, carried into the CLI's Node; never reconstruct it from user totals or leave the adapter's default zero.
- Agent polls refresh reachability only; judge runtime health and convergence from a report younger than the live window, and keep stale reports as unavailable evidence.
- Never identify an unused invitation from current-period traffic or a null first time alone: a reset or undated imported use still has lifetime evidence. Quota predicates multiply integers, expiry includes both window endpoints, and unused age is strictly more than the threshold.
- Existing or imported usage with an unknown first time stays unknown after more growth; never assign a recent report as the historical first use. The last node and receipt time still advance, and known first times stay set once.
- Startup prunes events only after fleet identity and schema checks succeed; pruning in a ledger constructor once let a refused foreign-fleet open erase older local facts.
- Event details accept only typed field names, statuses, counts, audit IDs, and token names/scopes; never copy user records, credential values, raw report errors, addresses, or device metadata. A missing report cannot announce an apply recovery, and a repeated state or write adds no transition event.
- Never derive displayed node totals from the last-arriving epoch or clear them with user/history/node deletion; duplicates and retired epochs leave activity alone, and a late older collection window adds bytes without replacing fresher activity.
- Removing a person erases lifetime totals, per-user baselines, and daily history in the user's transaction; node report sequences and epochs stay, and the ledger itself drops unknown IDs before comparing counters so a late report cannot recreate them.
- Deleting a node expires its waiting and pending commands in the same transaction; a replacement with the same logical ID must never inherit a queued restart.
- A cut-off must wait for the credential-removal revision to be reported applied; resetting an inbound against the previous composition can restore the revoked credentials.
- nginx answers 502/503/504 for a stopped or hung service — `ControlClient` raises those as retryable unreachable errors; as plain refusals, a stopped ctld failed the fence at once with "refused: HTTP 502". A write the backup hook counts as maybe-committed (a lost reply, any 5xx) raises `ControlServiceUncertain`, which Meridian drivers turn into `UnknownResourceOutcome`.
- `serve` is a daemon: the root callback skips the beta banner and the update check for it (it once printed the banner into journald and phoned out on every start).
- Decode the path before routing — `ControlClient` percent-encodes IDs, so `:` in endpoint IDs arrives as `%3A` and every endpoint PUT 404'd; node routes match only topology IDs (`_NODE`), or a grant stored `main:exit` before its response refused it and broke the fleet view.
- Compare timestamps parsed, never as strings — the contract allows fractional seconds, and `…:00.5Z` sorts before `…:00Z`.
- Answer like nginx everywhere — `HEAD` dispatches as `GET`, `send_error()` writes nginx's page (http.server's own named the backend), and any miss under `/sub/` gets the unknown-subscription answer; routes read before authentication (`/auth/*`, enroll, hello) take 64 KiB bodies, not the 4 MiB the APIs allow.
- Never log requests or store where they came from: paths carry the secret path and subscription tokens (`log_message` is silenced); a token keeps only a once-a-minute `last_used_at`.
- An app that sends no valid `x-hwid` is served and counted nowhere — Remnawave refused it, which locks out apps without HWID support; browsers and the connection page's `/sub/<token>/info` account check never register a device (the page read 404 there once, which disabled every import).
- In full mode a raw `x-hwid` matching a pending fingerprint (no first-seen time) is no device — it once promoted an app into another device's slot after a raise from private.
- Secrets never ride a snapshot — the copy drops the `secrets` table, sessions, enrollment tokens, nonces, and the `ui_*` owner tables, then VACUUMs (autocommit, or SQLite refuses) so their pages go too; a restore regenerates them, so a seized server's CA signs nothing agents accept. Privacy settings and their audit always ride; device and history rows only while their level is on, and a restore drops private fingerprints (their key never rides), including any still awaiting promotion to full. Strip through `strip_unsnapshotted()`, which skips tables an older schema lacks: a restore strips before migrating, and a bare `DELETE FROM ui_owner` refused every schema-7 snapshot.
- A console check holds only inside the write's own transaction — `Store.conditions()` re-runs it after `BEGIN IMMEDIATE` (session liveness via `OwnerAuth.while_live` on every owner request and `hold_live` in the `/ui/api/auth` writes, which authenticate themselves; declared people); judged before the body was read, a revoked tab still wrote, and a person mid-apply could be relinked. Declared counts every revision after the newest applied one, approved or failed (a merely proposed one declares no one, or a `propose` token locked the owner out): an apply creates its people before it records applied, and a failed one leaves them to the CLI's retry.
- A revision's number is kept from the moment it is proposed — an approval that landed with its reply lost was otherwise left `approved` forever (in flight in `fleet history`) once acquisition gave up.
- `executescript()` commits on its own — create tables with `Store.create()`, never inside `transaction()`.
- Hash and sign the document as JSON values, never re-serialized typed models (the agent verifies the bytes it received); verify a `NodeProof` over the hello dict as received, too.
- Record a hello nonce only after the proof verifies, and keep it until `issued_at` + 300 s + margin, or a captured hello replays.
- Traffic baselines and revisions outlive node deletion (`retired_revision:` in `meta`) — a re-added node whose agent kept its state would otherwise count its totals twice and refuse every document as older.
- A poll answers before its session expires, so the agent's next request is a fresh `hello` rather than a 401.
- `control/` never imports the deployer (CLI, SSH, panel, provision, reconciler); architecture-tested.
- Never compress or send Referrer-Policy on `/sub/` — nginx gzips JSON/Base64 (YAML stays plain, as `gzip_types` has none) and adds its own Referrer-Policy; the panel's duplicate was a corpus defect.
- A fingerprint copy without `fingerprint_copy` lands in the primary balancer and failover groups, mixing fingerprints toward one server (TSPU escalates); copies group per fingerprint too (`copy_groups()`: a Safari path's Chrome and Firefox copies once shared one balancer); sing-box omits copies entirely.
- Mihomo and Stash read YAML 1.2, PyYAML writes 1.1: dump through `mihomo._Yaml12SafeDumper`, which quotes strings 1.2 resolves as numbers or booleans — a random short ID like `12e34567` once became a float and Mihomo refused the document (System Lab caught it by chance).
- Stash spells fields its own way (`sni`, Hysteria2 `auth`) and has no `exclude-filter` or `GEOIP,private`; Remnawave's Stash and Clash answers had no failover at all.
