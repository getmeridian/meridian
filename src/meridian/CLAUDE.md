# src/meridian — Python CLI package
## Design decisions
**Cluster config** — one hidden Schema V4 `cluster.yml` holds topology intent, bindings, allocations, and checkpoints (`cluster.py` model, `cluster_persistence.py` YAML); users and operator-owned privacy live in the control service.
**Service access** — `control/client.py` speaks HTTPS from the deployer's machine to nginx's secret path on 443 with the admin token; no SSH tunnel. `remnawave/` keeps only migrate's `RemnawaveReader`, the `User`/`Node`/`Host` shapes the access adapters return, and the error types they raise.
**SSH abstraction** — `ServerConnection` runs locally or over SSH (non-root adds `sudo -n`); `conn.run()` returns `CommandResult`, `ssh_transfer.py` moves files, and the `SSHUI` callbacks (`ssh_auth.py`) keep Rich out of transport. Keepalives end a silent connection in ~15s, and a timeout or exit 255 drops the ControlMaster (`reset_multiplex()`) so the next command redials.
**One key bootstrap** — `ssh_keys.py` owns Meridian's key pair, the `authorized_keys` install, and the key-login check for Engine and CLI alike; `resolve.install_meridian_key()` is the CLI's one-time-password path.
**Server facts** — `facts.py` caches OS, kernel, Docker, UFW, containers, sshd ports, disk, and sysctl; use it before adding one-off probe parsing.
**Errors over exits** — library modules raise `MeridianError` subclasses (`core/errors.py`) carrying a `category`; only command entry points call `console.fail()`, whose `hint_type` picks the footer and exit code (tested). Every error must be actionable.
**Shared logic stays out of commands** — `resolve.py` and `setup/` serve commands and Engine; library code never imports `commands/`.
**Protocol keys** — `core/topology.py` owns the protocol vocabulary; `handoff.protocol_key()` classifies delivered links.
**Exit country** — `registry_country.py` reads the RIR country via RDAP (no geo-IP) when an exit is first named and stores it in `ExitIntent.region` (`--country` overrides), keeping the compiler pure.
**Local home** — `config.default_home()` prefers `$XDG_CONFIG_HOME/meridian` (`~/.config/meridian`), adopting an older 4.x home (`~/.meridian-v4`, `~/.meridian`) only if XDG is absent and it holds `servers.json`; `MERIDIAN_HOME` overrides.
**Fleet contexts** — the install home keeps per-person files (SSH key, sockets, preferences, update cache, Xray runtime) and is itself the `default` context; another context's `cluster.yml`, backup, `servers.json`, and `setup.json` live in `contexts/NAME/` (`contexts.py`). The shelf is per context because `srv-*` refs resolve inside one fleet; `fleet_contexts.refuse_servers_claimed_elsewhere()` (in `SetupRuntime.apply`) keeps a host in one fleet's intent. A context a restore took over holds `superseded.json` (who, when; local, never in `cluster.yml`): it claims nothing, only reads run, and `context remove default` then clears just its fleet files. `config.select_context()` binds the per-fleet globals once (`MERIDIAN_HOME` > `--context` > `MERIDIAN_CONTEXT` > `current-context`).
**Neutral host names** — `host_runtime.py` is the one place for unit, `/opt`, and config names (`ctld`, `netagent`, `netcore`); its Docker names are read only by `migrate` and teardown, to remove a Remnawave fleet's containers.
**Binary pins** — `binary_pins.py` holds the server binaries `fleet upgrade` may raise (Realm) and their trust rules; `github_releases.py` reads newer same-major releases with GitHub's per-asset sha256, saved in `ClusterConfig.binary_pins` and carried into `runtime_pins`.
**One control backend (#95)** — every fleet runs Meridian's control service; client paths, including device caps and registrations, use `control_access.access_panel()`, fleet/node/relay status `fleet_panel()` (the projection carries service node and endpoint IDs, gateways included), and `check` reads units and agent reports. A Remnawave fleet is only read to move it: a version-3 `cluster.yml` without a backend loads as `remnawave` (`_name_legacy_backend`), `context._gate_remnawave()` points every other command at `meridian migrate` (`migrate/`, checkpointed in `ClusterConfig.control_migration`), and `deploy` offers the move in a terminal.
**Revisions on the service (#95)** — on a control-service fleet `service_fence.py` moves the apply fence into the service and records each reviewed apply as a revision (secret-free intent, plan and review hashes, author, status); fence.json serves only until the service first answers, then is marked handed over so older Meridians refuse; a service newer than the CLI refuses the apply too (`core/version_skew.py`). `meridian fleet history` lists them.
**Backups (#95)** — every device that manages a control-service fleet pulls an encrypted snapshot of the service after each change (`backup/`, format in `control/snapshot.py`), sealed to its own key and a recovery key printed once.
**Workload secrets** — `reconciler/workloads.py` allocates or reuses complete Reality key triples and persists them before remote mutation; `xray_workload.py` renders only reviewed protocols and egress.
## What's done well
- **Forward-compatible YAML** — unknown keys land inertly in `_extra` (never store load-bearing state there); `load_topology_cluster()` refuses pre-topology files with rebuild guidance.
- **Applied kinds are explicit** — `core/resources.APPLIED_KINDS` lists what plan/apply drives; a leftover Remnawave binding is forgotten only by migrate's cut-over (`cutover.PANEL_SIDE_KINDS`) and fails closed anywhere else.
- **One owner per state** — the control service owns users, `cluster.yml` owns topology, and the control server's apply fence (`reconciler/fence.py`) stops a stale or foreign copy from applying.
- **Read-only fleet projection** — `adapters/cluster.py` is the only source of node/relay rows; it never projects routing gateways as exits or source-restricted relay hops as public endpoints.
## Pitfalls
- A command-result read refused without retry is a failed node outcome, not a timeout; retain completed sibling results and expose a non-retryable warning.
- Persist a requested retirement cut-off in the typed control-user binding before applying the removal; transient runtime flags alone lose the request after a full queue or interrupted apply.
- **A handed-over fence.json is never a fallback** — once the service keeps the fence, an unreachable service is retried and refused; falling back to the file would let a stale copy apply around it.
- **Server ownership compares canonical addresses and fails closed** — `refuse_servers_claimed_elsewhere()` matches `canonical_endpoint_address()` forms (`2001:db8::1` and its long spelling once passed as two machines), a context it cannot read refuses instead of being skipped, and active bindings claim their servers until retirement or forgetting (an intent edit alone once freed a server whose cleanup was still to run).
- **A live agent that could not apply is a failed node** — `ServiceFleetPanel` sets `Node.apply_failed` from the report's `failed`, and `fleet status` degrades (exit 4); reading only `is_live()` once called it connected and healthy.
- **A refused service token stops `fleet status`** — `ServiceFleetPanel.ping()` is false only for an unreachable service; a 401/403 raises `RemnawaveAuthError` (exit 2), where `ControlClient.ping()` swallowed it into degraded (4).
- **Local state is fail-closed** — only missing `cluster.yml`/`servers.json` means fresh; malformed files need recovery, and `srv-*` IDs survive connection edits.
- **Never hard-code the home in messages** — print `config.HOME_DISPLAY`; a literal `~/.meridian` sent 4.x users into 3.x's directory.
- **Read paths as `config.NAME` at call time** — a module-level `from meridian.config import CLUSTER_CONFIG` keeps the fleet chosen at import and ignores `--context` (architecture-tested).
- **Rendered inputs are typed** — validate and canonicalize hostname, SNI, port, and transport path before nginx, Xray, or control-service serialization.
- **Shared links never use the panel path** — build subscription URLs with `PanelConfig.subscription_url()` (connection-page path + `/sub/`); `SUB_PUBLIC_DOMAIN` matches it.
- **Local mode follows the saved profile** — `ServerEntry.runs_here()` matches the recorded `/etc/machine-id` or a bindable address, never the outbound IP (a laptop on the server's VPN shares it); open saved servers with `resolve.connection_for_entry()`.
- **A one-time SSH password only reaches a trusted host key** — it rides the askpass environment of one command and is never saved, logged, or put in an error; `check_ssh` raises `SSHPasswordOnlyError` (user, `ssh-copy-id` hint) only when the server lists `password` or `keyboard-interactive`.
- **Sudo must be passwordless and checked up front** — a failing `sudo -n true` is a user error with a `sudo "$(command -v meridian)"` or NOPASSWD hint, never an SSH key problem; so is an unwritable `known_hosts`.
- **SSH ControlPath must fit a Unix socket** — macOS allows 103 bytes and ssh adds 17; hash the target into the path and drop multiplexing when `MERIDIAN_HOME` is still too deep.
- **Camouflage targets** — never apple.com (ASN mismatch with VPS providers) or www.microsoft.com (certificate over REALITY's 8192-byte limit; no traffic passes); `diagnostics.camouflage.camouflage_refusal()` refuses both for every `--sni` and `sni` command, and a relay's own SNI must be reachable from its exit, which dials it. A `--self-steal` name is served by the exit only after apply, so `own_hostname()` checks its DNS from the exit instead: unresolved stops, elsewhere warns.
- **Reality key material is atomic** — refuse partial private/public/short-ID state instead of rotating keys; `node replace` carries a workload's keys to the new server.
- **Hysteria2 always carries salamander** — the `finalmask` password derives from the workload's Reality private key (`salamander_password()`); never store or rotate it separately.
- **Exits resolve only over IP-addressed DoH** — `xray_workload.EXIT_DOH_RESOLVERS` as parallel `https+local` servers plus freedom `ForceIPv4v6` (gateways keep the host resolver: foreign DoH may be blocked in-country); a plain or hostname resolver, `localhost`, or an `AsIs`/`UseIP*` strategy hands names to the host's plain resolver.
- **Local Xray is evidence, not a requirement** — validate delivered configs with `run -test` (malformed fails); a missing runtime or an archive that misses `XRAY_SHA256` is inconclusive, and that archive never runs.
- **Deployer-side HTTPS uses httpx** — its certifi bundle verifies GitHub; urllib failed certificate checks on uv-managed Pythons, so `fleet upgrade` could never see a release.
- **Exit-IP observers are single-stack** — match the server's address family, or a dual-stack exit answers over the other one and fails the egress match.
- **Failed traffic is classified by a direct TCP connect** — `connectivity.py` separates `no_traffic` from `unreachable`; UDP (Hysteria2) paths are never TCP-probed.
- **Whatever adds a firewall rule retires it** — `migrate` deletes a Remnawave node's Docker-internal API rule (`fw-node-api`, plus its pre-rename comment) with the node runtime.
- **Readiness checks name their transient errors** — pass `poll_until_ready(transient=...)`; anything else propagates instead of timing out silently.
- **Verification reads both backends' plans** — `verification._v4_context` takes Hosts or client endpoints, the control runtime or service, and Inbounds embedded in a workload profile; reading only panel kinds silently dropped `test` route checks on a control-service fleet.
- **Page links are subscriptions** — every service user has a live page at their subscription URL; CLI reads never need an upload or publication marker, and legacy YAML markers are consumed and dropped on save.
- **A missing PWA template raises** — never render a blank page.
