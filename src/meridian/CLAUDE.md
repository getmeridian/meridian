# src/meridian — Python CLI package
## Design decisions
**Protocol keys** — `core/topology.py` owns the protocol vocabulary; `handoff.protocol_key()` classifies delivered subscription links and falls back to a fixed page label when a link has no name.
**Cluster config** — Schema V3 stores workload-scoped topology intent, generation bindings, allocations, and compact action checkpoints in one hidden `cluster.yml`. Client/user runtime state remains in Remnawave PostgreSQL.
**Remnawave integration** — `remnawave.py` wraps the REST API with `httpx`. Direct HTTPS calls from deployer's machine (no SSH tunneling for API). JWT auth, retry with backoff, Meridian-specific error types.
**SSH abstraction** — `ServerConnection` unifies local and remote execution. Local mode uses `bash -c`; remote uses SSH. Non-root triggers `sudo -n`. The `SSHUI` callback protocol in `ssh_auth.py` decouples transport from presentation; CLI callers pass `RichSSHUI` from `ssh_ui.py`, Engine/headless callers get logger-only output by default. File transfer methods (`put_bytes`, `put_text`, `get_text`) live in `_FileTransferMixin` in `ssh_transfer.py`; `ServerConnection` inherits from it.
**Remote execution primitives** — `conn.run()` returns `CommandResult` metadata and supports `cwd`, `env`, retries, ok codes, sensitive commands, and operation labels. File writes use `put_text`/`put_bytes`; never embed generated file content in shell heredocs. `CommandResult` and `RemoteCommandResult` have explicit `to_remote()`/`from_remote()` conversion methods. Adapters delegate to these methods, not dict unpacking.
**Server facts** — `facts.py` is the typed cache for OS, Docker, UFW, containers, sshd ports, disk, and sysctl data. Use it before adding one-off probe parsing in provisioners or diagnostics.
**Console output** — `fail()` with `hint_type` (user/system/bug) controls the footer. Every error must be actionable. `ConsoleState` class wraps globals; module-level functions delegate to singleton instance.
**Engine boundary** — `meridian.engine` owns command-free runtime use cases only when a local executable surface needs them. Static Studio does not need Engine; executable Studio will need it for SSH, files, secrets, events, and cancellation.
**Remnawave version policy** — `config.py` pins the tested backend/node/subscription-page images as `tag@sha256:<multi-arch index digest>` (move them together, refresh digests with `scripts/pin_image_digests.py`, update the CHANGELOG matrix) plus a `REMNAWAVE_MIN_VERSION` floor. Pins install on fresh servers and replace older or same-version tags; newer or floating operator tags are kept (`remnawave/versions.py`). `fleet upgrade` saves newer same-major releases (`remnawave/registry.py`) in `ClusterConfig.image_pins`; `effective_pins()` feeds the newer of saved and CLI pin into the reviewed `runtime_pins`. PostgreSQL/Valkey pins are Meridian-owned and always rendered. Verification refuses panels below the floor and warns on an untested newer major.
**Exit country** — `registry_country.py` reads the address's Regional Internet Registry country (IANA RDAP bootstrap, no geo-IP service) once, when deploy, `node add`, or the wizard first names an exit; the answer lives in `ExitIntent.region` so the compiler stays pure, and `--country` overrides it.
**Local home** — `config.default_home()` picks `$XDG_CONFIG_HOME/meridian` (else `~/.config/meridian`), adopting an earlier 4.x fleet in `~/.meridian-v4` or `~/.meridian` only while the XDG directory is absent; `servers.json` marks 4.x state, so 3.x's `~/.meridian` is never adopted. `MERIDIAN_HOME` overrides all of it.
**Resumable setup** — `core/setup.py` owns secret-free contracts; `setup/` owns atomic draft persistence, stage invalidation, and immutable server-shelf selection.
**Finite compiler** — `compiler/` purely transforms complete setup intent into typed, dependency-ordered, hash-reviewed V4 resources. It never performs I/O or generates secrets.
**Workload secrets** — `reconciler/workloads.py` allocates or reuses complete Reality key triples and persists them before remote mutation; `xray_workload.py` renders only the reviewed protocols and egress policy.
**Errors over exits** — library modules raise typed exceptions (`MeridianError` hierarchy in `core/errors.py`) and expose their classification as `category`; `hint_type` belongs only to `console.fail()`. Only CLI command entry points call `console.fail()`.
## What's done well
- **Forward-compatible YAML** — `_extra` dict in ClusterConfig preserves unknown YAML keys for forward-compat only. Pre-topology dev-build keys (`nodes`, `desired_*`, `applied_state`) land there inertly; `load_topology_cluster()` refuses such files with rebuild guidance. Never store load-bearing runtime state in `_extra`.
- **Single source of state** — Remnawave DB is authoritative for users. cluster.yml is authoritative for deployment topology; the control server's apply fence (`reconciler/fence.py`) stops a stale or foreign copy from applying instead of syncing.
- **Relay = Host** — Relays map to Remnawave Host entries. Enable/disable host → subscriptions auto-adapt.
- **Extracted shared logic** — `panel_bootstrap.py` runs the SSH provisioner and bootstraps control-plane credentials for `setup/runtime.py`; `node_deploy.py` owns node container rollout, panel readiness, and API tokens; `reality_keys.py` generates Reality keypairs. `resolve.py` owns `ResolvedServer`, `ensure_server_connection`, and pure resolution helpers; `commands/resolve.py` adds CLI prompts and rendering. Library modules import from `meridian.resolve`, never from `commands/`. `cluster_persistence.py` owns YAML serialization/deserialization; `cluster.py` keeps the data model and validation. `diagnostics/` owns reusable SSH health and client-side verification checks; commands own rendering.
- **Architecture tests** — `tests/test_architecture.py` enforces layer boundaries, file size budget, private import bans, commands/resolve import ban for library modules, and contract drift checks at CI time.
- **Read-only fleet projection** — `adapters/cluster.py` resolves the intent's saved server IDs into control, exit, gateway, and advertised relay endpoint views without mutating persisted state; it is the only source of node/relay rows.
## Pitfalls
- **Local state is fail-closed** — only missing `cluster.yml`/`servers.json` means fresh; malformed files require recovery, and generated `srv-*` IDs survive connection edits.
- **Never hard-code the home in messages** — print `config.HOME_DISPLAY`; a literal `~/.meridian` sent 4.x users into 3.x's directory.
- **Topology deletion is last** — node, relay, and teardown operations retain registry/topology state until every required API and SSH cleanup succeeds or is confirmed already absent.
- **Rendered inputs are typed** — validate and canonicalize hostname, SNI, port, and transport path values before nginx, Xray, or Remnawave serialization.
- **Published Hosts are assertions** — reconcile complete protocol fields against public listeners; observation or mutation failure must stop apply.
- **Panel accessible via HTTPS** — Remnawave backend is reverse-proxied by nginx at a secret path on public 443; all REST goes from the deployer's machine directly, no SSH tunnel.
- **Shared links never use the panel path** — build subscription URLs with `PanelConfig.subscription_url()` (connection-page path + `/sub/`); `SUB_PUBLIC_DOMAIN` matches it.
- **Local mode follows the saved profile** — `ServerEntry.runs_here()` matches the recorded `/etc/machine-id` or a locally bindable address, never the outbound public IP (a laptop on the server's VPN shares it); open saved servers with `resolve.connection_for_entry()`. Sudo follows the process UID, never the resolved user name.
- **Sudo must be passwordless and checked up front** — `sudo -n true` fails with "a password is required" both locally and remotely; report it as a user error with a working `sudo "$(command -v meridian)"` or NOPASSWD hint, never as an SSH key problem. An unwritable `known_hosts` is also a user error.
- **SSH ControlPath must fit a Unix socket** — macOS allows 103 bytes and ssh adds a 17-character suffix; hash the target into the path and drop multiplexing when `MERIDIAN_HOME` is still too deep.
- **Camouflage target**: never recommend apple.com (ASN mismatch with VPS providers).
- **Do not call `console.fail()` from library modules** (resolve, panel_bootstrap, node_deploy, reality_keys, provision/). Raise a `MeridianError` subclass instead. Enforced by `test_library_modules_do_not_import_console_fail`.
- **PQ encryption removed in v4** — Xray VLESS PQ requires per-user encryption fields on inbound clients plus Remnawave API support. Do not re-add the flag without both.
- **Reality key material is atomic** — redeploy must refuse partial private/public/short-ID state rather than rotate keys and break clients; a workload moved by `node replace` carries its keys to the new server.
- **Hysteria2 naming boundary** — external keys and URLs use `hysteria2`; Remnawave profiles require protocol/network `hysteria` plus version `2`.
- **Hysteria2 always carries salamander** — the inbound's `finalmask` password derives from the workload's Reality private key (`salamander_password()`); never store or rotate it separately. Remnawave copies the inbound mask into every client format.
- **Unknown panel admin is a user error** — register is refused once any admin exists; with no saved credentials and both register and login refused, stop with restore-or-`meridian teardown` guidance instead of retrying.
- **Remnawave 3.4 API tokens** — creation requires `name` and `expiresInDays`; use wildcard scope for the provisioner token. Tokens are signed with `APP_SECRET` (2.x `JWT_AUTH_SECRET`, carried over on upgrade).
- **Xray runtime and config failures differ** — keep the executable/assets atomic and validate canonical configs with `run -test`; malformed delivery fails, while local runtime absence is inconclusive.
- **Exit-IP observers are single-stack** — pick IPv4-only or IPv6-only observers by the server's address; a dual-stack observer lets a dual-stack exit answer over the other family and fail the egress match.
- **Failed traffic is classified by a direct TCP connect** — `connectivity.py` reports `no_traffic` (port answers, session carries nothing) vs `unreachable`; UDP (Hysteria2) paths are never TCP-probed and stay plain failures.
- **The Xray JSON subscription is an array** — one config per virtual Host in view order (primary "Automatic", then the fingerprint copy); `parse_xray_subscription()` validates every entry and returns the first.
- **Xray downloads are checksum-verified** — a missing, malformed, or mismatched release SHA2-256 sidecar makes connection verification inconclusive; never execute that archive.
- **Whatever adds a firewall rule retires it** — node retirement deletes the Docker-internal node API rule (`fw-node-api`, plus its pre-rename comment); a leftover once named Meridian on a server reused as a relay.
- **Readiness checks name their transient errors** — pass `poll_until_ready(transient=...)` for the failures a booting service raises; anything else is a bug and propagates instead of timing out silently.
- **A missing PWA template raises** — `render._render_pwa_template()` never returns a blank page to upload.
- **Fleet role contracts are finite** — do not project routing gateways as exits or source-restricted internal relay hops as public endpoints.
